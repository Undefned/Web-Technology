<h3 id="q1">1. Устройство сайта и его аппаратно-программного окружения</h3>

**Аппаратное окружение (где живёт сайт):**
- **Клиент** — устройство пользователя (ПК, смартфон, планшет). Он отправляет запросы.
- **Сервер** — мощный компьютер (или сеть), который круглосуточно хранит файлы сайта и обрабатывает запросы.
- **Сеть** — интернет-каналы, роутеры, DNS-серверы.

**Программное окружение (из чего состоит):**
- **На сервере:** ОС (Linux, Windows), веб-сервер (Nginx, Apache), интерпретатор (PHP, Node.js, Python), СУБД (MySQL, PostgreSQL).
- **На клиенте:** браузер (Chrome, Safari, Firefox), который умеет рендерить HTML/CSS/JS.

**Схема работы:**
```
Браузер → Запрос по URL → DNS (находит IP сервера) → Сервер → Обработка → Ответ (HTML+CSS+JS) → Браузер отображает страницу.
```

<h3 id="q2">2. Определение веб-сайта, его передача и отображение в браузере</h3>

**Веб-сайт** — это набор связанных веб-страниц, объединённых под одним доменом, написанных на HTML/CSS/JS, доступных через HTTP/HTTPS.

**Передача:**
- Браузер отправляет **HTTP-запрос** (метод GET, адрес, заголовки).
- Сервер отвечает **HTTP-ответом** (статус 200 OK, заголовки, тело — HTML-код).
- Используется протокол **HTTPS** (зашифрованный TLS/SSL).

**Отображение (критический путь рендеринга):**
1. Загрузка HTML → построение DOM-дерева.
2. Загрузка CSS → построение CSSOM-дерева.
3. Объединение в Render Tree.
4. Вычисление геометрии (Layout/Reflow).
5. Отрисовка пикселей (Paint).
6. Композиция слоёв (Composite).

<h3 id="q3">3. Сборка простого сайта: особенности, стек технологий. Дизайн, фронтенд, бекенд, база данных</h3>

**Особенности простого сайта:** без сложной логики, до 5–10 страниц.

**Стек технологий:**

| Тип | Технологии |
|------|------------|
| Фронтенд | HTML5, CSS3, JavaScript (чистый или Vue/Svelte) |
| Бекенд (если нужен) | Python + Flask, Node.js + Express, PHP |
| База данных (если нужна) | SQLite (легко), потом PostgreSQL |
| Сборка | Vite, Parcel (для начинающих: Live Server) |

Пример структуры:
```
site/
├── index.html
├── about.html
├── css/
│   └── style.css
├── js/
│   └── main.js
└── images/
```

**Дизайн, фронтенд, бекенд, база данных:**
- **Дизайн** — внешний вид, пользовательские интерфейсы, макеты (Figma, Photoshop).
- **Фронтенд** — код, который выполняется в браузере (HTML/CSS/JS). Отвечает за клик, анимацию, форму.
- **Бекенд** — код на сервере (Python/PHP/Node.js). Обрабатывает данные, работает с БД, авторизацию.
- **База данных** — хранилище информации (пользователи, товары, статьи). Пример: SQL-запрос `SELECT * FROM users`.

**Связь:**
```
Фронтенд → AJAX/fetch → API бекенда → БД → ответ → фронтенд → отображение.
```

<h3 id="q4">4. Дизайн-концепция сайта. Определение, подходы, примеры</h3>

**Дизайн-концепция** — это общая идея и визуальный язык сайта: цвета, шрифты, ритмы, настроение.

**Подходы:**
- **Flat design** — плоские элементы, без теней (Google Material Design).
- **Neumorphism** — объём, похожий на мягкий пластик (редко, для портфолио).
- **Brutalism** — нарочито грубо, битые сетки, резкие цвета.
- **Минимализм** — много воздуха, минимум деталей (Apple).

**Примеры:**
- Сайт студии — элегантная типографика и плавные скроллы.
- Интернет-магазин — яркие карточки товаров, кнопки «купить».

<h3 id="q5">5. Экранная типографика, специальные символы и общие правила вёрстки текста в вебе</h3>

**Особенности экранной типографики:**
- Засечные шрифты (Times) хуже читаются на экране, лучше без засечек (Arial, Roboto, Open Sans).
- Размер текста: базовый 16px (не меньше 14px).
- Межстрочный интервал: line-height = 1.4–1.5.
- Ширина строки: 50–75 символов.

**Специальные символы (HTML-мнемоники):**
```
&nbsp; — неразрывный пробел
&lt;  — <
&gt;  — >
&amp; — &
&copy; — ©
&mdash; — —
```

**Правила вёрстки текста:**
- Не использовать несколько пробелов подряд.
- Заголовки строго по иерархии (H1 → H2 → H3).
- Параграфы — в `<p>`, не через `<br>`.
- Для списков — `<ul>/<ol>`.

<h3 id="q6">6. Проектирование и дизайн веб-форм</h3>

**Принципы:**
- Логичная группировка полей (например, «Адрес доставки»).
- Метки (label) обязательно над полем или слева.
- Порядок полей от простого к сложному.
- Обязательные поля помечать звёздочкой *.

**Дизайн:**
- Высота поля ~ 40px (для пальца на тачскрине).
- Понятный фокус (outline: none + свой стиль).
- Валидация «на лету» (зелёная галочка / красная рамка).

**Пример:** форма логина — два поля (email, пароль), кнопка «Войти», ссылка «Забыли пароль».

<h3 id="q7">7. Реализация веб-форм и отправки информации</h3>

**HTML:**
```html
<form id="contact-form" method="POST" action="/send.php">
  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>
  <button type="submit">Отправить</button>
</form>
```

**Отправка без перезагрузки (JS + Fetch):**
```javascript
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const formData = new FormData(form);
  const res = await fetch('/api/contact', { method: 'POST', body: formData });
  if (res.ok) alert('Отправлено!');
});
```

**Бекенд (Node.js):**
```js
app.post('/api/contact', (req, res) => {
  const email = req.body.email;
  // сохранить в БД, отправить письмо
  res.json({ success: true });
});
```

<h3 id="q8">8. Валидация сайта по стандартам HTML и CSS</h3>

**Зачем:** чтобы сайт работал во всех браузерах, был доступным и SEO-дружественным.

**Инструменты:**
- W3C Validator для HTML (validator.w3.org)
- W3C CSS Validator (jigsaw.w3.org/css-validator)

**Что проверять:**
- Закрыты ли все теги.
- Нет ли устаревших атрибутов (например, `align`).
- Валидность цветов и единиц измерения в CSS.
- Доступность: ARIA-атрибуты, alt для картинок.

<h3 id="q9">9. Оптимизация показателей производительности сайта</h3>

**Ключевые метрики (Core Web Vitals):**
- **LCP** (загрузка главного контента) — < 2.5 сек.
- **FID** (отклик на первое действие) — < 100 мс.
- **CLS** (сдвиги вёрстки) — < 0.1.

**Что делать:**
- Сжимать изображения (WebP вместо JPEG).
- Использовать кэширование браузера.
- Минифицировать CSS/JS.
- Удалить неиспользуемый CSS.
- Подключить CDN.
- Отложить загрузку скриптов (defer, async).

<h3 id="q10">10. Развитие IT-специалиста. Оформление кейсов, портфолио, рост</h3>

**Оформление кейсов (Case study):**
- Проблема → Решение → Технологии → Результат (цифры: +30% скорости).
- Показывать не только готовый сайт, но и код (GitHub), архитектуру, сложности.

**Портфолио:**
- 3–5 сильных проектов (лучше работающие сайты).
- Личный сайт-визитка с фильтрацией работ.
- GitHub с качественными README, коммитами, тестами.

**Рост:**
- Junior → Middle → Senior → Lead / Architect / Tech Lead.
- Параллельно: менторство, выступления, open source.

<h3 id="q11">11. Введение в проектную деятельность. Жизненный цикл продукта. Команда и процессы</h3>

**Жизненный цикл продукта:**
1. **Идея** → 2. **Анализ** → 3. **Проектирование** → 4. **Разработка** → 5. **Тестирование** → 6. **Запуск** → 7. **Поддержка** → (8. Утилизация или реинкарнация).

**Команда:**
- PM (Project Manager) — сроки, ресурсы.
- Аналитик — требования.
- Дизайнер — интерфейс.
- Разработчики (frontend, backend, QA).
- DevOps — сервера, деплой.

**Процессы:** митинги, планирование, ретроспективы, таск-трекеры (Jira, Trello).

<h3 id="q12">12. Методологии веб-разработки</h3>

- **Waterfall** — жёсткая последовательность (хорошо для госпроектов). Минус: нельзя повернуть назад.
- **Agile** — гибкая, итеративная. Разбивка на спринты (1–4 недели).
- **Scrum** — разновидность Agile: роли (Scrum-мастер, PO, команда), артефакты (бэклог, спринт).
- **Kanban** — доска с колонками (To Do / In Progress / Done), без фиксированных итераций.

Для веба чаще всего: **Scrum + Kanban** (скрам-канбан).

<h3 id="q13">13. Методы и параметры аналитики сайта</h3>

**Основные метрики:**
- **Количество сессий / пользователей**
- **Bounce rate** (отказы) — ушёл с одной страницы.
- **Конверсия** — целевое действие (покупка, подписка).
- **Среднее время на сайте**
- **Источники трафика** (поиск, соцсети, прямой)

**Инструменты:**
- Google Analytics 4 (GA4)
- Яндекс.Метрика
- Hotjar (тепловые карты)
- Open Web Analytics (самостоятельный хостинг)

**Методы:** A/B-тестирование, когортный анализ, воронки (funnels).

<h3 id="q14">14. Тестирование и публикация продукта</h3>

**Виды тестирования:**
- **Юнит-тесты** (Jest, PHPUnit) — проверка отдельных функций.
- **Интеграционное** — работа модулей вместе.
- **E2E** (Cypress, Playwright) — симуляция действий пользователя.
- **Кроссбраузерное** (BrowserStack, LambdaTest).
- **Нагрузочное** (k6, JMeter).

**Публикация:**
- Подготовить окружение на хостинге.
- Загрузить файлы (через Git, FTP, CI/CD).
- Проверить SSL-сертификат.
- Сделать бэкап предыдущей версии.
- Переключить DNS или код.

<h3 id="q15">15. Доменные имена и хостинг</h3>

**Доменные имена:**
- Структура: `name.com` (TLS-зона .com, .ru, .org).
- Регистратор (Nic.ru, Reg.ru, GoDaddy).
- DNS записи: A (IPv4), AAAA (IPv6), CNAME (алиас), MX (почта), TXT.

**Хостинг (типы):**
| Тип | Описание | Пример |
|-----|----------|--------|
| Shared | Общий сервер, дешёво | Beget, Timeweb |
| VPS/VDS | Виртуальный сервер | DigitalOcean, Vultr |
| Dedicated | Выделенный сервер | Hetzner |
| Serverless | Без управления сервером | Vercel, Netlify, Cloudflare Pages |

**Как выбрать:** для простого сайта — Shared или Netlify. Для сложного — VPS.

<h3 id="q16">16. Развитие, поддержка и мониторинг продукта</h3>

**Поддержка:**
- Фикс багов по запросу.
- Обновление зависимостей (npm update, composer).

**Развитие:** добавлять новые фичи на основе аналитики, улучшать SEO, переделывать интерфейс по результатам A/B-тестов.

<h3 id="q18">18. Основы UX/UI: Дон Норман, UX, UI, зачем нужен дизайн интерфейсов</h3>

**Дон Норман** — американский учёный, автор книги «Дизайн привычных вещей». Он ввёл понятие **пользовательского опыта (UX)** в контексте дизайна.

**UX (User Experience)** — всё, что чувствует и переживает пользователь при взаимодействии с продуктом. Это не только экран, а эмоции, время, усилия.

> «Никакой продукт не является островом. Продукт — это набор взаимодействий. UX — это целостное впечатление». — Дон Норман

**UI (User Interface)** — конкретные элементы, с которыми взаимодействует пользователь: кнопки, поля ввода, иконки, цвета, шрифты, анимация.

**Отличие UX от UI:**
> **UX — это то, как вы себя чувствуете в ресторане.** (удобные стулья, приятная музыка, быстрый официант)
> **UI — это вилка, тарелка, скатерть и меню.** (то, что вы видите и трогаете)

**Зачем нужен дизайн интерфейсов:**
- Снижает когнитивную нагрузку
- Увеличивает конверсию
- Уменьшает количество ошибок и звонков в поддержку
- Создаёт доверие к продукту

<h3 id="q19">19. Целевая аудитория и анализ конкурентов</h3>

**Целевая аудитория — как и зачем:**
- Нельзя сделать сайт «для всех»
- Помогает выбрать стиль, функции, устройства

**Как делать:**
1. Собрать гипотезы
2. Провести интервью или анкетирование
3. Сегментировать по демографии, поведению, психографии

**Анализ конкурентов — как и зачем:**
- Не изобретать велосипед
- Понять, что работает, а что бесит

**Как делать:**
1. Выбрать 3–5 конкурентов
2. Проанализировать навигацию, контент, формы, скорость
3. Составить таблицу «Сильные / Слабые стороны / Что взять»

<h3 id="q20">20. Исследования: когда нужны, зачем, виды</h3>

**Когда нужны:**
- Перед началом проектирования
- После запуска
- При падении метрик

**Виды исследований:**

| Этап | Качественные (почему?) | Количественные (сколько?) |
|------|------------------------|---------------------------|
| До дизайна | Интервью, наблюдения | Опросы, аналитика |
| Во время дизайна | Юзабилити-тестирование | A/B тесты |
| После запуска | Звонки в поддержку | Метрики, тепловые карты |

**Главное правило:** сначала качественные (узнать проблемы), потом количественные (подтвердить масштаб).

<h3 id="q21">21. Проведение интервью</h3>

**Как подготовиться:**
- Сценарий на 30–40 минут
- Открытые вопросы
- Без вопросов-подсказок

**Как выбрать респондентов:**
- Скрининг-анкета
- Человек реально сталкивается с задачей
- Разнообразие: новички и опытные

**Как общаться:**
- Начать с простых фактов
- Просить показать, а не рассказать
- Не перебивать
- Задавать «почему» несколько раз (5 Whys)
- В конце спросить: «что мы забыли спросить?»

**Запрещено:** продавать, защищать продукт, подсказывать решения.

<h3 id="q22">22. Персоны (Personas)</h3>

**Что это:** Собирательный образ реального пользователя на основе исследований.

**Зачем:**
- Чтобы команда говорила на одном языке
- Чтобы принимать решения
- Чтобы не делать «функции ради функций»

**Как делать:**
1. Выделить 2–5 типов пользователей
2. Описать по шаблону: имя, фото, демография, цели, боли, сценарий
3. Повесить в офисе / в Figma

**Пример:** «Бизнесмен Борис» (45 лет, летает 2 раза в месяц, ненавидит долгие формы).

<h3 id="q23">23. CJM и User Story</h3>

**CJM (Customer Journey Map)** — карта пути клиента. Визуализация шагов, эмоций, точек касания.

**Зачем:** увидеть, где пользователь злится, бросает или испытывает восторг.

**Как делать:** таблица: Этап → Действие → Эмоция → Боли → Возможности.

**User Story** — «Я как [тип пользователя] хочу [действие] чтобы [достичь цели]».

**Пример:**
- «Я как **покупатель** хочу **сохранять товары в избранное** чтобы **вернуться к ним позже**».

**Зачем:** перевести требования на язык пользы для пользователя.

<h3 id="q24">24. Карта сайта и вайрфреймы</h3>

**Карта сайта (Site Map)** — иерархическая схема всех страниц и разделов.

**Зачем:** понять логику навигации, не пропустить важные страницы, согласовать с заказчиком.

**Вайрфреймы (Wireframes)** — «скелет» интерфейса, чёрно-белая схема.

**Уровни:**
- Low-fidelity — от руки
- Mid-fidelity — Figma, серые прямоугольники
- High-fidelity — почти как макет, но без стилей

<h3 id="q25">25. Accessibility (A11y) — доступность</h3>

**Что это:** возможность пользоваться сайтом людям с ограничениями.

**Уровни WCAG 2.1:**
- A — минимальный (госсайты)
- AA — рекомендуемый для коммерческих
- AAA — максимальный

**Как обеспечивать:**
1. Альтернативный текст (`alt`)
2. Контраст текста 4.5:1
3. Навигация с клавиатуры (Tab, Enter)
4. ARIA-роли
5. Не полагаться только на цвет
6. Размер кликабельных элементов ≥ 44×44 pt

**Инструменты:** WAVE, axe DevTools, Lighthouse.

<h3 id="q26">26. Принципы мобильного дизайна</h3>

| Параметр | Десктоп | Мобильный |
|----------|---------|-----------|
| Ввод | Мышь | Палец |
| Экран | Большой | Маленький |
| Контекст | Дома / в офисе | На ходу |

**Принципы:**
- Tap target ≥ 44×44 pt
- Жесты, но не прятать важные функции
- Приоритет контента
- Нижняя навигация (таб-бар)
- Адаптивные формы (`inputmode="numeric"`)
- Не убивать скролл

<h3 id="q27">27. Подготовка макетов для передачи в разработку</h3>

**В Figma:**
- Именование слоёв
- Автолейауты
- Стили текста и цвета
- Компоненты и состояния (hover, active, disabled)
- Сетка

**Документация:**
- Интерактивные прототипы
- Экспорт иконок (SVG, WebP)
- Поведение ошибок
- Адаптив
- Реальный контент

**Финальный шаг:** ревиз дизайна с разработчиком.

**Инструменты:** Figma Dev Mode, Zeplin, Avocode.
