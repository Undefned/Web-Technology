Array — фиксированный размер, сложность O(1) по индексу.
обяз

Array — коллекция фиксированного размера с прямым доступом по индексу.

Характеристики:

  • Размер задаётся при создании и не меняется
  • Доступ по индексу: O(1) (константное время)
  • Элементы хранятся непрерывно в памяти
  • Быстрый доступ, низкий overhead
  • При создании все элементы инициализируются значениями по умолчанию

Создание и использование:

// Создание
int[] arr1 = new int[10];          // Все элементы = 0
int[] arr2 = new int[] { 1, 2, 3 };// Инициализация
int[] arr3 = { 1, 2, 3 };          // Сокращённая запись

// Доступ
arr1[0] = 42;           // O(1)
int x = arr1[0];        // O(1)

// Методы
Array.Sort(arr1);       // Сортировка O(n log n)
Array.Reverse(arr1);    // Разворот O(n)
Array.Resize(ref arr1, 20);  // Создаёт новый массив

Когда использовать:

  • Размер известен и не меняется
  • Нужна максимальная производительность
  • Работа с низкоуровневыми операциями (P/Invoke, Span)
  • Фиксированное количество элементов
List<T> — динамический массив, сложность Add.
обяз

List<T> — динамический массив, который автоматически расширяется.

Сложность операций:

  • Доступ по индексу: O(1)
  • Добавление в конец (Add): O(1) амортизированно (иногда O(n) при расширении)
  • Вставка в середину (Insert): O(n) — сдвиг элементов
  • Удаление из середины (RemoveAt): O(n) — сдвиг элементов
  • Поиск (Contains, IndexOf): O(n)
  • Сортировка (Sort): O(n log n)

Как работает расширение:

  • Начальная ёмкость по умолчанию: 4 элемента
  • При переполнении ёмкость удваивается (4 → 8 → 16 → 32 ...)
  • Требует копирования всех элементов в новый массив

Оптимизация:

// Без оптимизации — несколько расширений
var list = new List<int>();
for (int i = 0; i < 1000; i++)
    list.Add(i);  // Расширения: 4 → 8 → 16 → 32 → ... → 1024

// С оптимизацией — одно выделение
var list2 = new List<int>(1000);
for (int i = 0; i < 1000; i++)
    list2.Add(i);  // Без расширений
Dictionary<K,V> — хэш-таблица, сложность.

Dictionary<K,V> — коллекция ключ-значение на основе хэш-таблицы.

Сложность операций:

  • Добавление (Add): O(1) в среднем, O(n) в худшем (коллизии)
  • Поиск (TryGetValue, this[]): O(1) в среднем, O(n) в худшем
  • Удаление (Remove): O(1) в среднем, O(n) в худшем
  • Итерация (foreach): O(n)

Внутреннее устройство:

  • Массив buckets (корзин) для хранения списков элементов
  • Ключи хранятся в связных списках внутри корзин
  • Использует GetHashCode() ключа для определения корзины
  • При коллизиях элементы попадают в одну корзину

HashSet<T> — что это, сложность.
обяз

HashSet<T> — коллекция уникальных элементов без дубликатов.

Характеристики:

  • Хранит только уникальные элементы
  • Построен на основе хэш-таблицы
  • Сложность операций: O(1) в среднем
  • Не поддерживает индексацию (нет this[index])
  • Порядок элементов не гарантируется

Использование:

var set = new HashSet<int>();
set.Add(1);
set.Add(2);
set.Add(1);  // Игнорируется (уже есть)

Console.WriteLine(set.Contains(1));  // True
Console.WriteLine(set.Count);        // 2

// Удаление дубликатов из списка
var numbers = new List<int> { 1, 2, 2, 3, 3, 3 };
var unique = new HashSet<int>(numbers);
Console.WriteLine(unique.Count);  // 3

// Множества (Set operations)
var set1 = new HashSet<int> { 1, 2, 3 };
var set2 = new HashSet<int> { 2, 3, 4 };
set1.IntersectWith(set2);  // { 2, 3 }
set1.UnionWith(set2);      // { 1, 2, 3, 4 }
set1.ExceptWith(set2);     // { 1 }

Когда использовать:

  • Нужно хранить уникальные элементы
  • Частые операции проверки существования
  • Удаление дубликатов
  • Операции над множествами (пересечение, объединение)
Queue<T> и Stack<T> — описание.
обяз

Queue<T> — FIFO (First In, First Out)

  • Первый добавленный элемент будет первым удалён
  • Аналогичен очереди в магазине
  • Методы: Enqueue() (добавить), Dequeue() (извлечь), Peek() (посмотреть)
  • Применение: обработка задач, очереди сообщений, BFS в графах

Stack<T> — LIFO (Last In, First Out)

  • Последний добавленный элемент будет первым удалён
  • Аналогичен стопке тарелок
  • Методы: Push() (добавить), Pop() (извлечь), Peek() (посмотреть)
  • Применение: обратные вызовы, парсинг, DFS в графах, отмена действий (Undo)

Примеры:

// Queue — FIFO
var queue = new Queue<string>();
queue.Enqueue("Первый");
queue.Enqueue("Второй");
queue.Enqueue("Третий");
Console.WriteLine(queue.Dequeue());  // "Первый"
Console.WriteLine(queue.Dequeue());  // "Второй"

// Stack — LIFO
var stack = new Stack<string>();
stack.Push("Первый");
stack.Push("Второй");
stack.Push("Третий");
Console.WriteLine(stack.Pop());  // "Третий"
Console.WriteLine(stack.Pop());  // "Второй"

// Реальный пример: обработка команд
var commands = new Queue<ICommand>();
commands.Enqueue(new SaveCommand());
commands.Enqueue(new PrintCommand());
while (commands.Count > 0)
    commands.Dequeue().Execute();
LinkedList<T> — когда использовать?
mid

LinkedList<T> — двусвязный список.

Сложность операций:

  • Вставка/удаление в начало/конец: O(1)
  • Вставка/удаление в середине: O(1) если есть узел, иначе O(n)
  • Доступ по индексу: O(n) (нужно пройти по списку)
  • Поиск: O(n)

Сравнение с List:

  • List: быстрый доступ по индексу, медленная вставка/удаление в середине
  • LinkedList: медленный доступ по индексу, быстрая вставка/удаление в середине

Когда использовать:

  • Частые вставки/удаления в середине
  • Размер коллекции неизвестен и меняется
  • Не нужен доступ по индексу
  • Работа с очередями с приоритетом

Пример:

var list = new LinkedList<int>();
var node1 = list.AddFirst(1);
var node2 = list.AddLast(3);
list.AddAfter(node1, 2);   // 1 → 2 → 3

// Перебор
foreach (int item in list) { }

// Вставка в середину без поиска
var middle = list.Find(2);
if (middle != null)
    list.AddBefore(middle, 0);  // 1 → 0 → 2 → 3

Concurrent коллекции — какие есть?
обяз

Concurrent коллекции — потокобезопасные коллекции из System.Collections.Concurrent.

Список:

  • ConcurrentDictionary<K,V> — потокобезопасный словарь
  • ConcurrentQueue<T> — потокобезопасная очередь (FIFO)
  • ConcurrentStack<T> — потокобезопасный стек (LIFO)
  • ConcurrentBag<T> — неупорядоченная коллекция
  • BlockingCollection<T> — блокирующая коллекция (Producer-Consumer)

Примеры:

// ConcurrentDictionary
var dict = new ConcurrentDictionary<string, int>();
dict.TryAdd("key", 42);
dict.AddOrUpdate("key", 0, (k, v) => v + 1);  // 43

// ConcurrentQueue
var queue = new ConcurrentQueue<int>();
queue.Enqueue(1);
queue.Enqueue(2);
queue.TryDequeue(out int result);  // result = 1

// ConcurrentBag (производительность, порядок не гарантируется)
var bag = new ConcurrentBag<string>();
bag.Add("Hello");
bag.TryTake(out string item);

// BlockingCollection (Producer-Consumer)
var bc = new BlockingCollection<int>();
// Producer
Task.Run(() => { for(int i=0; i<10; i++) bc.Add(i); bc.CompleteAdding(); });
// Consumer
foreach (var item in bc.GetConsumingEnumerable())
    Console.WriteLine(item);

Преимущества перед lock:

  • Оптимизированы для многопоточности
  • Используют lock-free и низкоуровневые операции
  • Лучшая производительность при высокой конкуренции
  • Проще в использовании
IEnumerable vs IQueryable — КРИТИЧНО для EF.
обяз

IEnumerable<T>:

  • Выполняется в памяти (на клиенте)
  • Все данные загружаются из БД, фильтрация идёт в .NET
  • Медленно для больших таблиц
  • Нет оптимизации запроса
  • Используйте когда данные уже в памяти

IQueryable<T>:

  • Выполняется в БД (на сервере)
  • Фильтрация превращается в SQL WHERE
  • Быстро для больших таблиц
  • Строит оптимизированный SQL-запрос
  • Используйте для запросов к БД

Критическая разница:

// ❌ ПЛОХО — все данные в память
IEnumerable<Order> orders = db.Orders;
var result = orders.Where(o => o.Total > 1000).ToList();
// SQL: SELECT * FROM Orders (все записи!)
// Фильтрация в .NET

// ✅ ХОРОШО — фильтрация в БД
IQueryable<Order> orders = db.Orders;
var result = orders.Where(o => o.Total > 1000).ToList();
// SQL: SELECT * FROM Orders WHERE Total > 1000

Демонстрация:

// IEnumerable — фильтрация на клиенте
IEnumerable<Phone> phones = db.Phones;
var result = phones.Where(p => p.Price > 500).ToList();
// SQL: SELECT * FROM Phones (все телефоны)
// Затем в памяти: WHERE Price > 500

// IQueryable — фильтрация в БД
IQueryable<Phone> phones = db.Phones;
var result = phones.Where(p => p.Price > 500).ToList();
// SQL: SELECT * FROM Phones WHERE Price > 500

Правила:

  • Всегда используйте IQueryable для фильтрации в БД
  • Превращайте в IEnumerable только после ToList() или AsEnumerable()
  • Используйте AsNoTracking() для чтения без отслеживания
  • Избегайте .ToList() до .Where()

{

// IList — когда нужен доступ по индексу
void Swap(IList<int> items, int i, int j)

    items[i] = items[j];
    items[j] = temp;
}
IEnumerator и yield return — как работает?
обяз

yield return — создаёт итератор с отложенным выполнением.

Как работает:

  • Компилятор генерирует state machine
  • Код выполняется лениво — только при итерации
  • Каждый yield return возвращает элемент и приостанавливает выполнение
  • При следующем MoveNext() выполнение продолжается с того же места
  • Сохраняется состояние между вызовами

Пример:

// Метод с yield
IEnumerable<int> GetNumbers()
{
    Console.WriteLine("Начало");
    yield return 1;
    Console.WriteLine("После первого");
    yield return 2;
    Console.WriteLine("После второго");
    yield return 3;
    Console.WriteLine("Конец");
}

// Использование
var numbers = GetNumbers();  // Ничего не выполняется!
foreach (var n in numbers)   // Здесь начинается выполнение
{
    Console.WriteLine($"Получено: {n}");
}
// Вывод:
// Начало
// Получено: 1
// После первого
// Получено: 2
// После второго
// Получено: 3
// Конец

Варианты yield:

  • yield return — возвращает один элемент
  • yield break — завершает итерацию
  • Нельзя использовать в try-catch (только в try-finally)
LINQ — отложенное выполнение (deferred execution).
обяз

Отложенное выполнение (Deferred Execution) — LINQ-запросы выполняются не сразу, а только при итерации.

Как работает:

  • Запросы LINQ возвращают IEnumerable
  • Сам запрос не выполняется при объявлении
  • Выполнение происходит при foreach, ToList() или Count()
  • Запрос вычисляется заново при каждой итерации

Пример:

var numbers = new List<int> { 1, 2, 3, 4, 5 };

// Запрос не выполняется здесь
var query = numbers.Where(x => x > 3);

numbers.Add(6);  // Можно изменить коллекцию

// Только здесь запрос выполняется
foreach (var n in query)  // Вывод: 4, 5, 6
    Console.WriteLine(n);

// Повторная итерация — повторное выполнение
foreach (var n in query)  // Снова выполняется
    Console.WriteLine(n);

Методы с отложенным выполнением:

  • Where, Select, OrderBy, GroupBy
  • SelectMany, Skip, Take

Методы с немедленным выполнением:

  • ToList(), ToArray()
  • Count(), First(), Any()
  • Sum(), Average(), Max(), Min()
LINQ: немедленное выполнение — примеры.
обяз

Методы, которые принудительно выполняют запрос:

1. ToList() / ToArray() — материализуют результат в коллекцию

var list = numbers.Where(x => x > 5).ToList();  // Выполнилось сразу
var array = numbers.Select(x => x * 2).ToArray();

2. Count() / LongCount() — вычисляет количество элементов

int count = numbers.Where(x => x > 5).Count();

3. First() / FirstOrDefault() — возвращает первый элемент

int first = numbers.Where(x => x > 5).First();
int firstOrDefault = numbers.Where(x => x > 100).FirstOrDefault();

4. Any() / All() — проверка условия

bool any = numbers.Any(x => x > 5);
bool all = numbers.All(x => x > 0);

5. Sum() / Average() / Max() / Min() — агрегатные функции

int sum = numbers.Sum();
double avg = numbers.Average();
int max = numbers.Max();
First() vs FirstOrDefault() vs Single() vs SingleOrDefault().
обяз
Метод Пустой результат Несколько элементов
First() Исключение (InvalidOperationException) Возвращает первый
FirstOrDefault() default (null для ссылочных) Возвращает первый
Single() Исключение Исключение (больше одного)
SingleOrDefault() default Исключение (больше одного)

Когда использовать:

  • First() — когда точно знаем, что есть элементы
  • FirstOrDefault() — когда возможно отсутствие элементов
  • Single() — когда должен быть ровно один элемент
  • SingleOrDefault() — когда может быть 0 или 1 элемент

Примеры:

var numbers = new List<int> { 1, 2, 3 };

// First
int first = numbers.First();  // 1
int error = new List<int>().First();  // Exception!

// FirstOrDefault
int empty = new List<int>().FirstOrDefault();  // 0

// Single
int single = numbers.Single(n => n == 2);  // 2
int error2 = numbers.Single(n => n > 1);   // Exception (2 и 3)

// SingleOrDefault
int single2 = numbers.SingleOrDefault(n => n == 5);  // 0
int error3 = numbers.SingleOrDefault(n => n > 1);    // Exception!

Производительность:

  • First() и FirstOrDefault() — O(1) (останавливаются на первом совпадении)
  • Single() и SingleOrDefault() — O(n) (проверяют, что только один)

Написать свой метод Where / Select (с yield).
mid

MyWhere — фильтрация с отложенным выполнением

public static IEnumerable<T> MyWhere<T>(this IEnumerable<T> source, Func<T, bool> predicate)
{
    if (source == null) throw new ArgumentNullException(nameof(source));
    if (predicate == null) throw new ArgumentNullException(nameof(predicate));
    
    foreach (var item in source)
    {
        if (predicate(item))
            yield return item;
    }
}

// Использование
var numbers = new List<int> { 1, 2, 3, 4, 5 };
var result = numbers.MyWhere(x => x > 3);  // Отложенное выполнение
foreach (var n in result)
    Console.WriteLine(n);  // 4, 5

MySelect — проекция

public static IEnumerable<TResult> MySelect<TSource, TResult>(
    this IEnumerable<TSource> source,
    Func<TSource, TResult> selector)
{
    if (source == null) throw new ArgumentNullException(nameof(source));
    if (selector == null) throw new ArgumentNullException(nameof(selector));
    
    foreach (var item in source)
    {
        yield return selector(item);
    }
}

// Использование
var squares = numbers.MySelect(x => x * x);

MyWhere с проверкой аргументов (eager validation)

public static IEnumerable<T> MyWhere<T>(this IEnumerable<T> source, Func<T, bool> predicate)
{
    // Проверки выполняются сразу (eager)
    if (source == null) throw new ArgumentNullException(nameof(source));
    if (predicate == null) throw new ArgumentNullException(nameof(predicate));
    
    return MyWhereIterator(source, predicate);
}

private static IEnumerable<T> MyWhereIterator<T>(IEnumerable<T> source, Func<T, bool> predicate)
{
    foreach (var item in source)
        if (predicate(item))
            yield return item;
}
