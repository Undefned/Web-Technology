🧩 7. Делегаты, События, Generics база

Делегат (delegate) — указатель на метод.
обяз

Делегат — тип, представляющий ссылку на метод.

Структура делегата:

  • Хранит ссылку на объект и метод
  • Может ссылаться на статический или экземплярный метод
  • Поддерживает многоадресность (цепочка методов)
  • Типобезопасен (проверяет сигнатуру)

Примеры:

// Объявление делегата
public delegate int MathOperation(int a, int b);

// Методы, соответствующие делегату
public static int Add(int a, int b) => a + b;
public static int Multiply(int a, int b) => a * b;

// Использование
MathOperation op = Add;           // Ссылка на метод
int result = op(2, 3);            // 5

op = Multiply;                    // Можно изменить
result = op(2, 3);                // 6

// Многоадресный делегат
op += Multiply;                   // Добавляем в цепочку
result = op(2, 3);                // Выполнит Add И Multiply (последний результат)

Применение:

  • Обработка событий (event)
  • Callback-методы
  • LINQ (Func, Action)
  • Асинхронные операции (продолжения)
Func, Action, Predicate — встроенные делегаты.
обяз

Встроенные делегаты в .NET:

Func — делегат с возвращаемым значением

  • Последний параметр — возвращаемый тип
  • До 16 входных параметров
// Func<int, int, int> — два параметра, возвращает int
Func<int, int, int> add = (a, b) => a + b;
int result = add(2, 3);  // 5

// Без параметров, возвращает string
Func<string> getMessage = () => "Hello";

Action — делегат без возвращаемого значения

  • Не возвращает значение (void)
  • До 16 входных параметров
Action<string> print = msg => Console.WriteLine(msg);
print("Hello");  // Вывод: Hello

Action log = () => Console.WriteLine("Log");

Predicate — делегат для проверки условия

  • Возвращает bool
  • Один параметр
  • То же, что Func<T, bool>
Predicate<int> isEven = x => x % 2 == 0;
bool even = isEven(4);  // true

Сравнение:

Делегат Возвращает Параметры Пример
Func<T, TResult> TResult 0–16 Func<int, int> square = x => x * x;
Action void 0–16 Action print = () => Console.WriteLine();
Predicate<T> bool 1 Predicate<int> isEven = x => x % 2 == 0;
Многоадресный делегат (MulticastDelegate).
mid

Многоадресный делегат — делегат, который может ссылаться на несколько методов одновременно.

Как работает:

  • Использует System.MulticastDelegate
  • Хранит список методов в цепочке
  • При вызове все методы выполняются последовательно
  • Возвращается последний результат (для Func)

Пример:

Action action = () => Console.WriteLine("Первый");
action += () => Console.WriteLine("Второй");
action += () => Console.WriteLine("Третий");

// Выполнит все три метода по порядку
action();

// Удаление
action -= () => Console.WriteLine("Второй");  // Удаляет последний (сравнивает по ссылке)
action -= new Action(() => Console.WriteLine("Первый"));  // Создаёт новый делегат (не удалит)

// Получение списка
var delegates = action.GetInvocationList();
foreach (var d in delegates)
{
    d.DynamicInvoke();
}

Важно:

  • Порядок вызова гарантирован (в порядке добавления)
  • Если метод выбрасывает исключение, выполнение останавливается
  • Для Func возвращается последнее значение
  • Используется в событиях (подписка нескольких обработчиков)
event vs delegate — разница (инкапсуляция).
обяз

event — специальная конструкция для инкапсуляции делегата.

Основные отличия:

1. Доступ извне

  • delegate: можно вызвать и присвоить из любого места
  • event: можно только += и -= (подписка/отписка)
  • Вызвать событие можно только внутри класса-владельца

2. Присваивание

  • delegate: можно перезаписать через =
  • event: нельзя перезаписать (только += и -=)

3. Компиляция

  • event компилируется в приватный делегат + два публичных метода (add и remove)
  • Аналогично свойствам (get/set) для полей

Пример:

public class Publisher
{
    // ❌ Публичный делегат — опасно
    public Action OnAction;
    
    // ✅ Событие — безопасно
    public event EventHandler<EventArgs> OnEvent;
    
    public void RaiseEvent()
    {
        // ✅ Можно вызвать только внутри
        OnEvent?.Invoke(this, EventArgs.Empty);
        
        // ❌ Нельзя вызвать событие извне
    }
}

// Использование
var p = new Publisher();

// С делегатом — всё что угодно
p.OnAction = () => Console.WriteLine("1");  // Перезаписали
p.OnAction += () => Console.WriteLine("2");
p.OnAction();  // Можно вызвать извне

// С событием — только подписка
p.OnEvent += (s, e) => Console.WriteLine("Событие");
// p.OnEvent = null;  // ❌ Ошибка
// p.OnEvent();  // ❌ Ошибка
Generics (обобщения) — зачем нужны.
обяз

Generics (обобщения) — позволяют создавать типы и методы, работающие с любыми типами данных.

Преимущества:

  • Безопасность типов — ошибки на этапе компиляции
  • Производительность — нет Boxing/Unboxing
  • Переиспользование — один код для разных типов
  • Читаемость — понятный код

Пример без Generics (плохо):

// ArrayList — хранит object (Boxing для значимых типов)
var list = new ArrayList();
list.Add(42);      // Boxing
list.Add("Hello");
int x = (int)list[0];  // Unboxing + приведение

Пример с Generics (хорошо):

// List<T> — хранит конкретный тип
var list = new List<int>();
list.Add(42);      // Нет Boxing
int x = list[0];   // Без приведения

Создание Generic класса:

public class Repository<T> where T : class
{
    private List<T> _items = new List<T>();
    
    public void Add(T item) => _items.Add(item);
    public T Get(int index) => _items[index];
}

// Использование
var users = new Repository<User>();
users.Add(new User());
var user = users.Get(0);
Ограничения обобщений: where T : class, struct, new(), unmanaged.
обяз

Ограничения Generics — определяют, какие типы могут быть использованы.

Ограничение Описание Пример
where T : class Только ссылочные типы class Repository<T> where T : class
where T : struct Только значимые типы class Parser<T> where T : struct
where T : new() Должен иметь конструктор без параметров class Factory<T> where T : new()
where T : unmanaged Неуправляемые типы (C# 7.3+) class Buffer<T> where T : unmanaged
where T : BaseClass Наследуется от BaseClass where T : Person
where T : IInterface Реализует интерфейс where T : IDisposable
where T : notnull Не null (C# 8+) where T : notnull

Комбинирование ограничений:

// Несколько ограничений
class Repository<T> where T : class, IEntity, new()
{
    public T Create()
    {
        return new T();  // ✅ new() гарантирует конструктор
    }
}

// Использование с unmanaged
unsafe struct Buffer<T> where T : unmanaged
{
    private T* _ptr;  // Можно использовать указатель
}

Важно:

  • Ограничения проверяются на этапе компиляции
  • Порядок: class/struct → интерфейсы → new()
  • new() должно быть последним
Ковариантность (out) и контравариантность (in).
mid

Ковариантность и контравариантность — для обобщённых интерфейсов и делегатов.

Ковариантность (out):

  • Позволяет использовать более производный тип
  • Маркер out T — тип используется только для возврата
  • Применяется к IEnumerable<out T>, Func<out TResult>
// IEnumerable<T> ковариантен
IEnumerable<string> strings = new List<string>();
IEnumerable<object> objects = strings;  // ✅ Ковариантность

// Функция, возвращающая string
Func<string> getString = () => "Hello";
Func<object> getObject = getString;  // ✅ Ковариантность

Контравариантность (in):

  • Позволяет использовать более базовый тип
  • Маркер in T — тип используется только для ввода
  • Применяется к Action<in T>
// Action<T> контравариантен
Action<object> printObject = obj => Console.WriteLine(obj);
Action<string> printString = printObject;  // ✅ Контравариантность

// IComparer<T> контравариантен
IComparer<object> comparer = new ObjectComparer();
IComparer<string> stringComparer = comparer;  // ✅

Создание своих интерфейсов:

// Ковариантный интерфейс (только для возврата)
interface IProducer<out T>
{
    T GetItem();
}

// Контравариантный интерфейс (только для ввода)
interface IConsumer<in T>
{
    void Process(T item);
}

// Использование
IProducer<string> producer = new StringProducer();
IProducer<object> producer2 = producer;  // ✅

IConsumer<object> consumer = new ObjectConsumer();
IConsumer<string> consumer2 = consumer;  // ✅
Как реализованы дженерики в .NET — стирание типов? Нет, reified.
mid

В .NET Generics — reified (информация о типах сохраняется).

Отличие от Java (стирание типов):

  • Java: информация о типах стирается после компиляции
  • .NET: информация о типах сохраняется в рантайме

Как работает в .NET:

  • При JIT-компиляции создаётся уникальный код для каждого типа
  • Для ссылочных типов — один общий код (оптимизация)
  • Для значимых типов — отдельный код для каждого типа

Пример:

var listInt = new List<int>();
var listString = new List<string>();

// Получаем реальные типы
Type t1 = listInt.GetType();    // System.Collections.Generic.List`1[System.Int32]
Type t2 = listString.GetType(); // System.Collections.Generic.List`1[System.String]

// t1 и t2 — разные типы!
Console.WriteLine(t1 == t2);  // False

// Reflected типы (информация сохранена)
Console.WriteLine(typeof(List<>));  // System.Collections.Generic.List`1[T]

Преимущества reified:

  • Можно использовать typeof(T)
  • Можно использовать is и as
  • Можно создавать экземпляры через new T() (с ограничением)
  • Безопасность типов в рантайме
  • Производительность (оптимизированный код)
Когда генерируется конкретный Generic-класс — JIT при первом обращении.
mid

Generic класс создаётся (JIT-компилируется) при первом обращении.

Процесс:

  1. Компиляция C# → IL (обобщённый код с параметрами T)
  2. При первом обращении JIT создаёт конкретный тип
  3. Для ссылочных типов — один общий код (shared)
  4. Для значимых типов — отдельный код для каждого типа

Пример:

// IL содержит обобщённый код
class Repository<T>
{
    public T Get() { return default(T); }
}

// При первом обращении JIT создаёт код
var repo1 = new Repository<int>();    // Создаётся код для int
var repo2 = new Repository<int>();    // Использует существующий код

var repo3 = new Repository<string>(); // Создаётся код для string (shared)
var repo4 = new Repository<object>(); // Использует тот же код, что и string (shared)

Оптимизации:

  • Shared код: все ссылочные типы используют один код
  • Уникальный код: каждый значимый тип имеет свой код
  • Это экономит память и улучшает производительность
