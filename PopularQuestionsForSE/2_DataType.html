Значимые (value) vs ссылочные (reference) — разница?
обяз

Значимые типы (Value Types):

  • Хранят данные напрямую
  • Размещаются в стеке (или inline внутри объектов)
  • При присваивании создается копия данных
  • Не поддерживают наследование (кроме интерфейсов)
  • Освобождаются при выходе из области видимости
  • Примеры: int, bool, DateTime, struct, enum

Ссылочные типы (Reference Types):

  • Хранят ссылку на данные в куче
  • Размещаются в куче (Heap)
  • При присваивании копируется ссылка (не данные)
  • Поддерживают наследование
  • Управляются сборщиком мусора (GC)
  • Примеры: string, class, array, delegate

Сравнение:

ХарактеристикаЗначимыеСсылочные
ХранениеСтекКуча
ПередачаПо значению (копия)По ссылке
НаследованиеНетДа
Значение по умолчанию0, false, null (для Nullable)null
Управление памятьюАвтоматически (стек)Сборщик мусора
РазмерОбычно до 16 байтЛюбой
Примерыint, bool, structstring, class, array

Важные нюансы:

  • Строка (string) — ссылочный тип, но ведёт себя как значимый (иммутабельность)
  • Массивы — всегда ссылочный тип, даже если содержат значимые типы
  • Структуры (struct) — значимые, но могут иметь методы и интерфейсы
  • Значимые типы могут храниться в куче, если они являются полями класса

Демонстрация разницы:

// Значимый тип
int a = 10;
int b = a;      // Копия значения
b = 20;         // a всё ещё 10

// Ссылочный тип
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;          // Копия ссылки
list2.Add(4);               // list1 тоже изменился! {1, 2, 3, 4}
Stack vs Heap — где что хранится?
обяз

Стек (Stack):

  • Что хранит: значимые типы, ссылки на объекты в куче, параметры методов, локальные переменные
  • Принцип работы: LIFO (Last In, First Out)
  • Размер: ограничен (~1 МБ для Windows)
  • Скорость: очень быстрый
  • Управление: автоматическое (при входе/выходе из метода)
  • Пример: int x = 5; — x в стеке

Куча (Heap):

  • Что хранит: объекты ссылочных типов, строки, массивы
  • Принцип работы: неупорядоченное хранилище
  • Размер: ограничен только системной памятью
  • Скорость: медленнее стека
  • Управление: сборщиком мусора (GC)
  • Пример: var s = "Hello"; — ссылка в стеке, строка в куче

Визуализация:

void Method()
{
    int x = 5;                    // x в СТЕКЕ
    string s = "Hello";           // ссылка s в СТЕКЕ, "Hello" в КУЧЕ
    var obj = new Person();       // ссылка obj в СТЕКЕ, объект Person в КУЧЕ
    int[] arr = new int[10];      // ссылка arr в СТЕКЕ, массив в КУЧЕ
}

Когда объект из значимого типа попадает в кучу:

  • Boxing (упаковка): object o = 5;
  • Как поле ссылочного типа: class MyClass { int x; } — x будет в куче
  • В замыканиях (closures) — переменные захватываются и попадают в кучу

StackOverflowException:

  • Возникает при рекурсии без выхода
  • Стек переполняется (например, бесконечная рекурсия)
  • Решение: использовать итерацию или увеличить стек (редко)
class vs struct — 7 отличий.
обяз
# Характеристика class struct
1 Тип Ссылочный Значимый
2 Хранение Куча (Heap) Стек (или inline)
3 Наследование Да (кроме sealed) Нет (неявно sealed)
4 Конструктор без параметров Можно определить Всегда есть (нельзя заменить)

Когда использовать struct:

  • Объект маленький (≤ 16 байт)
  • Объект неизменяемый (immutable)
  • Часто создаётся и уничтожается (большая нагрузка на GC)
  • Не требует наследования
  • Логически является одним значением (Point, DateTime, Color)

Когда использовать class:

  • Объект большой (> 16 байт)
  • Объект изменяемый
  • Требуется наследование
  • Объект содержит другие ссылочные типы
  • Логически является сущностью (Person, Order, Product)

Пример правильного использования struct:

public struct Point
{
    public int X { get; }
    public int Y { get; }
    
    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
    
    public double DistanceTo(Point other)
    {
        return Math.Sqrt(Math.Pow(X - other.X, 2) + Math.Pow(Y - other.Y, 2));
    }
}

// Использование
Point p1 = new Point(0, 0);
Point p2 = new Point(3, 4);
double dist = p1.DistanceTo(p2);  // 5.0
record (C# 9) — чем отличается от class?
mid

record — ссылочный тип с value-семантикой (поведение как у значимых типов).

Ключевые отличия от class:

  • Сравнение по значению: Equals() сравнивает свойства, а не ссылки
  • Неизменяемость: свойства init (можно установить только при создании)
  • Автоматический ToString(): выводит все свойства
  • Deconstruct: автоматическая деконструкция
  • with выражение: копирование с изменением
  • Позиционный синтаксис: короткое определение

Примеры:

// Позиционный синтаксис (C# 9)
public record Person(string Name, int Age);

// Эквивалент с явным объявлением
public record Person
{
    public string Name { get; init; }
    public int Age { get; init; }
    
    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
    
    public void Deconstruct(out string name, out int age)
    {
        name = Name;
        age = Age;
    }
}

// Использование
var p1 = new Person("Alice", 30);
var p2 = new Person("Alice", 30);

Console.WriteLine(p1 == p2);  // True (сравнение по значению)
Console.WriteLine(p1);        // Person { Name = Alice, Age = 30 }

// Копирование с изменением
var p3 = p1 with { Age = 31 };
Console.WriteLine(p3);        // Person { Name = Alice, Age = 31 }

// Деконструкция
var (name, age) = p1;

Когда использовать record:

  • DTO (Data Transfer Objects)
  • Value Objects в DDD
  • Immutable данные
  • Объекты, где важна value-семантика

record vs struct:

  • record — ссылочный (куча), но с value-семантикой
  • struct — значимый (стек)
  • record struct (C# 10) — значимый с value-семантикой
string — ссылочный, но ведёт себя как значимый. Почему?
обяз

string — ссылочный тип (хранится в куче), но имеет поведение, характерное для значимых типов из-за иммутабельности (неизменяемости).

Иммутабельность строк:

  • Строку нельзя изменить после создания
  • Любая операция (конкатенация, замена, вставка) создаёт новую строку в куче
  • Старая строка остаётся в памяти до сборки мусора
  • Это безопасно для многопоточности (thread-safe)

Почему это поведение похоже на значимые типы:

  • При присваивании копируется ссылка, но изменить исходную строку нельзя
  • Сравнение == сравнивает значение, а не ссылку (перегрузка оператора)
  • Поведение интуитивно понятно (работаем со строкой как со значением)

Демонстрация:

string s1 = "Hello";
string s2 = s1;              // s2 ссылается на ту же строку
s2 = s2.ToUpper();           // Создаётся НОВАЯ строка "HELLO"
Console.WriteLine(s1);       // "Hello" — не изменилась!
Console.WriteLine(s2);       // "HELLO"

// Память: две разные строки в куче

Последствия иммутабельности:

  • Плохо: много операций со строками → много мусора → нагрузка на GC
  • Решение: использовать StringBuilder для частых изменений
  • Хорошо: безопасность в многопоточных сценариях
  • Хорошо: можно использовать как ключ в Dictionary

Пример проблемы:

// Плохо — много аллокаций
string result = "";
for (int i = 0; i < 10000; i++)
{
    result += i;  // Каждая итерация создаёт новую строку
}

// Хорошо — одна строка
var sb = new StringBuilder();
for (int i = 0; i < 10000; i++)
{
    sb.Append(i);
}
string result = sb.ToString();
Boxing и Unboxing — что это, влияние на производительность?
обяз

Boxing (упаковка): преобразование значимого типа в ссылочный.

  • Значение копируется из стека в кучу
  • Создаётся объект-обёртка
  • Происходит неявно

Unboxing (распаковка): обратное преобразование из ссылочного в значимый.

  • Значение извлекается из кучи
  • Требует явного приведения
  • Может выбросить InvalidCastException

Примеры:

int i = 42;
object obj = i;        // Boxing: int → object (куча)
int j = (int)obj;      // Unboxing: object → int

// Неявный Boxing
ArrayList list = new ArrayList();
list.Add(10);          // int упаковывается в object
list.Add("Hello");     // строка и так ссылочный тип

// Boxing в коллекциях
List<object> objects = new List<object>();
objects.Add(42);       // Boxing
objects.Add(3.14);     // Boxing

Влияние на производительность:

  • Память: упакованный объект занимает больше места (заголовок + данные)
  • Скорость: копирование в кучу и обратно требует времени
  • GC: упакованные объекты создают мусор → нагрузка на сборщик
  • Ошибки: распаковка неправильного типа → исключение

Как избежать Boxing:

  • Использовать обобщённые коллекции вместо необобщённых
  • Использовать IEquatable<T> вместо Equals(object)
  • Избегать передачи значимых типов как object
  • Использовать Span<T> и Memory<T>

Пример проблемы с производительностью:

// Плохо — много Boxing
var list = new ArrayList();
for (int i = 0; i < 1000000; i++)
{
    list.Add(i);  // Каждый раз Boxing
}

// Хорошо — нет Boxing
var list = new List<int>();
for (int i = 0; i < 1000000; i++)
{
    list.Add(i);  // int без упаковки
}
ref / out / in / ref readonly — различия?
обяз
Ключевое слово Описание Инициализация Может изменяться
ref Передача по ссылке Должна быть Да
out Передача по ссылке для возврата Не обязательна Да (метод обязан присвоить)
in Передача по ссылке только для чтения Должна быть Нет
ref readonly Возврат ссылки только для чтения — Нет (для возвращаемых значений)

ref:

  • Переменная ДОЛЖНА быть инициализирована до вызова
  • Метод может изменять значение
  • Используется для изменения значимых типов в методе
void Increment(ref int x) { x++; }
int a = 5;
Increment(ref a);  // a = 6

out:

  • Переменную МОЖНО не инициализировать
  • Метод ОБЯЗАН присвоить значение
  • Используется для возврата нескольких значений
void GetCoordinates(out int x, out int y) { x = 10; y = 20; }
GetCoordinates(out int x, out int y);  // x = 10, y = 20

in:

  • Передаёт по ссылке, но НЕ даёт изменять
  • Повышает производительность для больших структур
  • Метод не может изменить параметр
void Print(in LargeStruct data) { Console.WriteLine(data.X); }
var data = new LargeStruct();
Print(in data);

ref readonly (возврат):

  • Возвращает ссылку на данные
  • Вызывающий не может изменить данные
  • Избегает копирования больших структур
private LargeStruct _data;
public ref readonly LargeStruct GetData() => ref _data;
// Нельзя: GetData().X = 5;
const vs readonly — разница?
обяз
Характеристика const readonly
Время инициализации Компиляция Runtime (в конструкторе)
Инициализация Только при объявлении При объявлении ИЛИ в конструкторе
Может быть нестатическим Нет (всегда static) Да
Поддерживаемые типы Примитивы, string, enum Любые

const:

  • Значение встраивается во все места использования
  • Если изменить const в библиотеке, нужно перекомпилировать все зависимости
  • Не может быть вычислено в рантайме
  • Используется для математических констант, строковых литералов

readonly:

  • Значение вычисляется в рантайме
  • Может быть разным для разных экземпляров
  • Можно использовать с любыми типами
  • Для ссылочных типов запрещает менять ССЫЛКУ (но не данные объекта)
  • Используется для конфигурации, зависимостей

Примеры:

public class Config
{
    // const — всегда статический, значение на этапе компиляции
    public const double Pi = 3.14159265359;
    public const string AppName = "MyApp";
    
    // readonly — можно установить в конструкторе
    public readonly int MaxRetries;
    public readonly Guid InstanceId;
    public readonly List<string> Items;  // ссылка неизменна, но содержимое можно менять
    
    public Config(int maxRetries)
    {
        MaxRetries = maxRetries;
        InstanceId = Guid.NewGuid();      // вычисляется в рантайме
        Items = new List<string>();       // можно менять Items.Add()
        // const нельзя использовать в конструкторе
    }
}

Где использовать:

  • const: значения, известные на этапе компиляции (Pi, AppName, ConnectionString?)
  • readonly: значения, вычисляемые в рантайме (Id, зависимости, конфигурация)
  • static readonly: для инициализации один раз при старте
Nullable типы (int?) — что это?
обяз

int? — это синтаксический сахар для Nullable<int>.

Что такое Nullable<T>:

  • Это структура (значимый тип)
  • Содержит два поля: bool HasValue и T Value
  • Позволяет значимым типам принимать значение null
  • Работает только для значимых типов

Структура Nullable<T>:

public struct Nullable<T> where T : struct
{
    private bool _hasValue;
    private T _value;
    
    public bool HasValue => _hasValue;
    public T Value => _hasValue ? _value : throw new InvalidOperationException();
    
    public Nullable(T value)
    {
        _value = value;
        _hasValue = true;
    }
    
    public T GetValueOrDefault() => _value ?? default(T);
    public T GetValueOrDefault(T defaultValue) => _hasValue ? _value : defaultValue;
}

Использование:

int? nullableInt = null;
int? nullableInt2 = 42;

// Проверка
if (nullableInt.HasValue)
{
    Console.WriteLine(nullableInt.Value);
}

// Безопасное извлечение
int value = nullableInt ?? 0;  // null-coalescing
int value2 = nullableInt.GetValueOrDefault();

// Pattern matching (C# 7+)
if (nullableInt is int val)
{
    Console.WriteLine(val);
}

Операторы для Nullable:

  • ?? — null-coalescing (возвращает значение или default)
  • ??= — null-coalescing assignment (C# 8)
  • ?. — null-conditional operator (для ссылочных типов)
  • Value — выбрасывает исключение если null
  • GetValueOrDefault() — безопасное получение

Nullable reference types (C# 8+):

  • Отдельная фича для ссылочных типов
  • Помогает избежать NullReferenceException
  • Использует аннотации ? и !
  • Включается в проекте: <Nullable>enable</Nullable>
Операторы ?. (null-conditional) и ?? (null-coalescing).
обяз

?. (null-conditional operator):

  • Обращается к члену объекта ТОЛЬКО если объект != null
  • Возвращает null если объект null
  • Поддерживает цепочки вызовов
  • Работает с полями, свойствами, методами, индексами

?? (null-coalescing operator):

  • Возвращает левый операнд, если он не null
  • Иначе возвращает правый операнд
  • Работает со ссылочными типами и Nullable

??= (null-coalescing assignment, C# 8):

  • Присваивает правый операнд если левый null

Примеры:

Person person = null;

// Без ?. — нужно проверять
string name = person != null ? person.Name : null;

// С ?.
string name = person?.Name;  // null

// Цепочки
string city = person?.Address?.City;  // null если что-то null

// Вызов методов
person?.Speak();  // вызовет только если не null

// С индексами
var first = list?[0];

// ?? — значение по умолчанию
string name = person?.Name ?? "Unknown";

// ??= — присвоение, если null
List<string> items = null;
items ??= new List<string>();
items.Add("Hello");  // items уже не null

Комбинация ?. и ??:

string name = person?.Name ?? "Unknown";
int age = person?.Age ?? 0;
var address = person?.Address?.City ?? "Not specified";
var vs dynamic — отличия?
mid

var — статическая типизация:

  • Тип определяется компилятором
  • Тип фиксирован после определения
  • Ошибки типов выявляются на этапе компиляции
  • IntelliSense работает полностью
  • Требует инициализации при объявлении
  • Не может быть полем класса

dynamic — динамическая типизация:

  • Тип определяется в рантайме
  • Тип может меняться во время выполнения
  • Ошибки типов возникают при выполнении
  • IntelliSense работает ограниченно
  • Не требует инициализации
  • Может быть полем класса

Сравнение:

// var — статический
var x = 10;        // int
// x = "Hello";    // Ошибка компиляции: неявное преобразование
Console.WriteLine(x.GetType());  // System.Int32

// dynamic — динамический
dynamic y = 10;    // int
y = "Hello";       // OK — в рантайме
y = new Person();  // OK
y.SomeMethod();    // Ошибка будет только при выполнении (RuntimeBinderException)
Console.WriteLine(y.GetType());  // System.String (после присвоения)

// dynamic с COM-объектами
dynamic excel = Activator.CreateInstance(Type.GetTypeFromProgID("Excel.Application"));
excel.Visible = true;  // Работает без рефлексии

Когда использовать:

  • var: всегда, если тип очевиден (LINQ, сложные типы)
  • dynamic: при работе с COM-объектами, JSON без строгой типизации, Reflection
  • Избегайте dynamic: в критическом коде, где важна производительность и безопасность типов
Span<T> и Memory<T> — зачем, когда использовать?
mid

Span<T>:

  • Представление непрерывной области памяти
  • Не выделяет память (zero-allocation)
  • Может ссылаться на массив, стек, неуправляемую память
  • Только ref struct — не может быть полем класса
  • Живёт только в стеке
  • Очень быстрый

Memory<T>:

  • Аналогично Span, но может быть полем класса
  • Может использоваться в асинхронных методах
  • Безопасный (можно передавать между методами)
  • Чуть медленнее Span

Использование:

// Span — создание из массива
int[] array = new int[] { 1, 2, 3, 4, 5 };
Span<int> span = array.AsSpan(1, 3);  // { 2, 3, 4 }
span[0] = 10;  // array[1] = 10

// Span — без аллокаций
string text = "Hello World";
ReadOnlySpan<char> slice = text.AsSpan(6, 5);  // "World"

// Memory — для асинхронных операций
Memory<byte> memory = new byte[1024];
await WriteAsync(memory);

// Парсинг без выделений
ReadOnlySpan<char> number = "42".AsSpan();
int value = int.Parse(number);  // Без создания строки

Когда использовать:

  • Span: для синхронной обработки данных (парсинг, срезы, преобразования)
  • Memory: для асинхронных операций (чтение/запись в файлы, сети)
  • Избегайте: если не нужна максимальная производительность
unsafe код — когда разрешён, риски?

unsafe — код, работающий с указателями и напрямую с памятью.

Когда разрешён:

  • Включена опция компилятора /unsafe
  • Код помечен ключевым словом unsafe
  • Используется в блоке unsafe { ... }

Примеры:

unsafe void Example()
{
    int x = 10;
    int* ptr = &x;           // Получение адреса
    *ptr = 20;               // Изменение через указатель
    
    // Работа с массивами
    int[] arr = new int[10];
    fixed (int* p = arr)     // Закрепление массива
    {
        p[0] = 42;
    }
    
    // Структуры с указателями
    var data = new MyStruct();
    MyStruct* pData = &data;
    pData->Field = 5;
}

Риски:

  • Потеря безопасности типов — компилятор не проверяет типы
  • Повреждение памяти — можно записать данные в произвольное место
  • Buffer overflow — выход за границы массивов
  • AccessViolationException — доступ к недопустимой памяти
  • Не верифицируемый код — не проходит проверку CLR
  • Несовместимость — не работает в некоторых средах (например, Unity WebGL)

Когда использовать:

  • Взаимодействие с неуправляемым кодом (P/Invoke)
  • Высокопроизводительные вычисления (обработка изображений, аудио)
  • Работа с большими объёмами данных без копирования
  • Встроенные алгоритмы (криптография, сжатие)

Альтернативы unsafe:

  • Span<T> и Memory<T>
  • Marshal и MarshalAs
  • GCHandle для закрепления объектов
  • Buffer для низкоуровневой работы с памятью
decimal vs float vs double — когда что использовать?
обяз
Тип Размер Точность Диапазон Применение
float 4 байта ~7 цифр ±1.5e-45 … ±3.4e38 Графика, 3D, быстрые расчёты
double 8 байт ~15-16 цифр ±5e-324 … ±1.7e308 Научные расчёты, по умолчанию
decimal 16 байт ~28-29 цифр ±1e-28 … ±7.9e28 Финансовые расчёты

Ключевые отличия:

  • float/double: двоичное представление → ошибки округления
  • decimal: десятичное представление → точность для денежных операций
  • decimal медленнее, но точен
  • float/double быстрее, но есть погрешности

Примеры ошибок округления:

double d = 0.1 + 0.2;
Console.WriteLine(d);  // 0.30000000000000004 (не 0.3!)

decimal m = 0.1m + 0.2m;
Console.WriteLine(m);  // 0.3 (точно)

Когда использовать:

  • decimal: деньги, налоги, проценты, любые точные расчёты
  • double: научные расчёты, физика, математика, по умолчанию для дробных
  • float: графика, игры, когда нужна скорость и память

Сравнение производительности:

  • float — самый быстрый, наименьшая точность
  • double — быстрый, достаточно точный
  • decimal — самый медленный (~20-50x медленнее double)
Что такое выравнивание (alignment) в памяти?
mid

Выравнивание — размещение данных в памяти по адресам, кратным их размеру.

Зачем это нужно:

  • Производительность: процессор может читать выровненные данные за одну операцию
  • Невыровненные данные: процессор делает два чтения и комбинирует результат
  • На некоторых архитектурах (ARM) невыровненный доступ приводит к исключению

Примеры:

  • byte (1 байт) — не требует выравнивания
  • short (2 байта) — должен быть по адресу кратному 2
  • int (4 байта) — по адресу кратному 4
  • long (8 байт) — по адресу кратному 8

Управление выравниванием:

[StructLayout(LayoutKind.Sequential, Pack = 1)]
struct UnalignedStruct
{
    byte b;   // 1 байт
    int i;    // 4 байта — будет на смещении 1 (не выровнено)
}

[StructLayout(LayoutKind.Sequential, Pack = 4)]
struct AlignedStruct
{
    byte b;   // 1 байт + 3 байта padding
    int i;    // 4 байта — на смещении 4 (выровнено)
}

Размер структур с учётом выравнивания:

struct Struct1
{
    byte b;   // 1 байт
    int i;    // 4 байта
    // Размер = 8 байт (1 + 3 padding + 4)
}

struct Struct2
{
    int i;    // 4 байта
    byte b;   // 1 байт
    // Размер = 8 байт (4 + 1 + 3 padding)
}

Как управлять:

  • StructLayout.Sequential — сохраняет порядок, добавляет padding
  • StructLayout.Explicit — ручное управление через FieldOffset
  • StructLayout.Auto — CLR оптимизирует порядок
  • Pack — минимальное выравнивание (1, 2, 4, 8)
StructLayout — Explicit, Auto, Sequential.
mid

LayoutKind.Sequential:

  • Поля располагаются в порядке объявления
  • Добавляет padding для выравнивания
  • Используется для P/Invoke (взаимодействие с C/C++)
  • По умолчанию для структур

LayoutKind.Explicit:

  • Явное указание смещения каждого поля через FieldOffset
  • Позволяет создавать объединения (union)
  • Несколько полей могут занимать одну область памяти
  • Используется для низкоуровневых оптимизаций

LayoutKind.Auto:

  • CLR сама оптимизирует порядок полей
  • Улучшает производительность и уменьшает размер
  • По умолчанию для классов
  • Нельзя использовать с P/Invoke

Примеры:

// Sequential — порядок объявления
[StructLayout(LayoutKind.Sequential)]
struct Point
{
    public int X;  // offset 0
    public int Y;  // offset 4
    public int Z;  // offset 8
}

// Explicit — union (объединение)
[StructLayout(LayoutKind.Explicit)]
struct Union
{
    [FieldOffset(0)] public int IntValue;    // 4 байта
    [FieldOffset(0)] public float FloatValue; // те же 4 байта
    [FieldOffset(0)] public byte Byte0;      // первый байт
    [FieldOffset(1)] public byte Byte1;      // второй байт
    [FieldOffset(2)] public byte Byte2;      // третий байт
    [FieldOffset(3)] public byte Byte3;      // четвёртый байт
}

// Использование union
var u = new Union();
u.IntValue = 0x12345678;
Console.WriteLine(u.Byte0);  // 0x78 (младший байт)
