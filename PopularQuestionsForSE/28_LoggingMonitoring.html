📊 28. Логирование и мониторинг Mid+

ILogger vs Serilog vs NLog.
mid
Характеристика ILogger Serilog NLog
Встроен Да (в .NET Core) Нет (NuGet) Нет (NuGet)
Структурированные логи Ограничено ✅ Да ✅ Да
Sinks (вывод) Ограничено Много (Seq, Elastic, Console) Много (Файлы, БД)
Производительность Быстрый Средний Быстрый
Где использовать ASP.NET Core (по умолчанию) Сложное логирование Устаревшие проекты

ILogger:

builder.Services.AddLogging();
app.MapGet("/test", (ILogger<Program> logger) =>
{
    logger.LogInformation("Test endpoint called at {Time}", DateTime.Now);
    return "Ok";
});

Serilog:

Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .WriteTo.Seq("http://seq:5341")
    .WriteTo.Elasticsearch(new ElasticsearchSinkOptions(new Uri("http://elastic:9200")))
    .CreateLogger();

builder.Host.UseSerilog();
Структурированное логирование (JSON-логи).
mid

Структурированное логирование — логи в JSON-формате с полями.

Пример с Serilog:

_logger.Information("User {UserId} logged in from {IpAddress}", userId, ipAddress);

// В JSON:
{
    "Timestamp": "2026-07-17T12:00:00Z",
    "Level": "Information",
    "Message": "User 123 logged in from 192.168.1.1",
    "UserId": 123,
    "IpAddress": "192.168.1.1",
    "SourceContext": "MyApp.Services.AuthService"
}

Преимущества:

  • Можно фильтровать по полям (UserId=123)
  • Легко агрегировать (ELK, DataDog)
  • Лучше для анализа
Уровни логирования.
mid
Уровень Когда использовать
Trace Мельчайшие детали (отладка)
Debug Отладочная информация (для разработчиков)
Information Нормальная работа (логи в продакшене)
Warning Проблемы, которые не критичны
Error Ошибки, но приложение работает
Critical Критические ошибки (приложение падает)

Настройка уровней:

{
    "Logging": {
        "LogLevel": {
            "Default": "Information",
            "Microsoft.AspNetCore": "Warning",
            "MyApp": "Debug"
        }
    }
}
Health Checks — liveness, readiness, startup.
mid

Health Checks — проверка работоспособности приложения.

builder.Services.AddHealthChecks()
    .AddDbContextCheck<AppDbContext>()
    .AddRedis("localhost:6379");

app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = _ => true
});

app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false
});

В Kubernetes:

livenessProbe:
  httpGet:
    path: /health/live
    port: 80
  initialDelaySeconds: 30
  periodSeconds: 10

readinessProbe:
  httpGet:
    path: /health/ready
    port: 80
  initialDelaySeconds: 5
  periodSeconds: 5
OpenTelemetry — распределённая трассировка.
mid

OpenTelemetry — стандарт для сбора телеметрии.

builder.Services.AddOpenTelemetry()
    .WithTracing(tracing =>
    {
        tracing
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddSqlClientInstrumentation()
            .AddOtlpExporter(options =>
            {
                options.Endpoint = new Uri("http://jaeger:4317");
            });
    })
    .WithMetrics(metrics =>
    {
        metrics
            .AddAspNetCoreInstrumentation()
            .AddPrometheusExporter();
    });
