🗄️ 6. Spring Data JPA vs EF Core

EntityManager vs DbContext — разница

EntityManager (JPA) и DbContext (EF) — это главные объекты для работы с БД.

EntityManager (Java):

  • Управляет жизненным циклом сущностей
  • Содержит Persistence Context (1st level cache)
  • Методы: persist(), merge(), remove(), find(), createQuery()
  • Связан с транзакцией (@Transactional)
// Java — EntityManager
@Service
public class UserService {
    @PersistenceContext
    private EntityManager em;
    
    @Transactional
    public User save(User user) {
        em.persist(user);  // сохранить
        return user;
    }
    
    public User find(Long id) {
        return em.find(User.class, id);  // найти по ID
    }
    
    public List<User> findAll() {
        return em.createQuery("SELECT u FROM User u", User.class)
                 .getResultList();
    }
}

DbContext (C#):

public class AppDbContext : DbContext {
    public DbSet<User> Users { get; set; }
}

public class UserService {
    private readonly AppDbContext _db;
    
    public async Task<User> Save(User user) {
        _db.Users.Add(user);
        await _db.SaveChangesAsync();
        return user;
    }
    
    public async Task<User> Find(long id) {
        return await _db.Users.FindAsync(id);
    }
    
    public async Task<List<User>> FindAll() {
        return await _db.Users.ToListAsync();
    }
}
Persistence Context (1st level cache) — что это?

Persistence Context — это кэш первого уровня, который хранит загруженные сущности в рамках одной сессии/транзакции.

  • Автоматически кэширует загруженные сущности
  • Повторные запросы того же ID — без запроса к БД
  • Отслеживает изменения (dirty checking)
  • Живёт в рамках одной транзакции
@Transactional
public void example() {
    // 1-й запрос — идёт в БД
    User user1 = em.find(User.class, 1L);
    
    // 2-й запрос — берётся из кэша (БД не трогается)
    User user2 = em.find(User.class, 1L);
    
    // user1 == user2 — один и тот же объект!
    System.out.println(user1 == user2);  // true
    
    // Dirty checking — изменения сохранятся автоматически при коммите
    user1.setName("New Name");
    // ... конец транзакции — UPDATE в БД
}

В EF Core аналог — ChangeTracker:

var user1 = await _db.Users.FindAsync(1);
var user2 = await _db.Users.FindAsync(1);
// user1 == user2 — один объект (отслеживается)

user1.Name = "New Name";
await _db.SaveChangesAsync();  // UPDATE
2nd level cache (Hibernate) — почему в EF нет?

2nd level cache (L2 cache) — кэш, общий для всех сессий/EntityManager.

  • Хранит данные между разными транзакциями
  • Настраивается отдельно (EHCache, Redis, Hazelcast)
  • Требует осторожности (инвалидация, согласованность)
  • В EF Core нет встроенного L2 cache
// Подключение Hibernate L2 cache (EHCache)
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-jcache</artifactId>
</dependency>

// Настройка
@Cacheable
@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
@Entity
public class User {
    @Id
    private Long id;
    private String name;
}

// Использование — после первого запроса, данные будут в L2 cache
User user1 = em.find(User.class, 1L);  // идёт в БД
User user2 = em.find(User.class, 1L);  // из L2 cache (если сессия другая)

В C# — нет встроенного L2 cache. Решения:

  • Использовать IMemoryCache или IDistributedCache вручную
  • Второй уровень кэша EF Core — через сторонние библиотеки (EFCoreSecondLevelCacheInterceptor)
@Query vs NativeQuery — разница

@Query — для JPQL (Java Persistence Query Language), NativeQuery — для чистого SQL.

JPQL (@Query):

  • Работает с сущностями, а не таблицами
  • Переносимый между БД
  • Использует имена классов и полей

NativeQuery (nativeQuery = true):

  • Чистый SQL для конкретной БД
  • Можно использовать специфичные функции (PostgreSQL, MySQL)
  • Быстрее, но не переносимый
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    
    // JPQL — работа с сущностями
    @Query("SELECT u FROM User u WHERE u.age > :age")
    List<User> findOlderThan(@Param("age") int age);
    
    // JPQL с JOIN
    @Query("SELECT u FROM User u JOIN u.orders o WHERE o.total > :min")
    List<User> findUsersWithLargeOrders(@Param("min") BigDecimal min);
    
    // Native SQL — для сложных запросов
    @Query(value = "SELECT * FROM users WHERE age > ?1", nativeQuery = true)
    List<User> findOlderThanNative(int age);
    
    // Native с спецификой PostgreSQL
    @Query(value = "SELECT * FROM users WHERE data @> '{\"city\":\"Moscow\"}'::jsonb", nativeQuery = true)
    List<User> findByJson(String json);
}

В EF Core аналоги:

// LINQ (аналог JPQL)
var users = await _db.Users
    .Where(u => u.Age > age)
    .ToListAsync();

// Raw SQL (аналог NativeQuery)
var users = await _db.Users
    .FromSqlRaw("SELECT * FROM users WHERE age > {0}", age)
    .ToListAsync();
Pageable + Page — пагинация в Spring Data

Spring Data предоставляет удобную пагинацию через Pageable.

@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    Page<User> findByAgeGreaterThan(int age, Pageable pageable);
}

@Service
public class UserService {
    public Page<User> getUsers(int page, int size) {
        Pageable pageable = PageRequest.of(page, size, Sort.by("name").ascending());
        return repository.findByAgeGreaterThan(18, pageable);
    }
}

// Использование
Page<User> page = userService.getUsers(0, 10);
page.getContent();     // список пользователей
page.getTotalElements(); // всего записей
page.getTotalPages();   // всего страниц
page.hasNext();         // есть ли следующая

В EF Core аналог:

var users = await _db.Users
    .Where(u => u.Age > 18)
    .OrderBy(u => u.Name)
    .Skip(page * size)
    .Take(size)
    .ToListAsync();

var total = await _db.Users.CountAsync(u => u.Age > 18);
@EntityGraph — решение проблемы N+1

@EntityGraph — загрузка связанных сущностей в одном запросе (аналог Include в EF).

@Entity
public class User {
    @Id
    private Long id;
    private String name;
    
    @OneToMany(mappedBy = "user")
    private List<Order> orders;  // LAZY по умолчанию
}

@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    
    // N+1 проблема: каждый user вызывает отдельный запрос для orders
    
    // Решение 1: @EntityGraph
    @EntityGraph(attributePaths = {"orders"})
    @Query("SELECT u FROM User u")
    List<User> findAllWithOrders();
    
    // Решение 2: JOIN FETCH
    @Query("SELECT u FROM User u JOIN FETCH u.orders")
    List<User> findAllWithOrdersFetch();
}

// Или через аннотацию над методом JPA
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    @EntityGraph(attributePaths = {"orders", "orders.items"})
    List<User> findByAgeGreaterThan(int age);
}

В EF Core аналог — Include/ThenInclude:

var users = await _db.Users
    .Include(u => u.Orders)
    .ThenInclude(o => o.Items)
    .Where(u => u.Age > 18)
    .ToListAsync();
@MappedSuperclass — как abstract base class в EF

@MappedSuperclass — базовый класс, чьи поля наследуются, но сам не является таблицей.

@MappedSuperclass
public abstract class BaseEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @CreationTimestamp
    private LocalDateTime createdAt;
    
    @UpdateTimestamp
    private LocalDateTime updatedAt;
}

@Entity
public class User extends BaseEntity {
    private String name;
    private String email;
}

@Entity
public class Order extends BaseEntity {
    private BigDecimal total;
    private String status;
}

// Результат: таблицы users и orders имеют поля id, created_at, updated_at

В EF Core аналог — abstract base class:

public abstract class BaseEntity {
    public int Id { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime UpdatedAt { get; set; }
}

public class User : BaseEntity {
    public string Name { get; set; }
    public string Email { get; set; }
}
@Embeddable + @Embedded — как Owned Types в EF

@Embeddable — встраиваемый объект (Value Object), @Embedded — поле в сущности.

@Embeddable
public class Address {
    private String city;
    private String street;
    private String zipCode;
    
    // getters, setters
}

@Entity
public class User {
    @Id
    private Long id;
    private String name;
    
    @Embedded
    private Address address;  // поля address_city, address_street, address_zipcode
}

// Использование
User user = new User();
user.setName("John");
Address address = new Address();
address.setCity("Moscow");
address.setStreet("Lenina");
user.setAddress(address);

В EF Core аналог — Owned Types:

public class Address {
    public string City { get; set; }
    public string Street { get; set; }
    public string ZipCode { get; set; }
}

public class User {
    public int Id { get; set; }
    public string Name { get; set; }
    public Address Address { get; set; }
}

// Конфигурация
builder.OwnsOne(u => u.Address);
