🔄 30. Идемпотентность и обработка дубликатов Mid+

Что такое идемпотентность?
обяз

Идемпотентность — свойство операции, при котором повторный вызов даёт тот же результат.

Примеры:

  • GET — всегда идемпотентен (не меняет состояние)
  • PUT — идемпотентен (обновление ресурса)
  • DELETE — идемпотентен (первый раз 200, второй — 404)
  • POST — НЕ идемпотентен (создаёт новый ресурс)

Почему важно:

  • Сетевые проблемы → повторные запросы
  • At-least-once доставка сообщений
  • Retry в клиентах
Idempotency Key — как реализовать.
mid

Idempotency Key — уникальный идентификатор запроса.

Клиент:

// Клиент генерирует ключ
var idempotencyKey = Guid.NewGuid().ToString();
var request = new CreateOrderRequest { ... };

// Добавляет в заголовок
client.DefaultRequestHeaders.Add("Idempotency-Key", idempotencyKey);
var response = await client.PostAsync("/api/orders", content);

Сервер:

[HttpPost]
public async Task<IActionResult> CreateOrder(CreateOrderRequest request)
{
    // Проверка ключа
    var key = Request.Headers["Idempotency-Key"].FirstOrDefault();
    if (string.IsNullOrEmpty(key))
        return BadRequest("Idempotency-Key required");

    // Проверка в кэше/БД
    if (await _cache.ExistsAsync($"idempotent:{key}"))
    {
        // Возвращаем предыдущий результат
        var cached = await _cache.GetAsync<OrderResponse>($"idempotent:{key}");
        return Ok(cached);
    }

    // Обработка запроса
    var result = await _orderService.CreateAsync(request);

    // Сохраняем результат
    await _cache.SetAsync($"idempotent:{key}", result, TimeSpan.FromHours(24));

    return CreatedAtAction(nameof(GetOrder), new { id = result.Id }, result);
}
Обработка дубликатов в очередях.
mid

Проблема: At-least-once доставка → дубликаты сообщений.

Решение:

1. Idempotency Key в сообщении

public class Message
{
    public string IdempotencyKey { get; set; }
    public object Data { get; set; }
}

// Consumer
public async Task ProcessMessageAsync(Message message)
{
    if (await _cache.ExistsAsync(message.IdempotencyKey))
        return;  // Уже обработано

    await ProcessData(message.Data);
    await _cache.SetAsync(message.IdempotencyKey, "done", TimeSpan.FromHours(24));
}

2. Транзакционная обработка

// Использование транзакции БД
using var transaction = await _dbContext.Database.BeginTransactionAsync();
try
{
    await _dbContext.Orders.AddAsync(order);
    await _dbContext.SaveChangesAsync();
    
    // Только после сохранения
    await _messageBus.PublishAsync(new OrderCreatedEvent(order.Id));
    
    await transaction.CommitAsync();
}
catch
{
    await transaction.RollbackAsync();
    throw;
}

3. Deduplication Table

CREATE TABLE ProcessedMessages (
    MessageId VARCHAR(36) PRIMARY KEY,
    ProcessedAt DATETIME
);

-- Проверка перед обработкой
INSERT INTO ProcessedMessages (MessageId, ProcessedAt)
VALUES (@messageId, GETUTCDATE())
-- Если дубликат → ошибка
Как гарантировать exactly-once доставку.
mid

Exactly-once — идеальный случай, сложно реализовать.

Комбинация подходов:

  • Idempotency Key — уникальный ID запроса
  • Транзакция — атомарная запись в БД + публикация события
  • Outbox Pattern — сохранение событий в БД, доставка в фоне

Outbox Pattern:

// Создание заказа
public async Task CreateOrderAsync(Order order)
{
    using var transaction = await _dbContext.Database.BeginTransactionAsync();
    try
    {
        // 1. Сохраняем заказ
        await _dbContext.Orders.AddAsync(order);
        
        // 2. Сохраняем событие в Outbox
        var outbox = new OutboxMessage
        {
            Id = Guid.NewGuid(),
            Type = "OrderCreated",
            Data = JsonSerializer.Serialize(order),
            CreatedAt = DateTime.UtcNow
        };
        await _dbContext.OutboxMessages.AddAsync(outbox);
        
        await _dbContext.SaveChangesAsync();
        await transaction.CommitAsync();
    }
    catch { await transaction.RollbackAsync(); throw; }
}

// Фоновый процесс доставки
public class OutboxProcessor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            var messages = await _dbContext.OutboxMessages
                .Where(m => !m.Processed)
                .Take(100)
                .ToListAsync();
            
            foreach (var msg in messages)
            {
                try
                {
                    await _messageBus.PublishAsync(msg);
                    msg.Processed = true;
                    await _dbContext.SaveChangesAsync();
                }
                catch
                {
                    // Повтор позже
                }
            }
            
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
Как обрабатывать повторные запросы в REST API.
mid

GET — безопасен, можно повторять

[HttpGet("{id}")]
public IActionResult Get(int id)
{
    var user = _userService.Get(id);
    return user == null ? NotFound() : Ok(user);
}

PUT — идемпотентен

[HttpPut("{id}")]
public IActionResult Update(int id, User user)
{
    var existing = _userService.Get(id);
    if (existing == null) return NotFound();
    
    // Обновление (идемпотентно)
    existing.Name = user.Name;
    existing.Email = user.Email;
    _userService.Update(existing);
    return Ok(existing);
}

POST — реализуем идемпотентность

[HttpPost]
public async Task<IActionResult> Create([FromBody] User user, 
    [FromHeader(Name = "Idempotency-Key")] string key)
{
    if (string.IsNullOrEmpty(key))
        return BadRequest("Idempotency-Key required");

    // Проверка в кэше
    var cached = await _cache.GetAsync<User>($"idempotent:{key}");
    if (cached != null)
        return Ok(cached);

    // Создание
    var created = await _userService.CreateAsync(user);
    
    // Сохраняем в кэш
    await _cache.SetAsync($"idempotent:{key}", created, TimeSpan.FromHours(24));
    
    return CreatedAtAction(nameof(Get), new { id = created.Id }, created);
}
