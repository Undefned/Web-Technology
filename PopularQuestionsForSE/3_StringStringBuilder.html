🧵 3. String и StringBuilder 100%

String — иммутабельность: что это значит?
обяз

Иммутабельность (неизменяемость) — свойство объектов, которые нельзя изменить после создания.

Как это работает со строками:

  • Строка создаётся один раз и никогда не меняется
  • Любая операция (конкатенация, замена, вставка, удаление) создаёт новую строку
  • Старая строка остаётся в памяти до сборки мусора
  • Все строки в .NET иммутабельны

Почему это важно:

  • Безопасность: строки можно безопасно использовать в многопоточном коде
  • Производительность: можно использовать intern pool, кэширование
  • Надёжность: никакой код не может изменить вашу строку
  • Недостаток: много операций → много аллокаций → нагрузка на GC

Демонстрация:

string s = "Hello";
string s2 = s;              // s2 ссылается на ту же строку
s2 = s2 + " World";         // Создаётся НОВАЯ строка "Hello World"
Console.WriteLine(s);       // "Hello" — не изменилась!
Console.WriteLine(s2);      // "Hello World"

// В памяти:
// "Hello"    — всё ещё существует
// "Hello World" — новый объект

Решение проблемы:

  • Для частых изменений используйте StringBuilder
  • Он мутабельный и изменяет существующий буфер
  • Намного эффективнее в циклах
StringBuilder — внутреннее устройство (буфер).
обяз

StringBuilder — мутабельный класс для работы со строками.

Внутреннее устройство:

  • Содержит внутренний буфер — массив символов (char[])
  • Capacity — текущая ёмкость буфера
  • Length — текущая длина строки
  • При добавлении текста он изменяет буфер, а не создаёт новый объект
  • Когда длина превышает ёмкость, буфер автоматически расширяется
  • Расширение обычно в 2 раза

Структура:

public sealed class StringBuilder
{
    private char[] _buffer;     // Внутренний массив
    private int _length;        // Текущая длина
    private int _capacity;      // Ёмкость буфера
    private int _maxCapacity;   // Максимальная ёмкость
    
    // При добавлении
    public StringBuilder Append(string value)
    {
        int needed = _length + value.Length;
        if (needed > _capacity)
            EnsureCapacity(needed);  // Увеличиваем буфер
        // Копируем символы в буфер
        value.CopyTo(0, _buffer, _length, value.Length);
        _length += value.Length;
        return this;
    }
}

Оптимизация:

  • При создании можно задать начальную ёмкость: new StringBuilder(1000)
  • Это избегает многократных расширений
  • ToString() создаёт новую строку из буфера
  • Clear() сбрасывает длину, но сохраняет буфер

Пример:

var sb = new StringBuilder(100);  // Начальная ёмкость 100
Console.WriteLine(sb.Capacity);   // 100

sb.Append("Hello");               // Использует буфер
sb.Append(" World");              // Использует тот же буфер
sb.AppendFormat(" {0}", 42);      // "Hello World 42"

string result = sb.ToString();    // Создаёт строку

// Оптимизация: предварительное выделение
const int EXPECTED_SIZE = 10000;
var sbOptimized = new StringBuilder(EXPECTED_SIZE);
for (int i = 0; i < EXPECTED_SIZE; i++)
    sbOptimized.Append(i);  // Без перевыделений
Когда использовать StringBuilder vs string?
обяз

Используйте string когда:

  • Строка создаётся один раз и не изменяется
  • Конкатенация 2-3 строк (компилятор оптимизирует)
  • Нужно сравнение, поиск, чтение строк
  • Строка является константой или литералом
  • Работаете с ключами словаря (использует GetHashCode)

Используйте StringBuilder когда:

  • Строка часто изменяется (в циклах)
  • Более 5-10 конкатенаций в одном месте
  • Строите большие тексты (JSON, XML, HTML, SQL)
  • Неизвестен итоговый размер строки
  • Работаете в высоконагруженных системах

Сравнение производительности:

// ❌ ПЛОХО — много аллокаций
string s = "";
for (int i = 0; i < 10000; i++)
{
    s += i;  // Каждая итерация создаёт новую строку
}
// В памяти: 10000 объектов! Огромная нагрузка на GC

// ✅ ХОРОШО — один буфер
var sb = new StringBuilder(50000);  // Оптимальная ёмкость
for (int i = 0; i < 10000; i++)
{
    sb.Append(i);  // Изменяет существующий буфер
}
string result = sb.ToString();

Когда компилятор сам оптимизирует конкатенацию:

// Компилятор превращает это в одну строку
string s = "Hello" + " " + "World";  // Эквивалентно "Hello World"

// Но это уже не оптимизируется (переменные)
string s = a + b + c + d + e + f + g + h + i + j;  // Много аллокаций
String.Intern — пул строк.
mid

String.Intern() — механизм, который хранит уникальные строки в специальном пуле (intern pool).

Как работает:

  • Строковые литералы автоматически помещаются в пул
  • Динамически созданные строки — нет
  • String.Intern(str) — добавляет строку в пул или возвращает существующую
  • Если строка уже есть — возвращает ссылку на неё
  • Экономит память при множестве одинаковых строк

Пример:

string s1 = "Hello";                    // Литерал — в пуле
string s2 = new string('H', 5);         // "Hello" — не в пуле (новая память)
string s3 = string.Intern(s2);          // Помещаем в пул

Console.WriteLine(object.ReferenceEquals(s1, s2)); // False — разные объекты
Console.WriteLine(object.ReferenceEquals(s1, s3)); // True — один объект из пула

// Создание 1000 одинаковых строк без пула
for (int i = 0; i < 1000; i++)
{
    string s = new string('H', 5);  // 1000 отдельных объектов
}

// С пулом — один объект
string pool = string.Intern("Hello");
for (int i = 0; i < 1000; i++)
{
    string s = string.Intern("Hello");  // Все ссылаются на pool
}

Когда использовать:

  • Много одинаковых строк в памяти (например, названия тегов)
  • Строки читаются из файла или сети и часто повторяются
  • Не используйте: для уникальных строк (бесполезно)
  • Осторожно: строки в пуле не удаляются до конца приложения
Сравнение строк: Equals vs == vs Compare.
обяз

== и Equals: сравнивают значение строки (перегрузка оператора).

  • == — более читаемый
  • Equals — может использовать StringComparison
  • Оба сравнивают содержимое, а не ссылки
  • Для строк — одинаковы (для других типов — разница)

Compare: для сортировки (лексикографическое сравнение).

  • Возвращает int: отрицательное (меньше), 0 (равно), положительное (больше)
  • Используется в алгоритмах сортировки
  • Учитывает культуру по умолчанию

ReferenceEquals: сравнивает ссылки (адреса в памяти).

  • Не рекомендуется для строк
  • Может вернуть false для одинаковых строк из разных мест

Примеры:

string s1 = "Hello";
string s2 = "Hello";
string s3 = "HELLO";

Console.WriteLine(s1 == s2);                    // True (значение)
Console.WriteLine(s1.Equals(s2));               // True (значение)
Console.WriteLine(s1.CompareTo(s2));            // 0 (равны)
Console.WriteLine(string.Compare(s1, s3));      // -1 (регистр)
Console.WriteLine(string.Compare(s1, s3, true)); // 0 (без учёта регистра)

// ReferenceEquals
string s4 = new string("Hello".ToCharArray());  // Новая строка
Console.WriteLine(object.ReferenceEquals(s1, s4)); // False

Сравнение с учётом культуры:

// Ordinal — по байтам (быстро)
bool eq1 = string.Equals(s1, s2, StringComparison.Ordinal);

// InvariantCulture — стабильное сравнение
bool eq2 = string.Equals(s1, s2, StringComparison.InvariantCulture);

// CurrentCulture — системная культура
bool eq3 = string.Equals(s1, s2, StringComparison.CurrentCulture);

// IgnoreCase — без учёта регистра
bool eq4 = string.Equals(s1, s3, StringComparison.OrdinalIgnoreCase);
StringComparison — Ordinal, InvariantCulture, CurrentCulture.
mid

StringComparison.Ordinal:

  • Сравнивает по кодам символов (UTF-16)
  • Самый быстрый вариант
  • Не учитывает культурные правила
  • Используйте для: внутренних данных (пути, теги, ключи), парсинга

StringComparison.InvariantCulture:

  • Использует инвариантную культуру (стабильная для всех систем)
  • Одинаковое поведение на всех компьютерах
  • Чуть медленнее Ordinal
  • Используйте для: хранения данных, сортировки в нейтральной среде

StringComparison.CurrentCulture:

  • Учитывает текущую системную культуру
  • Поведение зависит от настроек ОС
  • Самый медленный
  • Используйте для: UI, пользовательского ввода, локализации

Варианты с игнорированием регистра:

  • OrdinalIgnoreCase — быстрое сравнение без учёта регистра
  • InvariantCultureIgnoreCase — как InvariantCulture, без регистра
  • CurrentCultureIgnoreCase — как CurrentCulture, без регистра

Примеры:

string a = "STRASSE";
string b = "Strasse";

// Ordinal — считает разными (S vs s)
bool o1 = string.Equals(a, b, StringComparison.Ordinal);          // False
bool o2 = string.Equals(a, b, StringComparison.OrdinalIgnoreCase); // True

// InvariantCulture — учитывает немецкие правила
bool i = string.Equals(a, b, StringComparison.InvariantCulture);   // False
bool ii = string.Equals(a, b, StringComparison.InvariantCultureIgnoreCase); // True

// Для сравнения с учётом языка
bool c = string.Equals("Strasse", "Straße", StringComparison.CurrentCulture);
// В немецкой культуре может быть True

Рекомендации Microsoft:

  • Для безопасности (сравнение паролей) — Ordinal
  • Для внутренних данных — Ordinal или OrdinalIgnoreCase
  • Для пользовательского ввода — CurrentCulture
  • Для сортировки в БД — InvariantCulture
StringBuilder.Append vs AppendLine vs AppendFormat.

Append: добавляет строку, массив символов, char.

sb.Append("Hello");
sb.Append('!');
sb.Append(new char[] { 'A', 'B' });

AppendLine: добавляет строку + перевод строки.

sb.AppendLine("Hello");      // "Hello\n"
sb.AppendLine();              // Пустая строка + перевод

AppendFormat: добавляет форматированную строку (как string.Format).

sb.AppendFormat("Name: {0}, Age: {1}", name, age);
sb.AppendFormat("{0:yyyy-MM-dd}", DateTime.Now);

Chain вызовов:

sb.Append("Hello")
  .AppendLine()
  .AppendFormat("Age: {0}", 30)
  .AppendLine(" years");

Производительность:

  • Append — самый быстрый
  • AppendLine — чуть медленнее (добавляет символы \r\n)
  • AppendFormat — медленнее (парсинг формата)
  • Совет: для максимальной производительности используйте Append с явными переносами
String.Create (C# 10) — высокопроизводительное создание строк.
mid

string.Create() — метод для создания строк с минимальным числом выделений памяти.

Как работает:

  • Создаёт строку заданной длины
  • Предоставляет Span<char> для прямой записи
  • Не создаёт промежуточных объектов
  • Аллокация только финальной строки

Сравнение с конкатенацией:

// ❌ Плохо — много аллокаций
string result = "Hello" + " " + "World" + "!";

// ✅ Хорошо — только одна аллокация
string result = string.Create(12, 42, (span, state) =>
{
    span[0] = 'H';
    span[1] = 'e';
    span[2] = 'l';
    span[3] = 'l';
    span[4] = 'o';
    span[5] = ' ';
    span[6] = 'W';
    span[7] = 'o';
    span[8] = 'r';
    span[9] = 'l';
    span[10] = 'd';
    span[11] = '!';
});

Практический пример:

// Создание строки с форматированием
string FormatPerson(string name, int age)
{
    // Определяем размер: "Name: X, Age: Y"
    int length = "Name: , Age: ".Length + name.Length + age.ToString().Length;
    
    return string.Create(length, (name, age), (span, state) =>
    {
        var (n, a) = state;
        int pos = 0;
        
        // Заполняем вручную
        "Name: ".AsSpan().CopyTo(span);
        pos += 6;
        n.AsSpan().CopyTo(span[pos..]);
        pos += n.Length;
        ", Age: ".AsSpan().CopyTo(span[pos..]);
        pos += 7;
        a.ToString().AsSpan().CopyTo(span[pos..]);
    });
}

Где использовать:

  • Высоконагруженные системы (HTTP-серверы, обработка данных)
  • Парсинг и сериализация
  • Когда важно минимизировать аллокации
  • Вместо StringBuilder для известной длины
