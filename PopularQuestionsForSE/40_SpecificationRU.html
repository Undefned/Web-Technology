1С интеграция — взаимодействие с 1С.
mid

1С — популярная ERP-система в РФ. Интеграция с .NET — частая задача.

Способы интеграции:

1. OData (HTTP)

// 1С публикует OData-сервис
// http://1c-server/odata/standard.odata
var client = new HttpClient();
var response = await client.GetAsync("http://1c-server/odata/standard.odata/Documents_Счет?$top=10");
var json = await response.Content.ReadAsStringAsync();
var documents = JsonSerializer.Deserialize<List<Document>>(json);

2. COM-объекты (1C:Enterprise 8)

// Добавить ссылку на com-объект 1С
var connection = new COMObject("V83.COMConnector");
var v8 = connection.CreateObject("V83.Application");
v8.Connect("File=""C:\\1C\\Base"";Usr=user;Pwd=password;");
var doc = v8.CreateObject("Document.Счет");
doc.Read(123);
var number = doc.Number;
doc.Post();

3. БД (прямой доступ к MSSQL)

  • 1C может работать с MSSQL
  • Прямые запросы к таблицам 1С (но это рискованно)
  • Лучше использовать представления или хранимые процедуры

4. Файловый обмен

  • XML/JSON файлы
  • CSV/Excel
  • Обмен через общую папку

5. Service Bus (RabbitMQ, Kafka)

  • 1С отправляет сообщения в очередь
  • .NET сервис обрабатывает
  • Асинхронная интеграция
ГОСТ-криптография — российские стандарты шифрования.
mid

ГОСТ-криптография — российские стандарты шифрования.

Основные ГОСТ:

  • ГОСТ 28147-89 — блочный шифр (устаревший, заменён на ГОСТ Р 34.12-2015)
  • ГОСТ Р 34.10-2012 — ЭЦП на основе эллиптических кривых (аналог ECDSA)
  • ГОСТ Р 34.11-2012 — хеш-функция Стрибог (аналог SHA-256)
  • ГОСТ Р 34.12-2015 — блочные шифры Кузнечик и Магма

Использование в .NET:

// Нужно установить пакет System.Security.Cryptography
// или использовать специализированные библиотеки (КриптоПро)

// Сертификаты по ГОСТ
var store = new X509Store(StoreName.My, StoreLocation.CurrentUser);
store.Open(OpenFlags.ReadOnly);
var certificates = store.Certificates.Find(
    X509FindType.FindByIssuerName, 
    "ГОСТ Р 34.10-2012", 
    false);

// Подпись по ГОСТ
using var gost = new Gost3410Signer(certificate);
var signature = gost.Sign(data);

// Проверка подписи
var isValid = gost.Verify(data, signature);

Требования по ФЗ-152:

  • Использовать российские криптографические алгоритмы
  • Сертифицированные СКЗИ (КриптоПро, VipNet)
  • Хранить ключи в сертифицированных ключевых носителях
ФСТЭК требования — аттестация и безопасность.
mid

ФСТЭК (Федеральная служба по техническому и экспортному контролю) — регулирует безопасность информационных систем.

Основные требования для разработчиков:

1. СУБД и ОС должны быть сертифицированы

  • Сертифицированные СУБД: PostgreSQL Pro, Oracle (спецверсия)
  • Сертифицированные ОС: Astra Linux, Alt Linux, Windows Server (сертифицированный)

2. Криптографические средства — сертифицированные СКЗИ

  • КриптоПро CSP
  • VipNet CSP
  • Signal-COM CSP

3. Строгое разграничение доступа

  • Роли и права (HR, RD, AD)
  • Мандатное управление доступом (MAC)

4. Аудит и логирование

  • Все действия логируются
  • Логи хранятся не менее 6 месяцев
  • Неизменяемость логов (WORM)

5. Классы защищённости (от К1 до К3)

  • К3 — минимальный
  • К1 — максимальный (военные системы)

Влияние на разработку:

  • Нет сторонних библиотек без сертификации
  • Нет доступа к внешним сетям (интернет, API)
  • Строгие контроль версий и ревью кода
  • Документирование всех изменений
Импортозамещение — российские аналоги.
mid

Импортозамещение — замена зарубежных продуктов на российские.

Что меняем:

Зарубежный Российский аналог
Windows Astra Linux, Alt Linux, Ред ОС
SQL Server PostgreSQL Pro, Tantor, Greenplum (российская поддержка)
Oracle PostgreSQL Pro
Kafka Кафка от VK (Managed Kafka)
RabbitMQ Yandex Message Queue
Azure/AWS Yandex Cloud, SberCloud, VK Cloud
GitHub GitFlic, GitLab (on-premise)
Jira Yandex Tracker, Jira (on-premise)
Slack Telegram (защищённая версия)

Влияние на .NET разработку:

  • .NET Core/5+ поддерживает Linux → можно использовать Astra Linux
  • PostgreSQL — отличная замена SQL Server
  • Yandex Cloud / SberCloud — замена Azure/AWS
  • GitFlic — замена GitHub

Сложности:

  • Не все библиотеки совместимы с Linux
  • Нужно адаптировать под российские ОС
  • Сертификация дополнительных компонентов
Postgres Pro / Альт — российские СУБД и ОС.
mid

PostgreSQL Pro — российская сборка PostgreSQL.

  • Полная совместимость с PostgreSQL
  • Сертифицирована ФСТЭК
  • Дополнительные модули и оптимизация
  • Техническая поддержка на русском
// PostgreSQL Pro — используется так же, как обычный PostgreSQL
// В .NET через Npgsql
var connectionString = "Host=localhost;Database=mydb;Username=postgres;Password=password;";
await using var conn = new NpgsqlConnection(connectionString);
await conn.OpenAsync();

await using var cmd = new NpgsqlCommand("SELECT * FROM users WHERE age > @age", conn);
cmd.Parameters.AddWithValue("@age", 18);
await using var reader = await cmd.ExecuteReaderAsync();

// Entity Framework Core с PostgreSQL Pro
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseNpgsql(connectionString));

Alt Linux / Astra Linux:

  • Российские ОС для госсектора
  • Сертифицированы ФСТЭК
  • .NET работает на Linux (включая Astra)

sudo apt-get update

dotnet --info

Рекомендации:

  • Используйте PostgreSQL Pro вместо SQL Server
  • Планируйте работу на Astra Linux
  • Тратьте время на сертификацию
  • Документируйте всю архитектуру
