🧱 1. Основы Go. Устройство и Философия

Для чего создавался Go? В чём его философия?

Go (или Golang) — язык программирования, созданный в Google в 2007–2009 годах. Его авторы — Роб Пайк, Кен Томпсон (создатель Unix) и Роберт Гризмер.

Почему они создали новый язык?

Им не нравились существующие языки для написания больших серверных систем:

  • C++ — слишком сложный, медленная компиляция, много небезопасных конструкций
  • Java — громоздкий, тяжёлая виртуальная машина, медленный старт
  • Python — медленный, плохо подходит для высоконагруженных систем

Философия Go — простота и эффективность:

  • Минимализм — в языке мало ключевых слов (всего 25), легко выучить
  • Быстрая компиляция — даже большие проекты собираются за секунды
  • Встроенная поддержка конкурентности — легко писать программы, которые используют все ядра процессора
  • Статическая типизация с выводом типов — безопасность + удобство
  • Единый стиль — встроенный форматтер go fmt избавляет от споров о форматировании
  • «Не умничай» — в Go часто есть только один правильный способ сделать что-то

Где используют Go:

  • Высоконагруженные бэкенд-сервисы (микросервисы)
  • Облачные технологии (Docker, Kubernetes написаны на Go)
  • Сетевые утилиты и прокси-серверы
  • Инструменты командной строки
Что такое GOPATH и почему от него отказались?

GOPATH — это старая система управления проектами в Go. Это была переменная окружения, которая указывала на папку, где Go искал ваш код и скачанные библиотеки.

Как это работало:

  • Вся работа должна была вестись внутри папки $GOPATH/src/
  • Проект должен был лежать по строгому пути: $GOPATH/src/github.com/ваш_аккаунт/название_проекта
  • Библиотеки скачивались в $GOPATH/pkg/ и $GOPATH/bin/

Почему отказались:

  • Неудобно работать с несколькими проектами одновременно
  • Невозможно использовать разные версии одной библиотеки в разных проектах
  • Сложно работать с системами контроля версий (Git)
  • Зависимости хранились глобально — проблемы с обновлениями

Что пришло на смену — Go Modules (с Go 1.11, 2018):

  • Теперь проект может лежать в любой папке на компьютере
  • Зависимости хранятся локально для каждого проекта
  • Файл go.mod — список всех библиотек и их версий
  • Файл go.sum — контрольные суммы для безопасности

Как начать новый проект сегодня:

mkdir my-project
cd my-project
go mod init github.com/ваш_аккаунт/my-project
# теперь можно писать код, добавлять зависимости через go get

Важно: GOPATH больше не используется в новых проектах, но некоторые старые проекты (и туториалы) могут его упоминать.

Что такое `go mod`? Основные команды.

Go Modules — это система управления зависимостями в Go. Она появилась как современная замена GOPATH.

Главные файлы:

  • go.mod — главный файл модуля. Там записаны:
    • Название модуля (путь к репозиторию)
    • Версия Go
    • Список всех зависимостей с их версиями
  • go.sum — файл с контрольными суммами (хэшами) всех библиотек. Гарантирует, что вы скачали именно те файлы, которые ожидаете.

Основные команды (очень важно знать):

КомандаЧто делает
go mod init <module_name>Создаёт новый модуль (файл go.mod)
go get <package>Добавляет зависимость (скачивает и обновляет go.mod)
go mod tidyУдаляет неиспользуемые зависимости и добавляет недостающие
go mod vendorКопирует все зависимости в папку vendor/ (для офлайн-сборки)
go mod whyПоказывает, зачем нужна конкретная зависимость
go mod verifyПроверяет, что зависимости не повреждены

Жизненный цикл работы с модулями:

# 1. Создаём проект
mkdir myapp && cd myapp
go mod init github.com/myuser/myapp

# 2. Добавляем внешнюю библиотеку
go get github.com/gorilla/mux

# 3. После удаления кода, который использовал библиотеку:
go mod tidy  # автоматически удалит ненужные зависимости

# 4. Обновить все зависимости до последних версий
go get -u ./...
Как компилируются Go-программы? Что такое горутины в рантайме?

Компиляция в Go:

  • Go — компилируемый язык, но компилируется он не в машинный код напрямую, а в машинный код через несколько этапов
  • Исходный код → промежуточное представление → оптимизация → машинный код
  • Результат — один исполняемый файл (.exe на Windows, без расширения на Linux/Mac)
  • В этом файле уже есть всё: и ваш код, и рантайм Go (сборщик мусора, планировщик горутин), и все библиотеки

Статическая линковка — что это?

  • Все библиотеки, которые вы используете, встраиваются прямо в исполняемый файл
  • Вам не нужно устанавливать .NET Runtime, JVM или что-то подобное
  • Вы просто копируете один файл на сервер и запускаете — это очень удобно

Что такое горутина (goroutine) на уровне рантайма?

  • Горутина — это легковесный поток выполнения. Легче обычного системного потока (потока ОС) в десятки раз.
  • Один системный поток может выполнять тысячи горутин
  • Планировщик Go сам решает, когда какую горутину запустить на каком ядре процессора
  • Горутины используют маленький начальный стек (около 2 КБ) и могут расширяться при необходимости
  • Это позволяет запускать миллионы горутин одновременно без проблем с памятью

Пример запуска горутины:

func main() {
    // Запускаем функцию в отдельной горутине
    go sayHello()
    
    // Ждём немного, чтобы горутина успела выполниться
    time.Sleep(time.Second)
}

func sayHello() {
    fmt.Println("Hello from goroutine!")
}
Точка входа — `func main()` и `package main`

В Go точка входа в программу — это функция main() в пакете main.

Что такое пакет main?

  • Это специальный пакет, который говорит компилятору: «Это исполняемая программа, а не библиотека»
  • Если вы пишете программу, которую можно запустить (.exe), она должна быть в package main
  • Если вы пишете библиотеку (пакет, который будут использовать другие), название пакета должно быть другим

Почему нет public static void main(String[] args), как в Java?

  • В Go всё проще — не нужно писать модификаторы доступа для main() и модификаторы класса
  • Go не использует классы как контейнеры для функций
  • Аргументы командной строки передаются через os.Args, а не через параметры функции

Минимальная программа в Go:

package main  // объявляем, что это исполняемая программа

import "fmt"  // подключаем пакет для форматированного вывода

func main() {
    fmt.Println("Привет, мир!")
}

Важные правила:

  • Функция main() не принимает аргументов и ничего не возвращает
  • Может быть только одна функция main() в пакете main
  • Имя пакета должно быть именно main (с маленькой буквы)
Как организовать код в Go? (cmd/, internal/, pkg/)

Стандартная структура проекта в Go не навязывается языком, но есть рекомендованные паттерны, которые используют большинство проектов.

Типичная структура:

myproject/
├── go.mod
├── go.sum
├── cmd/               # исполняемые программы
│   ├── server/        # отдельный сервер
│   │   └── main.go
│   └── client/        # отдельный клиент
│       └── main.go
├── internal/          # приватный код (только для этого проекта)
│   ├── database/
│   │   └── db.go
│   └── auth/
│       └── auth.go
├── pkg/               # публичные библиотеки (можно использовать извне)
│   ├── logger/
│   │   └── logger.go
│   └── utils/
│       └── utils.go
├── api/               # протоколы (gRPC, OpenAPI)
│   └── proto/
├── configs/           # конфигурационные файлы
└── scripts/           # вспомогательные скрипты

Что за папки:

  • cmd/ — здесь лежат исполняемые файлы. Каждый подкаталог внутри cmd/ — это отдельная программа.
  • internal/ — приватный код. Другие проекты не могут его импортировать. Это защищает внутреннюю логику.
  • pkg/ — публичный код. Другие проекты могут его импортировать. Это библиотеки, которые вы разработали для переиспользования.

Почему internal/ особенный?

  • Go запрещает импорт из папки internal/ за пределами родительского проекта
  • Это уровень защиты — вы можете менять код внутри internal/ без страха сломать внешние проекты

Когда использовать pkg/:

  • Когда вы хотите, чтобы другие разработчики использовали ваш код
  • Когда у вас есть утилиты, которые могут пригодиться в других проектах
Основные команды Go: go build, run, test, fmt, vet

Это самые важные команды, которые вы будете использовать каждый день:

КомандаЧто делаетПример
go build Компилирует программу в исполняемый файл go build -o myapp .
go run Компилирует и сразу запускает (для быстрой проверки) go run main.go
go test Запускает все тесты (*_test.go) go test -v ./...
go fmt Форматирует код по стандарту (всегда используйте!) go fmt ./...
go vet Проверяет код на потенциальные ошибки (статический анализ) go vet ./...

Почему go fmt важен:

  • В Go нет споров о форматировании — есть только один стиль
  • go fmt автоматически расставляет отступы, переносы, пробелы
  • Это экономит время и делает код читаемым для всех

Что такое go vet и зачем он нужен:

  • Находит ошибки, которые компилятор не может обнаружить
  • Примеры: неиспользуемые переменные, неправильные форматные строки в Printf, проблемы с конкурентностью
  • Запускайте перед каждым коммитом!

Самые частые флаги:

  • -v — подробный вывод (verbose)
  • -o имя_файла — задать имя выходного файла
  • ./... — означает «все подпакеты рекурсивно»
Что такое `defer`? Как он работает?

defer — это ключевое слово, которое откладывает выполнение функции до момента, когда текущая функция завершится.

Как это работает:

  • Когда вы пишете defer fmt.Println("Done"), эта строка не выполняется сразу
  • Она помещается в специальный стек (LIFO — Last In, First Out)
  • Когда функция main() (или другая) заканчивает работу, все defer-вызовы выполняются в обратном порядке

Пример:

func main() {
    defer fmt.Println("Третья")  // выполнится последней
    defer fmt.Println("Вторая")  // выполнится второй
    defer fmt.Println("Первая")  // выполнится первой
    fmt.Println("Основной код")
}
// Вывод:
// Основной код
// Первая
// Вторая
// Третья

Где используют defer на практике:

1. Закрытие файлов и соединений:

func readFile(filename string) {
    file, err := os.Open(filename)
    if err != nil {
        return
    }
    defer file.Close()  // файл закроется в любом случае
    
    // читаем файл...
}

2. Освобождение блокировок (мьютексов):

var mu sync.Mutex

func safeUpdate() {
    mu.Lock()
    defer mu.Unlock()  // мьютекс разблокируется автоматически
    
    // критическая секция...
}

3. Обработка паник:

defer func() {
    if r := recover(); r != nil {
        fmt.Println("Восстановились после паники:", r)
    }
}()

Важные моменты:

  • defer выполняется даже если произошла паника (кроме совсем фатальных ошибок)
  • Аргументы defer-функции вычисляются в момент объявления, а не выполнения
  • Используйте defer для любых операций очистки — это делает код надёжнее
Что такое пустой идентификатор `_`?

Пустой идентификатор _ (underscore) — это специальное место в Go, куда можно «выбросить» значение, которое вам не нужно.

Три основных использования:

1. Игнорирование возвращаемых значений:

// Функция возвращает два значения, но нам нужно только второе
_, err := os.Open("file.txt")
if err != nil {
    // обрабатываем ошибку
}

// Или игнорируем ошибку (не рекомендуется!)
_, _ = fmt.Println("Hello")

2. Игнорирование значения в итерации:

// Нам нужны только индексы, а не значения
for i, _ := range []int{1, 2, 3} {
    fmt.Println(i)  // 0, 1, 2
}

// Или нам нужны только значения, а не индексы
for _, value := range []int{1, 2, 3} {
    fmt.Println(value)  // 1, 2, 3
}

3. Импорт пакета только ради init():

import (
    "database/sql"
    _ "github.com/lib/pq"  // драйвер PostgreSQL регистрируется через init()
)

// Сам драйвер мы не используем, но он нужен для работы с БД

Почему это полезно:

  • Компилятор Go не позволяет оставлять неиспользуемые переменные
  • _ — способ сказать компилятору: «Я знаю, что это значение есть, но оно мне не нужно»
Документация и `godoc` — как документировать код?

В Go документация пишется прямо в коде — в виде обычных комментариев. Это называется «документирующие комментарии».

Правила написания документации:

  • Комментарий должен идти непосредственно перед объявлением функции, типа или пакета
  • Должен начинаться с имени элемента, который документирует
  • Желательно писать на английском (но можно и на русском, если проект внутренний)

Пример:

// Package mathutils содержит полезные математические функции.
package mathutils

// Add складывает два целых числа и возвращает результат.
// Пример:
//   result := Add(5, 3)  // result == 8
func Add(a, b int) int {
    return a + b
}

// Person представляет человека с именем и возрастом.
type Person struct {
    Name string
    Age  int
}

// Greet возвращает приветствие для человека.
func (p Person) Greet() string {
    return fmt.Sprintf("Привет, %s!", p.Name)
}

Как посмотреть документацию:

  • Онлайн: pkg.go.dev — там автоматически генерируется документация для всех публичных пакетов
  • Локально: go doc — показывает документацию в консоли
  • go doc Add — покажет документацию для функции Add
  • go doc -all — покажет всё

Советы:

  • Все публичные функции, типы, константы должны иметь документацию
  • Документация — это часть API, относитесь к ней серьёзно
  • В документации можно приводить примеры кода (они проверяются тестами!)
