🗄️ 37. NoSQL базы данных Mid+

MongoDB — документо-ориентированная БД.
mid

MongoDB — NoSQL БД с гибкой схемой (документы JSON).

Ключевые понятия:

  • Collection — аналог таблицы в SQL
  • Document — аналог строки (JSON)
  • BSON — бинарный JSON (быстрее, компактнее)
  • Index — для ускорения запросов

Пример в .NET (MongoDB.Driver):

// Подключение
var client = new MongoClient("mongodb://localhost:27017");
var database = client.GetDatabase("MyApp");
var collection = database.GetCollection<User>("Users");

// Модель
public class User
{
    [BsonId]
    public ObjectId Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    public int Age { get; set; }
    public List<string> Tags { get; set; }
}

// CRUD операции
// Вставка
await collection.InsertOneAsync(new User { Name = "Alice", Age = 30 });

// Поиск
var users = await collection.Find(u => u.Age > 18).ToListAsync();

// Поиск с проекцией
var names = await collection.Find(u => u.Age > 18)
    .Project(u => u.Name)
    .ToListAsync();

// Обновление
await collection.UpdateOneAsync(
    u => u.Id == id,
    Builders<User>.Update.Set(u => u.Age, 31));

// Удаление
await collection.DeleteOneAsync(u => u.Id == id);

// Агрегация
var avgAge = await collection.Aggregate()
    .Group(u => u.Age,
        g => new { Age = g.Key, Count = g.Count() })
    .ToListAsync();

Когда использовать MongoDB:

  • Гибкая схема (данные меняются)
  • Большие объёмы данных
  • Горизонтальное масштабирование
  • Вложенные структуры (документы внутри документов)
Redis — in-memory кэш.
mid

Redis — in-memory БД (самая популярная для кэша).

Структуры данных Redis:

  • String — простые значения
  • List — список (FIFO)
  • Set — множество (уникальные)
  • Sorted Set — множество с сортировкой
  • Hash — объект (ключ-значение)
  • Stream — очередь событий

Пример в .NET (StackExchange.Redis):

// Подключение
var connection = ConnectionMultiplexer.Connect("localhost:6379");
var db = connection.GetDatabase();

// String
await db.StringSetAsync("key", "value");
string value = await db.StringGetAsync("key");

// Hash
await db.HashSetAsync("user:1", "name", "Alice");
await db.HashSetAsync("user:1", "age", "30");
var name = await db.HashGetAsync("user:1", "name");
var all = await db.HashGetAllAsync("user:1");

// List (очередь)
await db.ListLeftPushAsync("queue", "item1");
await db.ListLeftPushAsync("queue", "item2");
var item = await db.ListRightPopAsync("queue");  // FIFO

// Set
await db.SetAddAsync("tags", "csharp");
await db.SetAddAsync("tags", "dotnet");
var members = await db.SetMembersAsync("tags");

// Sorted Set (лидерборды)
await db.SortedSetAddAsync("scoreboard", "Alice", 100);
await db.SortedSetAddAsync("scoreboard", "Bob", 200);
var top = await db.SortedSetRangeByRankAsync("scoreboard", 0, 1, Order.Descending);

// TTL
await db.KeyExpireAsync("key", TimeSpan.FromMinutes(10));

// Pub/Sub
var sub = connection.GetSubscriber();
await sub.SubscribeAsync("channel", (channel, message) =>
    Console.WriteLine($"Received: {message}"));
await sub.PublishAsync("channel", "Hello");
Elasticsearch — поиск и аналитика.
mid

Elasticsearch — поисковый движок + аналитика (ELK Stack).

Ключевые понятия:

  • Index — аналог таблицы
  • Document — JSON-документ
  • Shard — часть индекса (партицирование)
  • Query DSL — язык запросов (JSON)

Пример в .NET (Elasticsearch.Net / NEST):

// Подключение
var settings = new ConnectionSettings(new Uri("http://localhost:9200"))
    .DefaultIndex("users");
var client = new ElasticClient(settings);

// Модель
[ElasticsearchType(IdProperty = "Id")]
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
    [Text(Analyzer = "russian")]
    public string Description { get; set; }
}

// Индексация
await client.IndexDocumentAsync(new User { Id = 1, Name = "Alice", Description = "Разработчик C#" });

// Поиск
var response = await client.SearchAsync<User>(s => s
    .Query(q => q
        .Bool(b => b
            .Must(
                m => m.Match(mq => mq.Field(f => f.Name).Query("Alice")),
                m => m.Range(r => r.Field(f => f.Id).GreaterThan(0))
            )))
    .From(0)
    .Size(10));

// Полнотекстовый поиск (русский)
var searchResponse = await client.SearchAsync<User>(s => s
    .Query(q => q
        .Match(m => m
            .Field(f => f.Description)
            .Query("разработчик")
            .Analyzer("russian"))));

// Агрегации
var aggResponse = await client.SearchAsync<User>(s => s
    .Size(0)
    .Aggregations(a => a
        .Terms("by_name", t => t.Field(f => f.Name.Suffix("keyword")))));
Когда использовать NoSQL вместо SQL.
mid
Сценарий SQL NoSQL
Схема Фиксированная Гибкая (schemaless)
Транзакции ACID (строгие) BASE (eventual consistency)
Связи JOIN, Foreign Key Денормализация, вложенные документы
Масштабирование Вертикальное (сложное горизонтальное) Горизонтальное (sharding)
Скорость Средняя Высокая
Пример Финансы, учёт, CRM Каталоги, логи, аналитика, соцсети

Когда использовать SQL:

  • Строгие транзакции (деньги, заказы)
  • Сложные связи между данными
  • Схема стабильна
  • Нужны сложные запросы (JOIN, GROUP BY)

Когда использовать NoSQL:

  • Большие объёмы данных
  • Схема часто меняется
  • Высокая нагрузка (миллионы запросов)
  • Горизонтальное масштабирование
  • Вложенные структуры (документы)
  • Поиск (Elasticsearch)
  • Кэширование (Redis)
