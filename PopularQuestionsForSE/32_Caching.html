🗄️ 32. Кэширование стратегии и инвалидация Mid+

Cache-Aside — стратегия кэширования.
mid

Cache-Aside (Lazy Loading) — самая популярная стратегия.

Логика:

  1. Проверить кэш
  2. Если есть → вернуть
  3. Если нет → загрузить из БД
  4. Сохранить в кэш
  5. Вернуть
public async Task<User> GetUserAsync(int id)
{
    var cacheKey = $"user:{id}";
    
    // 1. Проверяем кэш
    var user = await _cache.GetAsync<User>(cacheKey);
    if (user != null)
        return user;
    
    // 2. Загружаем из БД
    user = await _db.Users.FindAsync(id);
    
    // 3. Сохраняем в кэш
    await _cache.SetAsync(cacheKey, user, TimeSpan.FromMinutes(10));
    
    return user;
}

// Обновление — инвалидация кэша
public async Task UpdateUserAsync(User user)
{
    await _db.SaveChangesAsync();
    await _cache.RemoveAsync($"user:{user.Id}");
}

Преимущества:

  • Простая реализация
  • Работает для любых данных
  • Кэшируются только запрошенные данные

Недостатки:

  • Cache Stampede (много запросов одновременно)
  • Нет автоматической инвалидации
Write-Through и Write-Behind.
mid

Write-Through (сквозная запись)

  • Запись одновременно в БД и кэш
  • Кэш всегда актуален
  • Медленнее (две операции)
public async Task UpdateUserAsync(User user)
{
    await _db.UpdateUserAsync(user);
    await _cache.SetAsync($"user:{user.Id}", user, TimeSpan.FromMinutes(10));
}

Write-Behind (Write-Back, отложенная запись)

  • Запись только в кэш (быстро)
  • Асинхронно синхронизируется с БД
  • Риск потери данных
  • Высокая производительность
public async Task UpdateUserAsync(User user)
{
    // Сразу в кэш
    await _cache.SetAsync($"user:{user.Id}", user, TimeSpan.FromMinutes(30));
    
    // Добавляем в очередь на синхронизацию
    await _queue.EnqueueAsync(new UserUpdateEvent(user));
}

// Фоновый процесс
public class UserSyncProcessor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            var events = await _queue.DequeueBatchAsync(100, stoppingToken);
            foreach (var evt in events)
            {
                await _db.UpdateUserAsync(evt.User);
            }
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}

Сравнение:

Стратегия Скорость записи Актуальность Риск потери
Cache-Aside Средняя Средняя Нет
Write-Through Медленная Высокая Нет
Write-Behind Быстрая Низкая Да
Cache Invalidation — как инвалидировать кэш.
mid

Cache Invalidation (инвалидация) — удаление устаревших данных из кэша.

Способы:

1. TTL (Time-To-Live) — время жизни

// Простой TTL
await _cache.SetAsync(key, data, TimeSpan.FromMinutes(10));

// Sliding TTL (продлевается при каждом обращении)
await _cache.SetAsync(key, data, new MemoryCacheEntryOptions
{
    SlidingExpiration = TimeSpan.FromMinutes(5)
});

2. Активная инвалидация (при обновлении данных)

public async Task UpdateUserAsync(User user)
{
    await _db.SaveChangesAsync();
    
    // Удаляем из кэша
    await _cache.RemoveAsync($"user:{user.Id}");
    await _cache.RemoveAsync($"users:list");
}

3. Версионирование

// Ключ содержит версию
var version = await _db.GetVersionAsync();
var key = $"users:list:v{version}";
var data = await _cache.GetAsync(key);

4. Event-based Invalidation (через брокер)

// Публикация события при изменении
await _eventBus.PublishAsync(new UserUpdatedEvent(user.Id));

// Подписка на события для инвалидации
public class UserCacheInvalidator : IEventHandler<UserUpdatedEvent>
{
    public async Task Handle(UserUpdatedEvent evt)
    {
        await _cache.RemoveAsync($"user:{evt.UserId}");
    }
}

5. Cache Stampede (защита от множественных запросов)

// Только один запрос к БД, остальные ждут
private readonly SemaphoreSlim _semaphore = new(1, 1);

public async Task<User> GetUserAsync(int id)
{
    var key = $"user:{id}";
    var user = await _cache.GetAsync<User>(key);
    if (user != null) return user;
    
    await _semaphore.WaitAsync();
    try
    {
        // Double-check после блокировки
        user = await _cache.GetAsync<User>(key);
        if (user != null) return user;
        
        user = await _db.Users.FindAsync(id);
        await _cache.SetAsync(key, user, TimeSpan.FromMinutes(10));
        return user;
    }
    finally
    {
        _semaphore.Release();
    }
}
Distributed Cache — Redis vs Memcached.
mid
Характеристика Redis Memcached
Тип Key-Value + структуры Key-Value (только строки)
Структуры List, Set, Hash, Sorted Set, Stream Нет
Персистентность Да (RDB/AOF) Нет (только в памяти)
Скорость Очень быстрый Очень быстрый
Сложность Средняя Низкая
Транзакции Да Нет
Lua скрипты Да Нет
Где использовать Сложное кэширование, сессии, lock Простое кэширование

Когда выбрать Redis:

  • Нужны сложные структуры данных
  • Нужна персистентность
  • Нужны транзакции/блокировки
  • Планируется масштабирование

Когда выбрать Memcached:

  • Простое кэширование (строки)
  • Максимальная производительность
  • Простота
  • Данные не важны (можно потерять)
