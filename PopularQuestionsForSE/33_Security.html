🔒 33. Security (OAuth2, IdentityServer, JWT) Mid+

OAuth2 — что это, flow'ы (Authorization Code, Client Credentials).
mid

OAuth2 — протокол авторизации для делегирования доступа.

Роли:

  • Resource Owner — владелец данных (пользователь)
  • Client — приложение, запрашивающее доступ
  • Authorization Server — выдает токены (IdentityServer, Keycloak)
  • Resource Server — защищённый API, проверяет токены

Authorization Code Flow (с PKCE) — для публичных клиентов (SPA, Mobile)

1. Клиент → Авторизация → Redirect на Login
2. Пользователь логинится
3. Авторизация → Redirect с code → Клиент
4. Клиент → Обмен code на токены → Авторизация
5. Авторизация → Возвращает Access Token + Refresh Token → Клиент

Client Credentials Flow — для серверных приложений

1. Клиент → ClientId + ClientSecret → Авторизация
2. Авторизация → Access Token → Клиент

Password Flow — устарел (небезопасен)

1. Клиент → Login + Password → Авторизация
2. Авторизация → Access Token → Клиент

Device Code Flow — для устройств без браузера

OpenID Connect — отличие от OAuth2.
mid

OAuth2 — авторизация (что можно делать).

  • Даёт доступ к API
  • Не содержит информации о пользователе
  • Токен — Access Token

OpenID Connect (OIDC) — аутентификация + авторизация.

  • Строится поверх OAuth2
  • Даёт информацию о пользователе (ID Token — JWT)
  • Содержит: sub (ID), name, email, picture
  • Использует UserInfo endpoint

Сравнение:

Характеристика OAuth2 OpenID Connect
Цель Авторизация (доступ к ресурсам) Аутентификация (кто пользователь)
Токены Access Token ID Token + Access Token
Информация о пользователе Нет Да (ID Token, UserInfo)
Используется для API доступ Вход в систему (Single Sign-On)

Пример ID Token (JWT):

{
    "iss": "https://auth.example.com",
    "sub": "1234567890",
    "aud": "myapp",
    "exp": 1516242622,
    "iat": 1516239022,
    "name": "John Doe",
    "email": "john@example.com",
    "picture": "https://example.com/avatar.jpg"
}
IdentityServer / Duende — реализация в .NET.
mid

IdentityServer — OAuth2/OpenID Connect сервер для .NET.

Настройка IdentityServer (Duende):

// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddIdentityServer()
    .AddInMemoryClients(new[]
    {
        new Client
        {
            ClientId = "myclient",
            ClientSecrets = { new Secret("secret".Sha256()) },
            AllowedGrantTypes = GrantTypes.ClientCredentials,
            AllowedScopes = { "api1" }
        }
    })
    .AddInMemoryApiScopes(new[]
    {
        new ApiScope("api1", "My API")
    })
    .AddTestUsers(new[]
    {
        new TestUser
        {
            SubjectId = "1",
            Username = "alice",
            Password = "password"
        }
    });

// Клиент (API)
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = "https://localhost:5001";
        options.Audience = "api1";
    });

// Использование в API
[Authorize]
[ApiController]
[Route("api/orders")]
public class OrdersController : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        var userId = User.FindFirst("sub")?.Value;
        return Ok(new { userId });
    }
}

JWT — углублённо (подпись, валидация, refresh token).
mid

Структура JWT: header.payload.signature

Подпись (Signature):

  • HS256 — симметричное шифрование (один секрет)
  • RS256 — асимметричное (публичный/приватный ключ)
// HS256 — быстрый, простой
var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes("super-secret-key"));
var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

// RS256 — безопаснее, для публичных клиентов
using var rsa = RSA.Create();
var privateKey = new RsaSecurityKey(rsa);
var creds = new SigningCredentials(privateKey, SecurityAlgorithms.RsaSha256);

Валидация токена:

var tokenHandler = new JwtSecurityTokenHandler();
var validationParameters = new TokenValidationParameters
{
    ValidateIssuer = true,
    ValidIssuer = "https://auth.example.com",
    ValidateAudience = true,
    ValidAudience = "myapi",
    ValidateLifetime = true,
    ValidateIssuerSigningKey = true,
    IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes("secret"))
};

try
{
    var principal = tokenHandler.ValidateToken(token, validationParameters, out _);
    // Токен валиден
}
catch (SecurityTokenException)
{
    // Токен не валиден
}

Политики авторизации — Policy-based authorization.
mid

Policy-based authorization — гибкая авторизация на основе политик.

Создание политики:

builder.Services.AddAuthorization(options =>
{
    // Простая политика
    options.AddPolicy("AdminOnly", policy =>
        policy.RequireRole("Admin"));
    
    // Сложная политика
    options.AddPolicy("CanEditUsers", policy =>
        policy.RequireClaim("permission", "edit_users")
              .RequireRole("Admin", "Manager")
              .RequireAssertion(context =>
                  context.User.HasClaim("department", "IT") ||
                  context.User.HasClaim("department", "HR")));
    
    // Политика с требованием возраста
    options.AddPolicy("Adult", policy =>
        policy.RequireAssertion(context =>
        {
            var ageClaim = context.User.FindFirst("age");
            return ageClaim != null && int.Parse(ageClaim.Value) >= 18;
        }));
});

Использование:

// В контроллере
[Authorize(Policy = "AdminOnly")]
[HttpGet]
public IActionResult Get() { }

[Authorize(Policy = "CanEditUsers")]
[HttpPut]
public IActionResult Update() { }

// В Razor
@if (User.HasClaim("permission", "edit_users"))
{
    <button>Edit</button>
}

Кастомный Authorization Handler:

public class MinimumAgeHandler : AuthorizationHandler<MinimumAgeRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        MinimumAgeRequirement requirement)
    {
        var ageClaim = context.User.FindFirst("age");
        if (ageClaim != null && int.Parse(ageClaim.Value) >= requirement.MinimumAge)
            context.Succeed(requirement);
        else
            context.Fail();
        return Task.CompletedTask;
    }
}

public class MinimumAgeRequirement : IAuthorizationRequirement
{
    public int MinimumAge { get; }
    public MinimumAgeRequirement(int age) => MinimumAge = age;
}
