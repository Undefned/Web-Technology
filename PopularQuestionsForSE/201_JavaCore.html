☕ 1. Java Core — отличия от C#

JVM vs CLR — в чем разница?

JVM (Java Virtual Machine) — виртуальная машина для Java. CLR (Common Language Runtime) — для .NET.

Основные отличия:

  • Языки: JVM — только Java (и совместимые), CLR — C#, F#, VB.NET
  • Байт-код: Java → .class (байт-код JVM), C# → .dll/.exe (IL)
  • Сборка мусора: JVM — G1, ZGC, Shenandoah; CLR — поколения (Gen 0,1,2)
  • JIT-компиляция: JVM — C1 (быстрый) и C2 (оптимизирующий); CLR — RyuJIT
  • Платформы: JVM — кроссплатформенная; CLR — исторически Windows, сейчас .NET Core кроссплатформенный
// В Java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, JVM!");
    }
}

// Компиляция: javac Main.java → Main.class
// Запуск: java Main
// В C#
public class Main {
    public static void Main(string[] args) {
        Console.WriteLine("Hello, CLR!");
    }
}

// Компиляция: csc Main.cs → Main.exe
// Запуск: dotnet run
Примитивы (int, long) vs ссылочные (Integer) — разница?

В Java есть два вида типов: примитивы и ссылочные (обёртки).

Примитивы (int, long, double, boolean, char, byte, short, float):

  • Хранятся в стеке
  • Не могут быть null
  • Значение по умолчанию: 0, false, '\u0000'
  • Быстрее, меньше памяти

Обёртки (Integer, Long, Double, Boolean, Character, Byte, Short, Float):

  • Хранятся в куче
  • Могут быть null
  • Имеют методы (toString, parseInt, compareTo)
  • Медленнее, больше памяти
// Java
int primitive = 42;        // прямое значение
Integer wrapper = 42;      // автобоксинг (int → Integer)
Integer nullable = null;   // можно null

// Автоупаковка (boxing) и распаковка (unboxing)
Integer boxed = 100;       // автоматическая упаковка
int unboxed = boxed;       // автоматическая распаковка

// Примитивы в коллекциях — только обёртки
List<Integer> list = new ArrayList<>();  // нельзя List<int>
// C# — всё через object (value types + reference types)
int value = 42;        // значимый тип
int? nullable = null;  // можно null через Nullable<T>
object boxed = value;  // boxing
int unboxed = (int)boxed;  // unboxing

// C# нет отдельной обёртки для int — int уже часть Unified Type System

Ключевое отличие от C#:

  • В Java примитивы и обёртки — это разные типы (int != Integer)
  • В C# int и object — это одно и то же (value type → object через boxing)
  • Java использует автобоксинг/анбоксинг (с Java 5), но это дорого
Checked vs Unchecked исключения — разница?

В Java исключения делятся на checked и unchecked. В C# все исключения unchecked.

Checked исключения (проверяемые):

  • Наследуются от Exception (кроме RuntimeException)
  • Компилятор требует их обрабатывать (try-catch или throws)
  • Примеры: IOException, SQLException, FileNotFoundException

Unchecked исключения (непроверяемые):

  • Наследуются от RuntimeException
  • Компилятор не требует их обрабатывать
  • Примеры: NullPointerException, ArrayIndexOutOfBoundsException, ArithmeticException
// Java — checked exception
public void readFile(String path) throws IOException {  // обязаны объявить
    FileInputStream file = new FileInputStream(path);
    // ...
}

// Использование — обязательно try-catch
try {
    readFile("test.txt");
} catch (IOException e) {
    e.printStackTrace();
}

// Java — unchecked exception (не нужно обрабатывать)
public void divide(int a, int b) {
    if (b == 0) {
        throw new ArithmeticException("Деление на ноль");
    }
    return a / b;
}
// C# — все исключения unchecked
public void ReadFile(string path) {
    var file = File.OpenRead(path);  // может бросить, но не обязаны объявлять
}

// Можем обработать, но не обязаны
try {
    ReadFile("test.txt");
} catch (IOException e) {
    // обработка
}

Почему в Java так сделали:

  • Checked exceptions — для ожидаемых ошибок (файл не найден, сеть недоступна)
  • Unchecked — для ошибок программиста (NPE, выход за границы)
  • В C# решили, что checked exceptions — это overhead и убрали
Модификаторы доступа в Java — отличие от C#

В Java есть 4 модификатора доступа. В C# — 6.

JavaC#Описание
publicpublicВезде
protectedprotectedВ классе + наследниках
default (package-private)internalВнутри пакета / сборки
privateprivateТолько внутри класса
—protected internalВнутри сборки ИЛИ наследники
—private protectedВнутри сборки И наследники

Особенности default (package-private):

  • Нет ключевого слова — просто не пишем модификатор
  • Доступно только внутри пакета
  • В C# аналог — internal (внутри сборки)
// Java
package com.example;

public class MyClass {
    public int publicField = 1;       // везде
    protected int protectedField = 2; // класс + наследники
    int defaultField = 3;             // внутри пакета (package-private)
    private int privateField = 4;     // только внутри класса
}
// C#
public class MyClass {
    public int publicField = 1;        // везде
    protected int protectedField = 2;  // класс + наследники
    internal int internalField = 3;    // внутри сборки
    private int privateField = 4;      // только внутри класса
    protected internal int piField;    // сборка ИЛИ наследники
    private protected int ppField;     // сборка И наследники
}
Final vs finally vs finalize — разница?

Три похожих слова, но совершенно разные вещи.

1. final — ключевое слово:

  • Переменная: нельзя изменить (как readonly в C#)
  • Метод: нельзя переопределить (как sealed в C#)
  • Класс: нельзя наследовать (как sealed в C#)

2. finally — блок в try-catch:

  • Выполняется всегда (даже при исключении)
  • Как в C#

3. finalize — метод для освобождения ресурсов:

  • Вызывается сборщиком мусора (GC) перед удалением
  • В C# аналог — ~ClassName() (финализатор/деструктор)
  • В Java 9+ deprecated — используют Cleaner
// Java
class Example {
    private final int CONSTANT = 42;  // final переменная — нельзя изменить
    
    public final void method() { }    // final метод — нельзя переопределить
    
    @Override
    protected void finalize() throws Throwable {  // вызовется перед удалением
        // освобождение ресурсов
        super.finalize();
    }
}

final class FinalClass { }  // final класс — нельзя наследовать
// C# аналоги
class Example {
    private const int CONSTANT = 42;  // const (или readonly)
    
    public sealed void Method() { }   // sealed метод
    
    ~Example() { }  // финализатор (finalize)
}

sealed class SealedClass { }  // sealed класс
static nested class vs inner class — разница?

В Java вложенные классы бывают двух типов: static и non-static (inner).

Static Nested Class:

  • Не имеет доступа к нестатическим полям внешнего класса
  • Может создаваться без экземпляра внешнего класса
  • Как обычный класс, но внутри другого

Inner Class (Non-static):

  • Имеет доступ ко всем полям внешнего класса
  • Всегда связан с экземпляром внешнего класса
  • Не может существовать без внешнего объекта
public class Outer {
    private String name = "Outer";
    
    // Static nested class
    public static class StaticNested {
        public void print() {
            // Не имеет доступа к name (нестатическое поле)
        }
    }
    
    // Inner class (non-static)
    public class Inner {
        public void print() {
            System.out.println(name);  // есть доступ к полю внешнего класса
        }
    }
}

// Использование
Outer.StaticNested nested = new Outer.StaticNested();  // без внешнего объекта

Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();  // с внешним объектом

В C# — только nested классы (все static, если объявлены static):

public class Outer {
    private string name = "Outer";
    
    public class Nested {  // всегда имеет доступ к полям внешнего
        public void Print(Outer outer) {
            Console.WriteLine(outer.name);  // нужен экземпляр
        }
    }
    
    public static class StaticNested {  // static nested
        // Не имеет доступа к нестатическим полям
    }
}
Enum в Java vs C# — разница?

В Java enum — это полноценный класс. В C# enum — это структура (значимый тип).

Java Enum:

  • Наследуется от java.lang.Enum
  • Может иметь поля, методы, конструкторы
  • Может реализовывать интерфейсы
  • Каждый элемент — это статический объект своего класса
// Java
public enum Status {
    PENDING(0, "Ожидает"),
    APPROVED(1, "Одобрено"),
    REJECTED(2, "Отклонено");
    
    private int code;
    private String description;
    
    Status(int code, String description) {
        this.code = code;
        this.description = description;
    }
    
    public int getCode() { return code; }
    public String getDescription() { return description; }
}

// Использование
Status status = Status.APPROVED;
System.out.println(status.getDescription());  // "Одобрено"

C# Enum:

  • Наследуется от System.Enum (значимый тип)
  • Не может иметь методов и полей (только значения)
  • Для расширения — extension methods
// C#
public enum Status {
    Pending = 0,
    Approved = 1,
    Rejected = 2
}

// Расширение для enum
public static class StatusExtensions {
    public static string GetDescription(this Status status) {
        switch (status) {
            case Status.Pending: return "Ожидает";
            case Status.Approved: return "Одобрено";
            case Status.Rejected: return "Отклонено";
            default: return "Неизвестно";
        }
    }
}
Аннотации (Annotations) vs Атрибуты (Attributes) — разница?

Аннотации в Java и атрибуты в C# — метаданные для кода.

Java Annotations:

  • Создаются через @interface
  • Могут иметь элементы (атрибуты)
  • Ретеншн: SOURCE (только код), CLASS (в байт-коде), RUNTIME (доступно в рантайме через Reflection)
  • Обрабатываются через Reflection или Annotation Processors
// Java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Loggable {
    String value() default "INFO";
    boolean enabled() default true;
}

// Использование
@Loggable(value = "DEBUG", enabled = true)
public void process() { }

// Чтение через Reflection
Method method = MyClass.class.getMethod("process");
Loggable loggable = method.getAnnotation(Loggable.class);
if (loggable != null) {
    System.out.println(loggable.value());  // "DEBUG"
}

C# Attributes:

  • Создаются через class с наследованием от Attribute
  • Имеют свойства (positional + named параметры)
  • Ретеншн: AttributeTargets — к чему можно применить
  • Обрабатываются через Reflection
// C#
[AttributeUsage(AttributeTargets.Method)]
public class LoggableAttribute : Attribute {
    public string Value { get; set; } = "INFO";
    public bool Enabled { get; set; } = true;
}

// Использование
[Loggable(Value = "DEBUG", Enabled = true)]
public void Process() { }

// Чтение через Reflection
var method = typeof(MyClass).GetMethod("Process");
var attr = method.GetCustomAttribute<LoggableAttribute>();
if (attr != null) {
    Console.WriteLine(attr.Value);  // "DEBUG"
}
