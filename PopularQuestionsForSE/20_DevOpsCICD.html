⚙️ 20. DevOps и CI/CD Mid+

Что такое CI/CD? GitHub Actions / GitLab CI.
обяз

CI (Continuous Integration) — непрерывная интеграция.

  • Автоматическая сборка после каждого коммита
  • Запуск тестов
  • Быстрое обнаружение ошибок

CD (Continuous Delivery / Deployment) — непрерывная доставка/развёртывание.

  • Автоматический деплой после успешной сборки
  • Можно настроить разные окружения (Dev, Staging, Prod)

GitHub Actions:

# .github/workflows/deploy.yml
name: Build and Deploy

on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '8.0'
      - run: dotnet restore
      - run: dotnet build --configuration Release
      - run: dotnet test
      - run: dotnet publish -c Release -o ./publish
      - uses: actions/upload-artifact@v3
        with:
          name: app
          path: ./publish

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v3
        with:
          name: app
      - name: Deploy to Azure
        uses: azure/webapps-deploy@v2
        with:
          app-name: 'myapp'
          publish-profile: ${{ secrets.AZURE_PUBLISH_PROFILE }}
          package: .
Docker Compose — для локальной разработки.
mid

Docker Compose — запуск нескольких контейнеров вместе.

Зачем:

  • Локальная разработка (API + БД + Redis)
  • Одна команда: docker-compose up
  • Настройка связей между контейнерами

Пример:

version: '3.8'

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "5000:80"
    environment:
      - ConnectionStrings__Default=Server=db;Database=MyApp;User=sa;Password=Passw0rd!
    depends_on:
      - db
      - redis

  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=Passw0rd!
    ports:
      - "1433:1433"
    volumes:
      - sql-data:/var/opt/mssql

  redis:
    image: redis:alpine
    ports:
      - "6379:6379"

volumes:
  sql-data:
Kubernetes (Pods, Services, Ingress) — базово.
mid

Kubernetes — оркестратор контейнеров.

Основные объекты:

1. Pod — минимальная единица (один или несколько контейнеров)

  • Общая сеть, общий том
  • Временный (может быть пересоздан)

2. Service — стабильный адрес для Pod'ов

  • ClusterIP: только внутри кластера
  • NodePort: доступ извне на порт ноды
  • LoadBalancer: внешний IP (для облаков)

3. Ingress — маршрутизация внешнего трафика

  • HTTP/HTTPS
  • Маршрутизация по пути/домену

4. Deployment — управление версиями Pod'ов

  • Масштабирование (replicas)
  • Rolling update (без простоя)
  • Rollback (откат)

5. ConfigMap / Secret — конфигурация

  • ConfigMap — текстовые настройки
  • Secret — пароли, ключи (Base64)

Пример:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: api
        image: myapp/api:v1
        ports:
        - containerPort: 80
        env:
        - name: ConnectionString
          valueFrom:
            secretKeyRef:
              name: db-secret
              key: connection-string
Helm Charts — управление Kubernetes приложениями.
mid

Helm — пакетный менеджер для Kubernetes.

Зачем:

  • Шаблонизация манифестов
  • Управление версиями приложений
  • Повторное использование конфигураций
  • Одна команда для установки сложного приложения

Структура Helm Chart:

mychart/
├── Chart.yaml          # Метаданные (название, версия)
├── values.yaml         # Значения по умолчанию
├── templates/          # Шаблоны Kubernetes
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   └── _helpers.tpl

Пример templates/deployment.yaml:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Values.appName }}
spec:
  replicas: {{ .Values.replicas }}
  template:
    spec:
      containers:
      - name: {{ .Values.appName }}
        image: {{ .Values.image.repository }}:{{ .Values.image.tag }}
        ports:
        - containerPort: {{ .Values.port }}

Команды Helm:

helm install myapp ./mychart
helm upgrade myapp ./mychart
helm rollback myapp 1
helm uninstall myapp
Мониторинг (Prometheus, Grafana) — базово.
mid

Мониторинг — отслеживание состояния приложений и инфраструктуры.

Prometheus — сбор метрик.

  • Pull-модель (сам опрашивает сервисы)
  • Хранит временные ряды
  • Язык запросов (PromQL)
  • Интеграция с .NET (OpenTelemetry, prometheus-net)

Grafana — визуализация.

  • Дашборды
  • Alert'ы
  • Поддерживает Prometheus, Elasticsearch, Loki

Пример в .NET:

// prometheus-net
app.UseHttpMetrics();
app.UseMetricServer();

// Или OpenTelemetry
builder.Services.AddOpenTelemetry()
    .WithMetrics(metrics =>
    {
        metrics
            .AddAspNetCoreInstrumentation()
            .AddPrometheusExporter();
    });

Важные метрики:

  • CPU / Memory (Node, Pod)
  • Request Rate (RPS)
  • Error Rate (5xx)
  • Response Time (P50, P95, P99)
Логирование (ELK, Seq) — базово.
mid

Логирование — сбор и анализ логов.

ELK Stack:

  • Elasticsearch: хранение и поиск логов
  • Logstash: обработка логов
  • Kibana: визуализация

Seq:

  • Простой, удобный для .NET
  • Структурированные логи (JSON)
  • Поддерживает Serilog

Пример с Serilog:

// Program.cs
Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .WriteTo.Seq("http://seq:5341")
    .WriteTo.Elasticsearch(new ElasticsearchSinkOptions(
        new Uri("http://elasticsearch:9200"))
    {
        IndexFormat = "logs-{0:yyyy.MM.dd}"
    })
    .CreateLogger();

builder.Host.UseSerilog();

// В коде
_logger.LogInformation("User {UserId} logged in", userId);

Структурированные логи (JSON):

{
    "Timestamp": "2026-07-17T12:00:00Z",
    "Level": "Information",
    "Message": "User 123 logged in",
    "UserId": 123,
    "SourceContext": "MyApp.Services.AuthService"
}
