📦 2. Сборка и запуск — Maven, Gradle, JAR

javac vs java — компиляция и запуск

javac — компилятор Java, java — виртуальная машина для запуска.

# Компиляция
javac MyProgram.java          # создаёт MyProgram.class

# Запуск
java MyProgram                # выполняет MyProgram

# С указанием classpath
javac -cp lib/*.jar MyProgram.java
java -cp .:lib/*.jar MyProgram

В C# аналоги:

# Компиляция
csc MyProgram.cs              # создаёт MyProgram.exe

# Запуск
dotnet run                    # через .NET CLI
./MyProgram.exe               # напрямую (Windows)
JAR vs WAR vs EAR — разница?

Три типа Java-архивов для разных целей.

JAR (Java ARchive):

  • Обычный архив с .class файлами
  • Для библиотек, утилит, консольных приложений
  • Содержит MANIFEST.MF (метаданные)

WAR (Web Application Archive):

  • Для веб-приложений (Servlet, JSP)
  • Содержит WEB-INF/ с web.xml и lib/
  • Разворачивается в Tomcat, Jetty, JBoss

EAR (Enterprise Application Archive):

  • Для корпоративных приложений (Java EE)
  • Содержит несколько WAR + EJB-JAR
  • Разворачивается в GlassFish, WildFly, WebLogic

В C# аналоги:

  • JAR → .dll / .exe
  • WAR → .dll + wwwroot/ в ASP.NET Core
  • EAR → нет аналога (все в одном .dll или микросервисы)
Maven vs Gradle — сравнение

Maven и Gradle — инструменты сборки для Java.

Maven:

  • XML-конфигурация (pom.xml)
  • Декларативный подход
  • Строгая структура проекта
  • Медленнее Gradle

Gradle:

  • Groovy/Kotlin DSL (build.gradle)
  • Программный подход (можно писать логику)
  • Быстрее (инкрементальная сборка, кэширование)
  • Используется в Android

В C# аналог — MSBuild + .csproj:

  • .csproj — XML (как Maven)
  • dotnet build — через CLI
  • NuGet — для зависимостей
pom.xml vs build.gradle — структура

pom.xml (Maven):

<project>
    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>
    
    <properties>
        <java.version>17</java.version>
    </properties>
    
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>3.1.0</version>
        </dependency>
    </dependencies>
</project>

build.gradle (Gradle):

plugins {
    id 'java'
    id 'org.springframework.boot' version '3.1.0'
}

group = 'com.example'
version = '1.0.0'
sourceCompatibility = '17'

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

В C# аналог — .csproj:

<Project Sdk="Microsoft.NET.Sdk.Web">
    <PropertyGroup>
        <TargetFramework>net8.0</TargetFramework>
        <ImplicitUsings>enable</ImplicitUsings>
    </PropertyGroup>
    
    <ItemGroup>
        <PackageReference Include="Microsoft.EntityFrameworkCore" Version="8.0.0" />
    </ItemGroup>
</Project>
Maven lifecycle — clean, compile, test, package, install, deploy

Maven имеет стандартный жизненный цикл сборки.

  • clean — удаляет папку target/ (очистка)
  • compile — компилирует исходники в target/classes/
  • test — запускает тесты (JUnit)
  • package — создаёт JAR/WAR в target/
  • install — копирует JAR в локальный репозиторий (~/.m2)
  • deploy — загружает JAR в удалённый репозиторий (Nexus, Artifactory)
# Команды Maven
mvn clean           # очистка
mvn compile         # компиляция
mvn test            # тесты
mvn package         # сборка JAR
mvn install         # установка в локальный репозиторий
mvn deploy          # деплой в удалённый репозиторий

# Комбинации
mvn clean install   # очистка + установка
mvn clean package   # очистка + сборка

В C# аналоги:

dotnet clean        # очистка (bin/obj)
dotnet build        # компиляция
dotnet test         # тесты
dotnet publish      # сборка для деплоя
dotnet pack         # создание NuGet-пакета
