BeanFactory vs ApplicationContext — разница

Оба — контейнеры для управления бинами, но ApplicationContext — более мощный.

BeanFactory:

  • Базовый контейнер
  • Ленивая инициализация (bean создаётся при первом запросе)
  • Меньше функциональности

ApplicationContext:

  • Расширяет BeanFactory
  • Eager инициализация (все singleton бины создаются при старте)
  • Поддержка событий (ApplicationEvent)
  • Поддержка интернационализации (i18n)
  • Поддержка AOP
// BeanFactory (редко используется)
BeanFactory factory = new XmlBeanFactory(new ClassPathResource("beans.xml"));
MyBean bean = (MyBean) factory.getBean("myBean");

// ApplicationContext (стандарт)
ApplicationContext ctx = new ClassPathXmlApplicationContext("beans.xml");
MyBean bean = ctx.getBean(MyBean.class);

// Spring Boot — ещё удобнее
@SpringBootApplication
public class App {
    public static void main(String[] args) {
        ApplicationContext ctx = SpringApplication.run(App.class, args);
    }
}

В C# аналог — IServiceProvider:

var services = new ServiceCollection();
services.AddSingleton<MyService>();
var provider = services.BuildServiceProvider();

var service = provider.GetService<MyService>();
Bean Lifecycle — init-method, destroy-method, @PostConstruct, @PreDestroy

Жизненный цикл бина в Spring.

Порядок:

  1. Создание экземпляра (конструктор)
  2. Внедрение зависимостей (setter-ы)
  3. @PostConstruct → init-method → InitializingBean.afterPropertiesSet()
  4. Бин готов к использованию
  5. При закрытии контекста: @PreDestroy → destroy-method → DisposableBean.destroy()
@Component
public class MyBean {
    public MyBean() {
        System.out.println("1. Конструктор");
    }
    
    @PostConstruct
    public void init() {
        System.out.println("2. @PostConstruct");
    }
    
    @PreDestroy
    public void destroy() {
        System.out.println("5. @PreDestroy");
    }
}

// XML-вариант
<bean id="myBean" class="MyBean"
      init-method="initMethod"
      destroy-method="destroyMethod"/>

В C# аналоги:

  • @PostConstruct → IHostedService.StartAsync()
  • @PreDestroy → IHostedService.StopAsync() / IDisposable
@Qualifier vs @Primary — разница

Когда несколько бинов одного типа, нужно указать, какой использовать.

@Primary:

  • Указывает, какой бин использовать по умолчанию
  • Если есть несколько бинов — будет выбран primary

@Qualifier:

  • Указывает конкретный бин по имени
  • Приоритет выше, чем @Primary
// Определяем два бина
@Component
public class FastPayment implements PaymentService { }

@Component
@Primary  // выбран по умолчанию
public class DefaultPayment implements PaymentService { }

// Использование
@Service
public class OrderService {
    private final PaymentService payment;
    
    @Autowired
    public OrderService(@Qualifier("fastPayment") PaymentService payment) {
        this.payment = payment;  // конкретно FastPayment
    }
}

// Без @Qualifier — будет DefaultPayment (из-за @Primary)

В C# аналоги:

// В C# нет прямого аналога, но можно через ключи
services.AddScoped<IPaymentService, FastPaymentService>("fast");
services.AddScoped<IPaymentService, DefaultPaymentService>();

// Использование через ключ
var service = provider.GetKeyedService<IPaymentService>("fast");
@Lazy — зачем нужен?

@Lazy откладывает создание бина до первого запроса.

  • По умолчанию все singleton бины создаются при старте (eager)
  • @Lazy — создаётся при первом обращении
  • Уменьшает время старта приложения
  • Помогает избежать циклических зависимостей
// Бин создаётся при первом вызове
@Component
@Lazy
public class HeavyService {
    public HeavyService() {
        System.out.println("Создание HeavyService (только при первом запросе)");
    }
}

// При внедрении тоже можно использовать @Lazy
@Service
public class OrderService {
    private final HeavyService heavy;
    
    @Autowired
    public OrderService(@Lazy HeavyService heavy) {
        this.heavy = heavy;  // прокси вместо реального бина
    }
}

В C# аналог:

// C# — можно через Lazy<T> или IServiceProvider
services.AddScoped<HeavyService>();

public class OrderService {
    private readonly Lazy<HeavyService> _heavy;
    
    public OrderService(Lazy<HeavyService> heavy) {
        _heavy = heavy;  // создастся при первом обращении
    }
}
@Profile — переключение конфигураций

@Profile активирует бин только для определённых профилей (окружений).

// Бин только для dev-профиля
@Component
@Profile("dev")
public class DevDataSource { }

// Бин только для prod-профиля
@Component
@Profile("prod")
public class ProdDataSource { }

// Для нескольких профилей
@Component
@Profile({"dev", "staging"})
public class StagingService { }

Активация профилей:

# application.properties
spring.profiles.active=dev

# Или через JVM-аргумент
-Dspring.profiles.active=prod

# В тестах
@ActiveProfiles("test")

В C# аналог:

// В C# — через IHostEnvironment.EnvironmentName
if (env.IsDevelopment()) {
    services.AddScoped<IDataSource, DevDataSource>();
} else if (env.IsProduction()) {
    services.AddScoped<IDataSource, ProdDataSource>();
}
@Conditional — условная регистрация бинов

@Conditional — регистрирует бин только при выполнении условия.

Встроенные условия:

  • @ConditionalOnClass — если есть класс в classpath
  • @ConditionalOnMissingClass — если нет класса
  • @ConditionalOnProperty — если есть свойство
  • @ConditionalOnWebApplication — если веб-приложение
  • @ConditionalOnBean — если есть бин
// Бин только если есть свойство "cache.enabled=true"
@Component
@ConditionalOnProperty(name = "cache.enabled", havingValue = "true")
public class RedisCache { }

// Бин только если есть класс DriverManager (для БД)
@ConditionalOnClass(DriverManager.class)
@Component
public class DatabaseInitializer { }

Кастомное условие:

public class WindowsCondition implements Condition {
    @Override
    public boolean matches(ConditionContext ctx, AnnotatedTypeMetadata meta) {
        return System.getProperty("os.name").toLowerCase().contains("win");
    }
}

@Component
@Conditional(WindowsCondition.class)
public class WindowsService { }
SpEL (Spring Expression Language) — что это?

SpEL — язык выражений для динамической конфигурации.

Где используется:

  • @Value аннотации
  • @ConditionalOnExpression
  • XML-конфигурация
// Внедрение значений
@Value("#{systemProperties['user.name']}")
private String username;

@Value("#{2 + 3}")
private int sum;  // 5

@Value("#{T(Math).random()}")
private double random;

@Value("#{systemProperties['java.home']}")
private String javaHome;

// Вызов методов
@Value("#{myBean.doSomething()}")
private String result;

// Условные выражения
@ConditionalOnExpression("#{systemProperties['os.name'].contains('Windows')}")

В C# аналогов нет — используется конфигурация через код.
