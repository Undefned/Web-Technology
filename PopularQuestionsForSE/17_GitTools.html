📚 17. Git. Инструменты база

Основные команды Git: clone, commit, push, pull, fetch.
обяз

clone — копирование репозитория

git clone https://github.com/user/repo.git

commit — сохранение изменений

git add .                    # Добавить все файлы
git commit -m "Сообщение"   # Создать коммит
git commit --amend          # Изменить последний коммит

push — отправка изменений в удалённый репозиторий

git push origin main
git push --force           # Принудительно (опасно!)

pull — получение изменений + слияние (fetch + merge)

git pull origin main

fetch — получение изменений без слияния

git fetch origin
git diff origin/main      # Посмотреть изменения

Другие важные команды:

git status                 # Состояние
git log                    # История
git branch                 # Список веток
git checkout               # Переключение ветки
git merge                  # Слияние веток
git rebase                 # Перебазирование
rebase vs merge — разница, когда использовать.
обяз

merge — сохраняет историю ветвления

git checkout main
git merge feature

# История: ветки остаются, появляется commit merge

rebase — переписывает историю (линейная)

git checkout feature
git rebase main

# История: коммиты feature переезжают наверх main (линейно)

Сравнение:

Характеристика merge rebase
История Ветвистая (сохраняет) Линейная (чистая)
Сложность Проще Сложнее (конфликты)
Безопасность Безопаснее Опасно (переписывает историю)
Время Меньше конфликтов Много конфликтов

Когда использовать:

  • merge: для публичных веток, главная ветка
  • rebase: для локальных веток, чтобы очистить историю
  • Никогда не rebase: общие ветки (main, develop)
Конфликты — как возникают, как решать.
обяз

Конфликт — когда Git не может автоматически объединить изменения.

Как возникает:

  • Два разработчика изменяют одни и те же строки
  • Один удалил файл, другой изменил
  • Слияние веток с разными версиями

Как решать:

1. Посмотреть конфликт

git status              # Видим конфликт
git diff               # Показывает конфликт

2. Открыть файл

<<<<<<< HEAD
Console.WriteLine("Моя версия");
=======
Console.WriteLine("Их версия");
>>>>>>> feature-branch

3. Исправить вручную

  • Удалить маркеры (<<<<<<<, =======, >>>>>>>)
  • Оставить правильную версию
  • Или объединить обе

4. Сохранить изменения

git add .
git commit -m "Resolved conflict"

Инструменты:

  • VS Code — встроенный мерж-тул
  • Git GUI — SourceTree, GitKraken
  • Командная строка — git mergetool
cherry-pick — зачем.
mid

cherry-pick — перенос конкретного коммита в другую ветку.

Когда использовать:

  • Нужно перенести один коммит, не сливая ветку
  • Исправление бага в продакшене (hotfix)
  • Перенос фичи в другую ветку
  • Отмена изменений

Пример:

# Найти нужный коммит
git log --oneline
# a1b2c3d Fix: исправление бага
# d4e5f6g Add: новая фича

# Переключиться на целевую ветку
git checkout main

# Перенести коммит
git cherry-pick a1b2c3d

# Если конфликт — исправить и продолжить
git cherry-pick --continue
# или отменить
git cherry-pick --abort

Важно:

  • Создаёт новый коммит (с новым хэшом)
  • Может вызвать конфликты
  • Не изменяет исходную ветку
reset (--soft, --hard, --mixed) — разница.
mid

reset — отмена изменений с разными уровнями.

--soft (мягкий)

  • Сбрасывает только HEAD (указатель ветки)
  • Индекс (staging) сохраняется
  • Рабочая директория сохраняется
  • Изменения остаются в staging
git reset --soft HEAD~1   # Отменить последний коммит, оставить изменения в staging

--mixed (по умолчанию)

  • Сбрасывает HEAD и индекс
  • Рабочая директория сохраняется
  • Изменения остаются в рабочей директории (unstaged)
git reset HEAD~1           # Отменить коммит, изменения в рабочей директории

--hard (жёсткий)

  • Сбрасывает всё (HEAD, индекс, рабочую директорию)
  • Изменения теряются (нельзя восстановить)
  • Опасная команда!
git reset --hard HEAD~1   # Удалить последний коммит и все изменения

Сравнение:

Режим HEAD Индекс (staging) Рабочая директория
--soft ✅ Сброс ✅ Сохраняется ✅ Сохраняется
--mixed ✅ Сброс ✅ Сброс ✅ Сохраняется
--hard ✅ Сброс ✅ Сброс ✅ Сброс (потеря данных)

Безопасная альтернатива: git revert (создаёт новый коммит).

Git Flow / GitHub Flow — базово.
mid

Git Flow:

  • Сложная модель с множеством веток
  • main — продакшен
  • develop — разработка
  • feature/* — фичи (от develop)
  • release/* — подготовка релиза
  • hotfix/* — срочные исправления
git flow init
git flow feature start new-feature
git flow feature finish new-feature
git flow release start 1.0.0
git flow release finish 1.0.0
git flow hotfix start critical-fix

GitHub Flow (проще):

  • main — всегда готов к деплою
  • feature/* — ветки для фич
  • Нет develop, release веток
  • Каждая фича → PR → main
  • Деплой из main

Сравнение:

Характеристика Git Flow GitHub Flow
Сложность Высокая Низкая
Ветки Много Мало
Деплой Релизные ветки Из main
Подходит для Крупные проекты CI/CD, микросервисы
