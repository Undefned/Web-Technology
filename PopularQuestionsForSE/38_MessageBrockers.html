📨 38. Message Brokers (RabbitMQ, Kafka, Azure Service Bus) Mid+

RabbitMQ — очередь сообщений.
mid

RabbitMQ — брокер сообщений (AMQP).

Ключевые понятия:

  • Producer — отправитель сообщения
  • Consumer — получатель сообщения
  • Queue — очередь хранения сообщений
  • Exchange — маршрутизация сообщений
  • Routing Key — ключ маршрутизации
  • Binding — связь Exchange → Queue
  • Ack — подтверждение получения

Типы Exchange:

  • Direct — точное совпадение routing key
  • Topic — по шаблону (wildcard)
  • Fanout — всем (broadcast)
  • Headers — по заголовкам

Пример в .NET (RabbitMQ.Client):

// Producer
var factory = new ConnectionFactory { HostName = "localhost" };
using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

channel.QueueDeclare("orders", durable: true, exclusive: false, autoDelete: false);

var body = Encoding.UTF8.GetBytes(JsonSerializer.Serialize(order));
channel.BasicPublish(exchange: "", routingKey: "orders", basicProperties: null, body: body);

// Consumer
var consumer = new EventingBasicConsumer(channel);
consumer.Received += (model, ea) =>
{
    var body = ea.Body.ToArray();
    var message = Encoding.UTF8.GetString(body);
    var order = JsonSerializer.Deserialize<Order>(message);
    
    ProcessOrder(order);
    
    channel.BasicAck(deliveryTag: ea.DeliveryTag, multiple: false);  // Подтверждение
};

channel.BasicConsume(queue: "orders", autoAck: false, consumer: consumer);
Apache Kafka — распределённый лог.
mid

Apache Kafka — распределённый журнал событий (лог).

Ключевые понятия:

  • Topic — категория событий (аналог очереди)
  • Partition — часть топика (параллелизм)
  • Producer — отправитель (публикует в топик)
  • Consumer — получатель (читает из топика)
  • Consumer Group — группа потребителей (балансировка)
  • Offset — позиция сообщения в партиции
  • Broker — сервер Kafka

Пример в .NET (Confluent.Kafka):

// Producer
var config = new ProducerConfig { BootstrapServers = "localhost:9092" };
using var producer = new ProducerBuilder<string, string>(config)
    .SetKeySerializer(Serializers.Utf8)
    .SetValueSerializer(Serializers.Utf8)
    .Build();

var result = await producer.ProduceAsync("orders", new Message<string, string>
{
    Key = order.Id.ToString(),
    Value = JsonSerializer.Serialize(order)
});

// Consumer
var consumerConfig = new ConsumerConfig
{
    BootstrapServers = "localhost:9092",
    GroupId = "order-processors",
    AutoOffsetReset = AutoOffsetReset.Earliest
};

using var consumer = new ConsumerBuilder<string, string>(consumerConfig)
    .SetKeyDeserializer(Deserializers.Utf8)
    .SetValueDeserializer(Deserializers.Utf8)
    .Build();

consumer.Subscribe("orders");

while (true)
{
    var result = consumer.Consume();
    var order = JsonSerializer.Deserialize<Order>(result.Message.Value);
    ProcessOrder(order);
    
    consumer.Commit(result);  // Сохраняем offset
}

RabbitMQ vs Kafka:

Характеристика RabbitMQ Kafka
Модель Очередь Журнал (лог)
Скорость Высокая Очень высокая
Хранение Пока не обработано Настраиваемое (дни/недели)
Повторное чтение Нет Да (по offset)
Сложность Средняя Высокая
Где использовать Задачи, RPC, микросервисы Streaming, аналитика, логи, события
Azure Service Bus — облачный брокер.
mid

Azure Service Bus — управляемый брокер сообщений в Azure.

Ключевые понятия:

  • Queue — очередь (FIFO)
  • Topic — топик (Publish/Subscribe)
  • Subscription — подписка на топик
  • Dead-Letter Queue — очередь для ошибочных сообщений
  • Sessions — группировка сообщений

Пример в .NET (Azure.Messaging.ServiceBus):

// Producer
await using var client = new ServiceBusClient(connectionString);
var sender = client.CreateSender("orders");

var message = new ServiceBusMessage(JsonSerializer.Serialize(order))
{
    MessageId = Guid.NewGuid().ToString(),
    SessionId = order.UserId.ToString()
};
await sender.SendMessageAsync(message);

// Consumer
var processor = client.CreateProcessor("orders", new ServiceBusProcessorOptions
{
    MaxConcurrentCalls = 10,
    AutoCompleteMessages = false
});

processor.ProcessMessageAsync += async args =>
{
    var body = args.Message.Body.ToString();
    var order = JsonSerializer.Deserialize<Order>(body);
    
    await ProcessOrderAsync(order);
    
    await args.CompleteMessageAsync(args.Message);  // Подтверждение
};

processor.ProcessErrorAsync += args =>
{
    Console.WriteLine(args.Exception.Message);
    return Task.CompletedTask;
};

await processor.StartProcessingAsync();
Dead Letter Queue — обработка ошибочных сообщений.
mid

Dead Letter Queue (DLQ) — очередь для сообщений, которые не удалось обработать.

Причины попадания в DLQ:

  • Превышен MaxDeliveryCount (количество попыток)
  • Истекло TTL (время жизни)
  • Ошибка валидации
  • Ошибка обработки (исключение)

Пример в Azure Service Bus:

// Настройка очереди с DLQ
var queueOptions = new CreateQueueOptions("orders")
{
    MaxDeliveryCount = 3,  // После 3 неудач → DLQ
    DefaultMessageTimeToLive = TimeSpan.FromMinutes(10),
    EnableDeadLetteringOnMessageExpiration = true
};
await adminClient.CreateQueueAsync(queueOptions);

// Обработка с DLQ
processor.ProcessMessageAsync += async args =>
{
    try
    {
        var order = JsonSerializer.Deserialize<Order>(args.Message.Body.ToString());
        await ProcessOrderAsync(order);
        await args.CompleteMessageAsync(args.Message);
    }
    catch (Exception ex)
    {
        // Dead-letter вручную
        await args.DeadLetterMessageAsync(args.Message,
            deadLetterReason: "ProcessingFailed",
            deadLetterErrorDescription: ex.Message);
    }
};

// Чтение из DLQ
var dlqProcessor = client.CreateProcessor("orders", new ServiceBusProcessorOptions
{
    SubQueue = SubQueue.DeadLetter
});

dlqProcessor.ProcessMessageAsync += async args =>
{
    var body = args.Message.Body.ToString();
    var reason = args.Message.DeadLetterReason;
    var error = args.Message.DeadLetterErrorDescription;
    
    // Анализ ошибки
    await HandleDeadLetterAsync(body, reason, error);
    
    await args.CompleteMessageAsync(args.Message);
};
