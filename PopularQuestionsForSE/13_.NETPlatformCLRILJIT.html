⚙️ 13. .NET Platform. CLR, IL, JIT Mid+

CLR — Common Language Runtime.
обяз

CLR — исполняющая среда для .NET-приложений.

Основные функции:

  • Управление памятью (Garbage Collector)
  • Безопасность (CAS, безопасность типов)
  • Обработка исключений
  • Загрузка сборок (Assemblies)
  • JIT-компиляция (IL → машинный код)
  • Управление потоками
  • Взаимодействие с COM и неуправляемым кодом

Схема работы:

Исходный код (C#) → Компиляция → IL (Intermediate Language) → JIT → Машинный код → CPU

Компоненты:

  • CTS (Common Type System) — единая система типов
  • CLS (Common Language Specification) — спецификация для языков
  • BCL (Base Class Library) — базовые классы
  • GAC (Global Assembly Cache) — хранилище сборок
IL (Intermediate Language) — что это.
обяз

IL (Intermediate Language) — промежуточный язык, в который компилируется C# код.

Особенности:

  • Независимость от платформы
  • Общий для всех .NET языков
  • Содержит метаданные (информация о типах)
  • Преобразуется в машинный код JIT-компилятором

Пример IL:

// C# код
public int Add(int a, int b) => a + b;

// IL
.method public hidebysig instance int32 Add(int32 a, int32 b) cil managed
{
    .maxstack 8
    ldarg.1    // Загрузить a
    ldarg.2    // Загрузить b
    add        // Сложить
    ret        // Вернуть
}

Просмотр IL:

  • ildasm (инструмент от Microsoft)
  • ILSpy / dnSpy (декомпиляторы)
  • dotPeek (JetBrains)
JIT-компиляция — Just-In-Time, преимущества.
обяз

JIT (Just-In-Time) — компиляция IL в машинный код во время выполнения.

Как работает:

  1. Метод вызывается впервые
  2. JIT компилирует IL в машинный код
  3. Код сохраняется в памяти
  4. При повторном вызове используется скомпилированный код

Преимущества:

  • Переносимость: IL не зависит от платформы
  • Оптимизация: JIT может оптимизировать под конкретную платформу
  • Безопасность: верификация IL во время компиляции
  • Производительность: вторая компиляция даёт оптимизированный код

Недостатки:

  • Задержка: первый вызов метода медленнее
  • Память: скомпилированный код занимает память

Типы JIT:

  • Normal JIT: компилирует метод при первом вызове
  • Econo JIT: быстрая компиляция (меньше оптимизаций)
  • Pre-JIT (NGEN): компиляция до выполнения (не используется в .NET Core)
AOT-компиляция (Ahead-Of-Time) — когда используется.
mid

AOT (Ahead-Of-Time) — компиляция IL в машинный код до выполнения.

Когда используется:

  • Mobile (iOS, Android) — запрещена JIT-компиляция
  • Blazor WebAssembly — клиентский код
  • Game consoles — PlayStation, Xbox
  • Низкое время запуска — серверные приложения
  • .NET Native (UWP)

Native AOT (.NET 8+):

  • Компиляция в нативный исполняемый файл
  • Быстрый старт
  • Меньше памяти
  • Ограниченный Reflection
  • Нет JIT-компиляции

Пример:

// Native AOT в .NET 8
<PublishAot>true</PublishAot>

dotnet publish -r win-x64 -c Release

Преимущества AOT:

  • Быстрый старт
  • Меньше потребление памяти
  • Безопасность (нельзя генерировать код)

Недостатки:

  • Больше размер файла
  • Ограниченный Reflection
  • Нельзя генерировать код во время выполнения
Управляемый vs Неуправляемый код.
обяз

Управляемый код (Managed Code):

  • Выполняется под управлением CLR
  • Память управляется GC
  • Безопасность типов
  • Пример: C#, VB.NET, F#

Неуправляемый код (Unmanaged Code):

  • Выполняется напрямую в ОС
  • Память управляется вручную
  • Нет безопасности типов
  • Пример: C++, WinAPI, COM

Сравнение:

Характеристика Управляемый Неуправляемый
Память GC Ручная (malloc/free)
Безопасность Высокая Низкая (утечки, buffer overflow)
Производительность Медленнее (обёртка) Быстрее
Примеры C#, VB.NET, F# C++, WinAPI

Взаимодействие:

// P/Invoke — вызов неуправляемого кода
[DllImport("user32.dll")]
static extern int MessageBox(IntPtr hWnd, string text, string caption, uint type);

MessageBox(IntPtr.Zero, "Hello", "Message", 0);

// unsafe код в C#
unsafe void Example()
{
    int* ptr = stackalloc int[10];
    ptr[0] = 42;
}
Сборка (Assembly) — .dll / .exe, структура.
обяз

Assembly — единица развёртывания и версионирования в .NET.

Форматы:

  • .exe — исполняемое приложение (с Entry Point)
  • .dll — библиотека (без Entry Point)

Структура сборки:

  • Manifest — метаданные (версия, зависимости)
  • IL-код — промежуточный язык
  • Метаданные — информация о типах
  • Ресурсы — изображения, строки, конфигурация

Имя сборки:

// Простое имя (Simple Name)
MyLibrary

// Полное имя (Full Name)
MyLibrary, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null

// Сильное имя (Strong Name)
MyLibrary, Version=1.0.0.0, Culture=neutral, PublicKeyToken=abcd1234

Просмотр сборки:

  • ildasm MyLibrary.dll — IL-код
  • ILSpy — декомпиляция в C#
  • dnSpy — декомпиляция + отладка
Манифест сборки — что содержит.
mid

Assembly Manifest — метаданные о сборке.

Содержит:

  • Имя сборки (Assembly Name)
  • Номер версии (Version)
  • Культура (Culture)
  • Строгое имя (Strong Name) — публичный ключ
  • Список файлов — все файлы в сборке
  • Список зависимостей (Reference) — другие сборки
  • Экспортируемые типы — публичные типы
  • Атрибуты — AssemblyInfo (автор, описание)

Пример манифеста:

.assembly extern mscorlib
{
    .publickeytoken = (B7 7A 5C 56 19 34 E0 89 )
    .ver 4:0:0:0
}
.assembly MyLibrary
{
    .hash algorithm 0x00008004
    .ver 1:0:0:0
}
.module MyLibrary.dll
GAC (Global Assembly Cache) — зачем, сильные имена.
mid

GAC (Global Assembly Cache) — глобальное хранилище сборок.

Зачем нужен:

  • Общий доступ к сборкам для всех приложений
  • Управление разными версиями сборок
  • Увеличение безопасности (сильные имена)

Сильное имя (Strong Name):

  • Состоит из: Имя + Версия + Культура + Публичный ключ
  • Защита от подделки сборок
  • Уникальность в GAC

Работа с GAC:

// Создание сильного имени
sn -k MyKey.snk

// Установка в GAC (устарело)
gacutil -i MyLibrary.dll

// .NET Core / .NET 5+ — GAC не используется
// Вместо него — папка приложения или NuGet

Почему GAC устарел:

  • Конфликты версий
  • Сложность развёртывания
  • Медленная эволюция
  • .NET Core не использует GAC
Reflection — что это, когда использовать.
mid

Reflection — механизм получения информации о типах во время выполнения.

Возможности:

  • Получение информации о типах, методах, свойствах
  • Создание объектов
  • Вызов методов (включая приватные)
  • Динамическая загрузка сборок
  • Работа с атрибутами

Примеры:

// Получение типа
Type type = typeof(string);
Type type2 = "Hello".GetType();

// Информация о типе
Console.WriteLine(type.Name);           // String
Console.WriteLine(type.FullName);       // System.String
Console.WriteLine(type.IsClass);        // True

// Получение методов
foreach (MethodInfo method in type.GetMethods())
    Console.WriteLine(method.Name);

// Создание объекта через Reflection
Type personType = typeof(Person);
object person = Activator.CreateInstance(personType);

// Вызов метода
MethodInfo method = personType.GetMethod("SetName");
method.Invoke(person, new object[] { "Alice" });

// Работа с атрибутами
[Obsolete("Use NewMethod instead")]
public void OldMethod() { }

var attr = typeof(MyClass)
    .GetMethod("OldMethod")
    .GetCustomAttribute<ObsoleteAttribute>();
Console.WriteLine(attr.Message);

Когда использовать:

  • DI контейнеры (регистрация типов)
  • Сериализация (JSON, XML)
  • Обработка атрибутов (MVC, Unit-тесты)
  • Динамическая загрузка плагинов
  • Инструменты и IDE (IntelliSense)

Производительность:

  • Медленнее прямого вызова (в 10-100 раз)
  • Кэшируйте результаты Type
  • Используйте Type.GetMethod один раз
Атрибуты (Attributes) — как создать, использовать.
mid

Атрибуты — метаданные, добавляющие информацию к типам и членам.

Создание атрибута:

[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
public class AuthorAttribute : Attribute
{
    public string Name { get; }
    public string Email { get; set; }
    
    public AuthorAttribute(string name)
    {
        Name = name;
    }
}

Использование:

[Author("Alice", Email = "alice@example.com")]
public class UserService
{
    [Author("Bob")]
    public void Save() { }
}

Получение атрибутов:

// Получение атрибута
var attr = typeof(UserService)
    .GetCustomAttribute<AuthorAttribute>();
Console.WriteLine($"Author: {attr.Name}");

// Получение всех атрибутов
var attrs = typeof(UserService)
    .GetCustomAttributes<AuthorAttribute>();

// Проверка
bool hasAttr = typeof(UserService)
    .IsDefined(typeof(AuthorAttribute), false);

Встроенные атрибуты:

  • Obsolete — устаревший код
  • Serializable — сериализация
  • Conditional — условная компиляция
  • DllImport — P/Invoke
  • DataAnnotations — валидация
Методы расширения (Extension Methods) — как работают.
обяз

Extension Methods — методы, добавляющие функциональность к существующим типам.

Правила:

  • Статический класс
  • Статический метод
  • Первый параметр — this + тип

Пример:

public static class StringExtensions
{
    public static bool IsEmail(this string str)
    {
        return str.Contains("@") && str.Contains(".");
    }
    
    public static string ToTitleCase(this string str)
    {
        return char.ToUpper(str[0]) + str.Substring(1).ToLower();
    }
}

// Использование
string email = "test@example.com";
bool isValid = email.IsEmail();  // Статический синтаксис

string name = "alice";
string title = name.ToTitleCase();  // "Alice"

Приоритет:

  • Экземплярные методы имеют приоритет
  • Расширения — если нет подходящего метода

Когда использовать:

  • Добавление функциональности к типам, которые нельзя изменить
  • Утилитные методы (LINQ, StringExtensions)
  • Fluent API (Builder паттерн)
Частичные классы (partial) — зачем.
mid

partial — разделение класса на несколько файлов.

Когда использовать:

  • Генерация кода (дизайнеры) — отдельный файл для машинного кода
  • Разделение больших классов
  • Разработка в команде (разные файлы для разных задач)

Пример:

// File1.cs
public partial class Person
{
    public string Name { get; set; }
    public string Email { get; set; }
}

// File2.cs
public partial class Person
{
    public void PrintInfo()
    {
        Console.WriteLine($"{Name} ({Email})");
    }
}

В WPF/Windows Forms:

  • Visual Studio генерирует код дизайнера в MainWindow.g.i.cs
  • Разработчик пишет код в MainWindow.xaml.cs
  • Оба файла — один класс
Статический конструктор — когда вызывается.
обяз

Статический конструктор — вызывается один раз для инициализации статических членов.

Когда вызывается:

  • Перед первым созданием экземпляра
  • Перед первым обращением к статическому члену
  • Только один раз за время работы приложения
  • Вызывается автоматически (нельзя вызвать явно)

Пример:

public class Config
{
    public static string ConnectionString { get; }
    
    // Статический конструктор
    static Config()
    {
        Console.WriteLine("Static constructor called");
        ConnectionString = "Server=localhost;Database=Test;";
    }
}

// Использование
string cs = Config.ConnectionString;  // Вызывается статический конструктор
var config = new Config();  // Не вызывается (уже вызван)

Особенности:

  • Не имеет параметров
  • Не имеет модификаторов доступа
  • Вызывается в потокобезопасном контексте
  • Если исключение — класс больше не инициализируется
  • Используется для сложной инициализации
.NET Standard vs .NET Core vs .NET Framework — разница.
обяз

.NET Framework:

  • Только Windows
  • Устаревшая версия
  • Нет новых фич
  • Поддержка устаревает
  • Пример: 4.8, 4.7.2

.NET Core:

  • Кросс-платформенный (Win, Linux, Mac)
  • Современная версия
  • Лучшая производительность
  • Активно развивается
  • Пример: 3.1 (последняя версия)

.NET 5/6/7/8:

  • Единая платформа (замена .NET Core + .NET Framework)
  • Кросс-платформенный
  • Новые фичи
  • Активно развивается
  • Пример: 8.0 (текущая)

.NET Standard:

  • Спецификация (не реализация)
  • Набор API, доступных во всех .NET
  • Используется для создания библиотек
  • Устаревает (уступает .NET 5+)

Рекомендации:

  • Новые проекты: .NET 8+ (LTS)
  • Библиотеки: .NET Standard 2.0 (совместимость)
  • Устаревшие проекты: .NET Framework (миграция)
