Expression Trees — что это, когда использовать.
mid

Expression Trees — представление кода в виде дерева (может быть скомпилировано).

Где используется:

  • LINQ to SQL / EF Core — преобразование C# в SQL
  • Dynamic LINQ — динамические запросы
  • Сериализация — правила валидации
  • Компиляция — динамическая генерация кода

Пример:

// Expression Tree
Expression<Func<int, bool>> expr = x => x > 5;

// Смотрим структуру
Console.WriteLine(expr);  // x => (x > 5)

// Компилируем в делегат
Func<int, bool> func = expr.Compile();
Console.WriteLine(func(10));  // True

// Строим вручную
ParameterExpression param = Expression.Parameter(typeof(int), "x");
ConstantExpression constant = Expression.Constant(5);
BinaryExpression greaterThan = Expression.GreaterThan(param, constant);
var lambda = Expression.Lambda<Func<int, bool>>(greaterThan, param);
var compiled = lambda.Compile();
Console.WriteLine(compiled(10));  // True

Когда использовать:

  • Динамические запросы
  • Правила и валидация
  • Генерация кода
  • ORM и DSL
Source Generators — что это, отличие от Reflection.
mid

Source Generators — генерация кода во время компиляции.

Отличие от Reflection:

Характеристика Source Generators Reflection
Время выполнения Компиляция (до runtime) Runtime (во время выполнения)
Производительность Высокая (нет накладных расходов) Низкая (медленно)
Доступ к приватным членам Да Да
Сложность Высокая Средняя
Примеры JSON сериализация, DI, MVVM DI, тестирование, атрибуты

Пример Source Generator:

[Generator]
public class HelloWorldGenerator : ISourceGenerator
{
    public void Initialize(GeneratorInitializationContext context) { }
    
    public void Execute(GeneratorExecutionContext context)
    {
        var source = @"
namespace Generated
{
    public static class HelloWorld
    {
        public static void SayHello() => Console.WriteLine(""Hello from generator!"");
    }
}";
        context.AddSource("HelloWorld.g.cs", source);
    }
}

// Использование (генерируется автоматически)
Generated.HelloWorld.SayHello();
Native AOT (.NET 8+) — что это, ограничения.
mid

Native AOT — компиляция приложения в нативный исполняемый файл.

Преимущества:

  • Быстрый старт (мгновенный)
  • Малое потребление памяти
  • Нет JIT-компиляции
  • Один исполняемый файл (.exe)
  • Подходит для Docker (маленький размер)

Ограничения:

  • Ограниченный Reflection (только compile-time)
  • Нет динамической генерации кода (Emit)
  • Некоторые библиотеки не совместимы
  • Больше размер файла (чем обычный)
  • Ограниченная поддержка платформ

Как использовать:

<Project Sdk="Microsoft.NET.Sdk">
    <PropertyGroup>
        <PublishAot>true</PublishAot>
        <SelfContained>true</SelfContained>
        <RuntimeIdentifier>win-x64</RuntimeIdentifier>
    </PropertyGroup>
</Project>

// Публикация
dotnet publish -c Release -r win-x64

Когда использовать:

  • CLI-инструменты
  • Серверные приложения (быстрый старт)
  • Docker-контейнеры
  • IoT и встраиваемые системы
Функциональное программирование в C# — неизменяемость, чистые функции.
mid

Функциональное программирование — парадигма с акцентом на функции и неизменяемость.

Неизменяемость (Immutability):

  • Объекты не изменяются после создания
  • При изменении создаётся новый объект
  • Пример: record, string
// Неизменяемый объект
public record Person(string Name, int Age);

var p1 = new Person("Alice", 30);
var p2 = p1 with { Age = 31 };  // Новая копия

Чистые функции (Pure Functions):

  • Одинаковый результат для одинаковых аргументов
  • Не имеет побочных эффектов (side effects)
  • Легко тестировать
// ❌ Нечистая функция (есть побочный эффект)
int AddAndLog(int a, int b)
{
    Console.WriteLine($"Adding {a} and {b}");  // Побочный эффект
    return a + b;
}

// ✅ Чистая функция
int Add(int a, int b) => a + b;

FP-концепции в C#:

  • LINQ — функциональные операции (Select, Where)
  • Делегаты — функции как значения
  • Лямбды — анонимные функции
  • Tuple — возврат нескольких значений
  • Record — неизменяемые объекты
Фоновые задачи — IHostedService, BackgroundService.
mid

IHostedService — интерфейс для фоновых задач в ASP.NET Core.

public interface IHostedService
{
    Task StartAsync(CancellationToken cancellationToken);
    Task StopAsync(CancellationToken cancellationToken);
}

BackgroundService — абстрактный класс для периодических задач.

Пример BackgroundService:

public class TimedHostedService : BackgroundService
{
    private readonly ILogger<TimedHostedService> _logger;
    
    public TimedHostedService(ILogger<TimedHostedService> logger)
    {
        _logger = logger;
    }
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            _logger.LogInformation("Background task running at: {time}", DateTime.Now);
            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }
}

Регистрация в DI:

// Program.cs
builder.Services.AddHostedService<TimedHostedService>();

// Альтернатива: IHostedService
builder.Services.AddHostedService<MyHostedService>();

Когда использовать:

  • Периодические задачи (очистка кэша)
  • Обработка очередей
  • Мониторинг и уведомления
  • Фоновые операции
Health Checks — для чего.
mid

Health Checks — проверка работоспособности приложения.

Зачем нужны:

  • Мониторинг состояния сервиса
  • Проверка зависимостей (БД, Redis, API)
  • Автоматическое восстановление
  • Kubernetes (liveness/readiness probes)
  • Load balancer (проверка живых экземпляров)

Пример:

// Program.cs
builder.Services.AddHealthChecks()
    .AddCheck<DatabaseHealthCheck>("database")
    .AddCheck<ApiHealthCheck>("api")
    .AddDbContextCheck<AppDbContext>()
    .AddUrlGroup(new Uri("https://api.example.com/health"), "external");

app.MapHealthChecks("/health", new HealthCheckOptions
{
    ResponseWriter = UIResponseWriter.WriteHealthCheckUIResponse
});

app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = _ => true  // Проверяет все
});

app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false  // Проверяет только liveness
});

Кастомный Health Check:

public class DatabaseHealthCheck : IHealthCheck
{
    private readonly AppDbContext _context;
    
    public DatabaseHealthCheck(AppDbContext context)
    {
        _context = context;
    }
    
    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        try
        {
            await _context.Database.ExecuteSqlRawAsync("SELECT 1", cancellationToken);
            return HealthCheckResult.Healthy("Database is healthy");
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy("Database is unhealthy", ex);
        }
    }
}
OpenTelemetry — распределённая трассировка.
mid

OpenTelemetry — стандарт для сбора телеметрии (трассировки, метрики, логи).

Компоненты:

  • Traces — распределённая трассировка (Jaeger, Zipkin)

Пример в ASP.NET Core:

// Program.cs
using OpenTelemetry.Trace;

builder.Services.AddOpenTelemetry()

            .AddSqlClientInstrumentation()    // SQL-запросы
            .AddOtlpExporter();               // Экспорт в Collector

// Использование Activity
var tracer = TracerProvider.Default.GetTracer("MyApp");
using var activity = tracer.StartActiveSpan("ProcessOrder");
activity.SetTag("order.id", orderId);
// ...
activity.End();

Почему важно:

  • Отслеживание запросов через микросервисы
  • Поиск узких мест
  • Диагностика ошибок
  • Анализ производительности
Rate Limiting — ограничение запросов в ASP.NET Core.
mid

Rate Limiting — ограничение количества запросов (защита от перегрузки).

Стратегии:

  • Fixed Window — фиксированное окно (например, 100 запросов/мин)
  • Sliding Window — скользящее окно
  • Token Bucket — токены + пополнение
  • Concurrency — ограничение параллельных запросов

Пример в .NET 7+:

// Program.cs
builder.Services.AddRateLimiter(options =>
{
    // Фиксированное окно
    options.AddFixedWindowLimiter("fixed", limiterOptions =>
    {
        limiterOptions.PermitLimit = 100;
        limiterOptions.Window = TimeSpan.FromMinutes(1);
        limiterOptions.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        limiterOptions.QueueLimit = 5;
    });
    
    // Token Bucket
    options.AddTokenBucketLimiter("token", limiterOptions =>
    {
        limiterOptions.TokenLimit = 100;
        limiterOptions.TokensPerPeriod = 10;
        limiterOptions.ReplenishmentPeriod = TimeSpan.FromSeconds(1);
    });
});

app.UseRateLimiter();

// В контроллере
[EnableRateLimiting("fixed")]
[HttpGet]
public IActionResult Get() { }

// Отключение для метода
[DisableRateLimiting]
[HttpGet("unlimited")]
public IActionResult Unlimited() { }
Polly — Retry, Circuit Breaker, Timeout.
mid

Polly — библиотека для устойчивости к ошибкам.

Основные политики:

1. Retry (повтор)

var retry = Policy
    .Handle<HttpRequestException>()
    .RetryAsync(3, onRetry: (ex, retryCount) =>
    {
        Console.WriteLine($"Retry {retryCount}: {ex.Message}");
    });

await retry.ExecuteAsync(async () =>
{
    await httpClient.GetAsync("https://api.example.com");
});

2. Circuit Breaker (предохранитель)

var circuitBreaker = Policy
    .Handle<HttpRequestException>()
    .CircuitBreakerAsync(
        exceptionsAllowedBeforeBreaking: 3,
        durationOfBreak: TimeSpan.FromSeconds(30)
    );

await circuitBreaker.ExecuteAsync(async () =>
{
    await httpClient.GetAsync("https://api.example.com");
});

3. Timeout (тайм-аут)

var timeout = Policy
    .TimeoutAsync(TimeSpan.FromSeconds(5));

await timeout.ExecuteAsync(async () =>
{
    await Task.Delay(10000);  // Будет отменён через 5 сек
});

4. Bulkhead (ограничение параллельности)

var bulkhead = Policy
    .BulkheadAsync(maxParallelization: 10, maxQueuingActions: 100);

await bulkhead.ExecuteAsync(() => DoWork());

5. Fallback (запасной вариант)

var fallback = Policy<string>
    .Handle<Exception>()
    .FallbackAsync("Default value");

var result = await fallback.ExecuteAsync(async () =>
{
    return await GetDataAsync();
});

Комбинирование:

var policy = Policy
    .WrapAsync(retry, circuitBreaker, timeout);

await policy.ExecuteAsync(async () =>
{
    await httpClient.GetAsync("https://api.example.com");
});
Channel (System.Threading.Channels) — Producer/Consumer.
mid

Channel — потокобезопасная очередь для Producer/Consumer.

Преимущества:

  • Встроен в .NET
  • Потокобезопасен
  • Поддерживает async/await
  • Разные стратегии (Bounded/Unbounded)

Пример Producer/Consumer:

// Создание канала
var channel = Channel.CreateBounded<string>(
    new BoundedChannelOptions(100)
    {
        FullMode = BoundedChannelFullMode.Wait
    });

// Producer
async Task ProducerAsync(ChannelWriter<string> writer)
{
    for (int i = 0; i < 100; i++)
    {
        await writer.WriteAsync($"Message {i}");
        await Task.Delay(100);
    }
    writer.Complete();  // Завершить
}

// Consumer
async Task ConsumerAsync(ChannelReader<string> reader)
{
    await foreach (var message in reader.ReadAllAsync())
    {
        Console.WriteLine($"Received: {message}");
    }
}

// Запуск
var producer = ProducerAsync(channel.Writer);
var consumer = ConsumerAsync(channel.Reader);

await Task.WhenAll(producer, consumer);

Неограниченный канал:

var unbounded = Channel.CreateUnbounded<int>();
unbounded.Writer.TryWrite(42);
var value = await unbounded.Reader.ReadAsync();
MemoryCache / DistributedCache — кэширование.
mid

MemoryCache — кэширование в памяти приложения.

builder.Services.AddMemoryCache();
app.MapGet("/cache", async (IMemoryCache cache) =>
{
    // Получение
    if (cache.TryGetValue("key", out string value))
        return value;
    
    // Установка с опциями
    cache.Set("key", "data", new MemoryCacheEntryOptions
    {
        AbsoluteExpiration = DateTimeOffset.Now.AddMinutes(10),
        SlidingExpiration = TimeSpan.FromMinutes(5),
        Priority = CacheItemPriority.High
    });
    
    return "data";
});

DistributedCache — распределённый кэш (Redis, SQL Server).

// Redis
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379";
    options.InstanceName = "MyApp";
});

app.MapGet("/cache", async (IDistributedCache cache) =>
{
    var data = await cache.GetStringAsync("key");
    if (data != null) return data;
    
    data = "computed";
    await cache.SetStringAsync("key", data, new DistributedCacheEntryOptions
    {
        AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
    });
    
    return data;
});

Когда использовать:

  • MemoryCache: в одном экземпляре, данные часто меняются
  • DistributedCache: несколько экземпляров, общий кэш
