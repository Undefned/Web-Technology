Streaming — Kafka, Event Hubs.
mid

Streaming — обработка данных в реальном времени.

Apache Kafka:

  • Распределённый журнал (лог)
  • Хранение данных на диске (настраиваемое)
  • Очень высокая пропускная способность
  • Партиционирование и репликация
// Producer
var producer = new ProducerBuilder<string, string>(config)
    .SetKeySerializer(Serializers.Utf8)
    .SetValueSerializer(Serializers.Utf8)
    .Build();

await producer.ProduceAsync("orders", new Message<string, string>
{
    Key = order.Id.ToString(),
    Value = JsonSerializer.Serialize(order)
});

// Consumer
var consumer = new ConsumerBuilder<string, string>(config)
    .SetKeyDeserializer(Deserializers.Utf8)
    .SetValueDeserializer(Deserializers.Utf8)
    .Build();

consumer.Subscribe("orders");
while (true)
{
    var result = consumer.Consume();
    var order = JsonSerializer.Deserialize<Order>(result.Message.Value);
    ProcessOrder(order);
}

Data Lake / Data Warehouse — базово.
mid

Data Warehouse (Хранилище данных):

  • Структурированные данные
  • Схема заранее известна (Schema-on-Write)
  • Оптимизированы для аналитики (OLAP)
  • Примеры: Snowflake, BigQuery, Redshift, SQL Server (Data Warehouse)
  • Используется для: отчёты, бизнес-аналитика, BI

Data Lake (Озеро данных):

  • Неструктурированные и полуструктурированные данные
  • Схема определяется при чтении (Schema-on-Read)
  • Хранит: JSON, CSV, Parquet, Avro, изображения, видео
  • Примеры: Azure Data Lake, AWS S3, Google Cloud Storage
  • Используется для: обработка больших данных, ML, исследование

Сравнение:

Характеристика Data Warehouse Data Lake
Данные Структурированные Любые
Схема Заранее (Write) При чтении (Read)
Производительность Высокая (оптимизирована) Средняя
Стоимость Высокая Низкая
Пример Snowflake, BigQuery Azure Data Lake, S3

Medallion Architecture (Bronze → Silver → Gold):

  • Bronze: сырые данные (как есть)
  • Silver: очищенные, валидированные
  • Gold: агрегированные, готовые к использованию
ETL / ELT — что это.
mid

ETL (Extract, Transform, Load) — классический процесс обработки данных.

  • Extract: извлечение данных из источников (БД, API, файлы)
  • Transform: преобразование данных (очистка, агрегация, денормализация)
  • Load: загрузка в целевое хранилище (Data Warehouse)
  • Трансформация ДО загрузки
  • Пример: SSIS, Talend, Informatica

ELT (Extract, Load, Transform) — современный подход (облака).

  • Extract: извлечение данных
  • Load: загрузка в Data Lake (сырые данные)
  • Transform: преобразование внутри Data Lake/Data Warehouse
  • Трансформация ПОСЛЕ загрузки
  • Пример: Snowflake, BigQuery, dbt

Сравнение:

Характеристика ETL ELT
Порядок Extract → Transform → Load Extract → Load → Transform
Где трансформация Вне БД (на отдельном сервере) Внутри БД (мощный движок)
Объём данных Средний Большой
Используется Классические on-premise Облачные Data Warehouses

Change Data Capture (CDC) — отслеживание изменений.
mid

CDC (Change Data Capture) — отслеживание изменений в БД.

Зачем:

  • Синхронизация данных между системами
  • Обновление кэшей
  • Аналитика в реальном времени
  • Репликация данных

Способы реализации:

1. Database Triggers

CREATE TRIGGER trg_order_audit
ON Orders
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    INSERT INTO OrderAudit (...)
    SELECT ... FROM inserted
END

2. Log-based CDC (другие DB)

  • PostgreSQL: pglogical, Debezium
  • SQL Server: Change Tracking, Change Data Capture
  • MySQL: binlog (Debezium, Canal)

4. EF Core — ChangeTracker

var entries = context.ChangeTracker.Entries()
    .Where(e => e.State == EntityState.Added || 
                e.State == EntityState.Modified ||
                e.State == EntityState.Deleted);

foreach (var entry in entries)
{
    var event = new EntityChangedEvent
    {
        EntityType = entry.Entity.GetType().Name,
        Action = entry.State.ToString(),
        Data = JsonSerializer.Serialize(entry.Entity)
    };
    await _eventBus.PublishAsync(event);
}
