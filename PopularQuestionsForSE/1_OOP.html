🧱 1. ООП. Базовые принципы 100%

Что такое инкапсуляция? Приведите пример.
обяз

Инкапсуляция — это механизм, который объединяет данные (поля) и методы работы с ними в одном классе, скрывая внутреннюю реализацию от внешнего мира. Доступ к состоянию объекта предоставляется только через публичные методы и свойства.

Зачем нужна инкапсуляция:

  • Защита данных от некорректного использования
  • Сокрытие сложности реализации
  • Возможность изменять внутреннюю логику без влияния на внешний код
  • Контроль над изменениями состояния (валидация)

Пример:

public class BankAccount
{
    // Приватное поле — доступно только внутри класса
    private decimal _balance;
    
    // Публичное свойство — доступно для чтения
    public decimal Balance => _balance;
    
    // Контролируемое изменение состояния
    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Сумма должна быть положительной");
        
        _balance += amount;
    }
    
    public bool Withdraw(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Сумма должна быть положительной");
            
        if (_balance >= amount)
        {
            _balance -= amount;
            return true;
        }
        return false;  // Недостаточно средств
    }
}

Клиентский код не может напрямую изменить _balance, обходятся валидацию и логику. Если мы решим добавить логирование или комиссию, изменим только методы класса — внешний код не пострадает.

Инкапсуляция vs Сокрытие:

  • Инкапсуляция — объединение данных и методов в контейнере (классе)
  • Сокрытие — ограничение доступа к данным через модификаторы (private, protected)
Что такое наследование? Приведите пример.
обяз

Наследование — это механизм, позволяющий создать новый класс (производный) на основе существующего (базового). Производный класс автоматически получает все публичные и защищенные члены базового класса и может расширять или переопределять его функциональность.

Ключевые аспекты:

  • Переиспользование кода — общая логика выносится в базовый класс
  • Иерархия типов — отношение "является" (is-a)
  • Полиморфизм — возможность работать с объектами производных классов через ссылки базового

Пример:

// Базовый класс
public class Animal
{
    public string Name { get; set; }
    public int Age { get; set; }
    
    // Виртуальный метод — можно переопределить
    public virtual void Speak() 
    { 
        Console.WriteLine($"{Name} издаёт звук"); 
    }
    
    public void Eat() 
    { 
        Console.WriteLine($"{Name} ест"); 
    }
}

// Производный класс
public class Dog : Animal
{
    public string Breed { get; set; }  // Новое свойство
    
    // Переопределение виртуального метода
    public override void Speak() 
    { 
        Console.WriteLine($"{Name} говорит: Гав-гав!"); 
    }
    
    // Новый метод
    public void Fetch() 
    { 
        Console.WriteLine($"{Name} приносит мяч"); 
    }
}

// Использование
Dog dog = new Dog { Name = "Бобик", Age = 3, Breed = "Овчарка" };
dog.Speak();    // "Бобик говорит: Гав-гав!"
dog.Eat();      // "Бобик ест"
dog.Fetch();    // "Бобик приносит мяч"

Важные ограничения:

  • Множественное наследование классов в C# запрещено (в отличие от C++)
  • Класс может наследовать только один базовый класс
  • Для множественного наследования поведения используются интерфейсы
  • Все классы неявно наследуются от System.Object
Что такое полиморфизм? Виды полиморфизма.
обяз

Полиморфизм — способность объектов с одинаковым интерфейсом иметь различную реализацию. Это позволяет писать код, работающий с объектами базового типа, который будет корректно выполнять действия в зависимости от реального типа объекта во время выполнения.

Три вида полиморфизма в C#:

1. Ad-hoc полиморфизм (перегрузка)

  • Несколько методов с одним именем, но разными параметрами
  • Выбор метода происходит на этапе компиляции
public class Calculator
{
    public int Add(int a, int b) => a + b;
    public double Add(double a, double b) => a + b;
    public int Add(int a, int b, int c) => a + b + c;
}

2. Параметрический полиморфизм (обобщения)

  • Один код работает с разными типами данных
  • Реализуется через Generics
public class List<T>
{
    private T[] _items;
    public void Add(T item) { /* ... */ }
    public T Get(int index) { /* ... */ }
}

List<int> intList = new List<int>();
List<string> stringList = new List<string>();

3. Полиморфизм включения (наследование)

  • Переопределение виртуальных методов в производных классах
  • Выбор метода происходит на этапе выполнения (runtime)
  • Реализуется через virtual/override
public class Shape
{
    public virtual void Draw() => Console.WriteLine("Рисуем фигуру");
}

public class Circle : Shape
{
    public override void Draw() => Console.WriteLine("Рисуем круг");
}

public class Rectangle : Shape
{
    public override void Draw() => Console.WriteLine("Рисуем прямоугольник");
}

// Полиморфизм в действии
Shape shape1 = new Circle();
Shape shape2 = new Rectangle();
shape1.Draw();  // "Рисуем круг"
shape2.Draw();  // "Рисуем прямоугольник"

List<Shape> shapes = new List<Shape> { new Circle(), new Rectangle() };
foreach (var shape in shapes)
    shape.Draw();  // Каждая фигура рисуется по-своему

Преимущества полиморфизма:

  • Код становится более гибким и расширяемым
  • Упрощается добавление новых типов (принцип Open/Closed)
  • Снижается связанность (coupling) между компонентами
  • Облегчается тестирование (подмена зависимостей)
Что такое абстракция? Отличие от интерфейса.
обяз

Абстракция — это процесс выделения существенных характеристик объекта и игнорирования несущественных для решения конкретной задачи. В ООП абстракция реализуется через абстрактные классы и интерфейсы.

Пример абстракции в реальной жизни:

  • Водитель автомобиля не должен знать, как работает двигатель — ему нужны только руль, педали и приборы (интерфейс управления)
  • Пользователь банкомата не должен знать внутреннее устройство банкомата — ему нужен экран, клавиатура и купюроприемник

Сравнение абстрактного класса и интерфейса:

Характеристика Абстрактный класс Интерфейс
Поля Может иметь (в т.ч. приватные) Нет (в C# 8+ можно static поля)
Реализация методов Может быть (частичная/полная) До C# 8 — только сигнатуры; с C# 8 — default реализация
Конструкторы Да Нет
Наследование Только один класс Несколько интерфейсов
Модификаторы доступа Все (public, protected, private) Все члены public (по умолчанию)
Отношение "IS-A" (является) "CAN-DO" (умеет делать)

Пример абстрактного класса:

public abstract class Vehicle
{
    public string Brand { get; set; }
    public int Speed { get; protected set; }
    
    // Абстрактный метод — без реализации
    public abstract void StartEngine();
    
    // Виртуальный метод — с реализацией по умолчанию
    public virtual void StopEngine()
    {
        Speed = 0;
        Console.WriteLine("Двигатель остановлен");
    }
    
    // Обычный метод
    public void Honk()
    {
        Console.WriteLine("Бип-бип!");
    }
}

public class Car : Vehicle
{
    public int DoorsCount { get; set; }
    
    public override void StartEngine()
    {
        Speed = 10;
        Console.WriteLine("Двигатель автомобиля запущен");
    }
}

Пример интерфейса:

public interface IFlyable
{
    void Fly();  // только сигнатура
}

public interface ISwimmable
{
    void Swim();  // только сигнатура
}

// Класс может реализовать несколько интерфейсов
public class Duck : IFlyable, ISwimmable
{
    public void Fly() => Console.WriteLine("Утка летит");
    public void Swim() => Console.WriteLine("Утка плывет");
}
abstract class vs interface — когда что использовать?
обяз

Когда использовать абстрактный класс:

  • Общее состояние: нужно хранить поля, общие для всех наследников
  • Общая реализация: часть методов уже реализована и может быть переиспользована
  • Базовый функционал: наследники должны расширять, а не заменять полностью
  • Иерархия: классы имеют явное отношение "является" (is-a)
  • API-эволюция: можно добавлять новые методы с реализацией без поломки наследников

Примеры абстрактных классов:

  • Stream — базовый класс для всех потоков (FileStream, MemoryStream)
  • Animal — общий функционал для всех животных
  • Vehicle — общие свойства для транспорта

Когда использовать интерфейс:

  • Контракт: нужно определить только поведение, без реализации
  • Множественное наследование: класс должен реализовать несколько поведений
  • Несвязанные классы: объекты разных иерархий могут реализовать один интерфейс
  • Тестирование: легко подменять реализации (mocking, DI)
  • Плагины: сторонние разработчики могут реализовать ваш интерфейс

Примеры интерфейсов:

  • IDisposable — освобождение ресурсов
  • IEnumerable — итерация по коллекции
  • IComparable — сравнение объектов
  • IRepository<T> — паттерн репозиторий

Смешанный подход:

// Абстрактный класс для общей логики
public abstract class Animal
{
    public string Name { get; set; }
    public abstract void Speak();
}

// Интерфейсы для дополнительного поведения
public interface IFlyable { void Fly(); }
public interface ISwimmable { void Swim(); }

// Класс-наследник с дополнительными интерфейсами
public class Duck : Animal, IFlyable, ISwimmable
{
    public override void Speak() => Console.WriteLine("Кря!");
    public void Fly() => Console.WriteLine("Лечу");
    public void Swim() => Console.WriteLine("Плыву");
}
Какие модификаторы доступа существуют в C#?
обяз

Модификаторы доступа определяют, где можно использовать класс или его члены. Это основа инкапсуляции и сокрытия.

Модификатор Доступ Пример использования
public Везде — внутри и вне сборки Публичное API библиотеки
private Только внутри класса Внутреннее состояние, вспомогательные методы
protected Внутри класса и в наследниках Методы, которые должны быть доступны для расширения
internal Внутри текущей сборки (проекта) Внутренние API, которые не должны быть видны снаружи
protected internal В сборке ИЛИ в наследниках (из других сборок) Редко используется
private protected В сборке И в наследниках (только в той же сборке) Для фреймворков, где нужна защита внутри сборки

Правила по умолчанию:

  • Для классов верхнего уровня — internal
  • Для членов класса (поля, методы) — private
  • Для вложенных классов — private

Пример:

public class Person
{
    // private — только внутри класса
    private string _passwordHash;
    private void ValidatePassword(string password) { /* ... */ }
    
    // protected — доступно для наследников
    protected string GetFullName() => $"{FirstName} {LastName}";
    
    // internal — внутри сборки
    internal string InternalInfo { get; set; }
    
    // public — везде
    public string FirstName { get; set; }
    public string LastName { get; set; }
    
    public void Save()
    {
        ValidatePassword(_passwordHash);  // Доступно
    }
}

public class Employee : Person
{
    public void ShowName()
    {
        // GetFullName() доступен (protected)
        Console.WriteLine(GetFullName());
        
        // _passwordHash не доступен (private)
        // Console.WriteLine(_passwordHash);  // Ошибка
    }
}

Советы по использованию:

  • Всегда начинайте с private — давайте минимальный доступ
  • Открывайте доступ постепенно по мере необходимости
  • public — только для того, что должно быть доступно снаружи
  • protected — для методов расширения в наследниках
  • internal — для API внутри проекта
virtual / override / new — в чем разница?
обяз

1. virtual — метод может быть переопределен

  • Помечает метод в базовом классе как "переопределяемый"
  • Метод имеет реализацию, но наследник может её заменить
  • Выбор метода зависит от реального типа объекта (полиморфизм)

2. override — переопределение виртуального метода

  • Заменяет реализацию базового метода в наследнике
  • Метод должен иметь ту же сигнатуру (имя, параметры, возвращаемый тип)
  • Обеспечивает полиморфное поведение
  • Нельзя переопределить невиртуальный метод

3. new — сокрытие метода базового класса

  • Создает новый метод с тем же именем, но не связанный с базовым
  • Не является полиморфным — выбор метода зависит от типа переменной
  • Компилятор выдаёт предупреждение, если не использовать new
  • Используется, когда метод базового класса нельзя изменить

Сравнение на примере:

public class BaseClass
{
    public virtual void VirtualMethod()
    {
        Console.WriteLine("Base.VirtualMethod");
    }
    
    public void NonVirtualMethod()
    {
        Console.WriteLine("Base.NonVirtualMethod");
    }
}

public class DerivedClass : BaseClass
{
    // override — полиморфное переопределение
    public override void VirtualMethod()
    {
        Console.WriteLine("Derived.VirtualMethod (override)");
    }
    
    // new — сокрытие (без полиморфизма)
    public new void NonVirtualMethod()
    {
        Console.WriteLine("Derived.NonVirtualMethod (new)");
    }
}

// Демонстрация разницы
BaseClass baseRef = new DerivedClass();

baseRef.VirtualMethod();     // "Derived.VirtualMethod (override)"  — полиморфизм
baseRef.NonVirtualMethod();  // "Base.NonVirtualMethod" — метод базового класса

DerivedClass derivedRef = (DerivedClass)baseRef;
derivedRef.NonVirtualMethod();  // "Derived.NonVirtualMethod (new)"

Когда что использовать:

  • virtual/override: для полиморфного поведения, расширения API
  • new: если метод базового класса нельзя изменить, но нужно добавить альтернативу
  • sealed override: запретить дальнейшее переопределение
  • abstract: если метод не имеет реализации в базовом классе
Что делает sealed? Для классов и методов.
обяз

sealed — запрещает наследование (для классов) или переопределение (для методов).

1. sealed class — запрет наследования

  • Класс не может иметь производных классов
  • Защищает класс от некорректного расширения
  • Улучшает производительность (компилятор оптимизирует)
  • Часто используется для утилитных классов, DTO, Value Objects
public sealed class MathHelper
{
    public static double CalculateCircleArea(double radius)
    {
        return Math.PI * radius * radius;
    }
}
// public class ExtendedMath : MathHelper { }  // Ошибка — нельзя унаследовать

2. sealed override — запрет дальнейшего переопределения

  • Метод уже переопределён, и нельзя переопределить его в следующих наследниках
  • Используется для "заморозки" поведения в иерархии
  • Сочетает sealed и override
public class Animal
{
    public virtual void Speak() => Console.WriteLine("...");
}

public class Dog : Animal
{
    public sealed override void Speak() => Console.WriteLine("Гав!");
}

public class Husky : Dog
{
    // Ошибка: нельзя переопределить sealed метод
    // public override void Speak() => Console.WriteLine("Ууу!");
    
    // Можно добавить новый метод с другим именем
    public void Howl() => Console.WriteLine("Ууу!");
}

Когда использовать sealed:

  • Безопасность: предотвратить нежелательное изменение поведения
  • Производительность: компилятор может использовать статические вызовы
  • Проектирование: класс спроектирован как завершённый, не для наследования
  • Во избежание ошибок: в сложных иерархиях

Что нельзя sealed:

  • Статические классы (они уже неявно sealed)
  • Структуры (они неявно sealed)
  • Интерфейсы (они не наследуются в классическом смысле)
  • Методы, которые не являются переопределением
Почему в C# запрещено множественное наследование классов?
обяз

Основная причина: Ромбовидная проблема (Diamond Problem).

Что это:

  • Класс D наследует два класса B и C
  • Оба B и C наследуют один класс A
  • В A есть метод M()
  • B и C могут переопределить M() по-разному
  • Какой M() должен использовать D?

Графически:

      A
     / \
    B   C
     \ /
      D
      
  Вопрос: какую версию метода M() наследует D?

Почему это проблема:

  • Неоднозначность: непонятно, какую реализацию использовать
  • Сложность: усложняет понимание иерархии
  • Нарушение инкапсуляции: детали реализации двух родителей смешиваются
  • Связанность: изменения в родителях могут непредсказуемо влиять на потомка

Как C# решает эту проблему:

  1. Запрет множественного наследования классов — класс может иметь только одного родителя
  2. Интерфейсы — вместо классов можно реализовать несколько интерфейсов
  3. Дефолтные методы интерфейсов (C# 8+) — если есть конфликт, класс должен явно реализовать метод
  4. Композиция — вместо наследования можно использовать делегирование

Пример с интерфейсами:

public interface IWork
{
    void DoWork();
}

public interface IEat
{
    void Eat();
}

public class Human : IWork, IEat
{
    // Реализуем оба интерфейса без конфликтов
    public void DoWork() => Console.WriteLine("Работаю");
    public void Eat() => Console.WriteLine("Ем");
}

// Если интерфейсы имеют одинаковые методы
public interface I1 { void M(); }
public interface I2 { void M(); }

public class C : I1, I2
{
    // Явная реализация для каждого интерфейса
    void I1.M() => Console.WriteLine("I1.M");
    void I2.M() => Console.WriteLine("I2.M");
}

Альтернативы множественному наследованию:

  • Композиция: класс содержит экземпляры других классов
  • Делегирование: передача вызовов внутренним объектам
  • Расширения (Extension Methods): добавление методов к существующим типам
  • Интерфейсы + default методы (C# 8+): частичное решение
От какого класса наследуются все типы в .NET?
обяз

Все типы в .NET (и классы, и структуры, и примитивы) неявно наследуются от System.Object.

Иерархия наследования:

System.Object
    ├── System.ValueType (для значимых типов)
    │     ├── System.Enum
    │     ├── System.Int32 (int)
    │     ├── System.Boolean (bool)
    │     ├── System.DateTime
    │     └── ... (все struct)
    │
    └── System.Delegate (для делегатов)
          └── System.MulticastDelegate
    │
    └── (все class)
          ├── System.String
          ├── System.Array
          ├── System.Exception
          ├── System.Collections.Generic.List<T>
          └── ... (все пользовательские классы)

Почему это важно:

  • Все типы имеют общий набор методов (ToString(), Equals(), GetHashCode())
  • Любой объект можно привести к object (Unified Type System)
  • Можно создавать коллекции, содержащие любые типы (ArrayList)
  • Значимые типы наследуются от ValueType, который наследуется от Object

IComparable vs IComparer — разница?

IComparable<T> — определяет естественный порядок сравнения объектов. Реализуется самим классом.

  • Метод: int CompareTo(T other)
  • Возвращает: отрицательное (меньше), 0 (равны), положительное (больше)
  • Используется для сортировки по умолчанию

IComparer<T> — внешний класс для сравнения двух объектов.

  • Метод: int Compare(T x, T y)
  • Позволяет реализовать несколько вариантов сортировки
  • Не требует изменения самого класса
  • Используется в List.Sort(IComparer)

Пример:

// Person реализует IComparable (сортировка по возрасту)
public class Person : IComparable<Person>
{
    public string Name { get; set; }
    public int Age { get; set; }
    
    public int CompareTo(Person other)
    {
        return Age.CompareTo(other.Age);
    }
}

// Внешний компаратор для сортировки по имени
public class PersonNameComparer : IComparer<Person>
{
    public int Compare(Person x, Person y)
    {
        return x.Name.CompareTo(y.Name);
    }
}

// Использование
List<Person> people = new List<Person> { /* ... */ };
people.Sort();                           // Сортировка по возрасту (IComparable)
people.Sort(new PersonNameComparer());   // Сортировка по имени (IComparer)
IEquatable<T> — зачем переопределять Equals?

IEquatable<T> — интерфейс для сравнения объектов на равенство без упаковки.

Почему это важно:

  • Метод Equals(object) требует упаковки для значимых типов (Boxing)
  • IEquatable<T> использует типизированный параметр (без упаковки)
  • Улучшает производительность, особенно в коллекциях
  • Лучше соответствует принципам обобщённого программирования

Пример:

public class Person : IEquatable<Person>
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    // Реализация IEquatable<T>
    public bool Equals(Person other)
    {
        if (other is null) return false;
        return Id == other.Id && Name == other.Name;
    }
    
    // Переопределение Equals(object) — для совместимости
    public override bool Equals(object obj)
    {
        return Equals(obj as Person);
    }
    
    // Обязательное переопределение GetHashCode()
    public override int GetHashCode()
    {
        return HashCode.Combine(Id, Name);
    }
}

Где используется:

  • Dictionary<K,V> — для сравнения ключей
  • HashSet<T> — для хранения уникальных элементов
  • List.Contains() — для поиска элемента
  • LINQ Distinct(), GroupBy(), Join()
Что такое UpCast и DownCast?
mid

UpCast (восходящее приведение):

  • Приведение от производного класса к базовому
  • Всегда безопасно (все объекты производного типа являются объектами базового)
  • Выполняется неявно
  • Не требует явного приведения

DownCast (нисходящее приведение):

  • Приведение от базового класса к производному
  • Не всегда безопасно (объект может не быть производным типом)
  • Требует явного приведения
  • Может выбросить InvalidCastException
  • Используйте as для безопасного приведения

Пример:

public class Animal { }
public class Dog : Animal { public void Bark() => Console.WriteLine("Гав!"); }

Animal animal = new Dog();      // UpCast — неявно, безопасно
// Dog dog = animal;            // Ошибка — DownCast требует явного приведения
Dog dog = (Dog)animal;          // DownCast — явно
dog.Bark();                     // "Гав!"

// Опасный DownCast
Animal animal2 = new Animal();
Dog dog2 = (Dog)animal2;        // InvalidCastException!

Безопасный DownCast:

if (animal is Dog)
{
    Dog dog = (Dog)animal;
    dog.Bark();
}

// Использование as
Dog dog = animal as Dog;
if (dog != null)
{
    dog.Bark();
}

// Pattern matching (C# 7+)
if (animal is Dog dog)
{
    dog.Bark();
}
Операторы is и as — разница?
обяз

is — проверка типа

  • Возвращает bool — совместим ли объект с указанным типом
  • Не выполняет приведение
  • Поддерживает паттерн-матчинг (C# 7+)
  • Не выбрасывает исключений

as — приведение с проверкой

  • Пытается привести объект к указанному типу
  • Возвращает null при неудаче
  • Не выбрасывает исключений
  • Работает только со ссылочными типами и Nullable-структурами
  • Не работает с не-Nullable значимыми типами (int, bool)

Сравнение:

object obj = "Hello World";

// is — проверка
if (obj is string)
{
    string s = (string)obj;  // всё равно нужно явное приведение
    Console.WriteLine(s.Length);
}

// as — приведение с проверкой
string s = obj as string;
if (s != null)
{
    Console.WriteLine(s.Length);
}

// Pattern matching с is (C# 7+)
if (obj is string str)
{
    Console.WriteLine(str.Length);
}

Когда что использовать:

  • is: когда нужно только проверить тип
  • as + проверка на null: для безопасного приведения
  • Pattern matching (is тип переменная): современный подход C#
  • Явное приведение (Type): когда уверены в типе
Паттерн Factory vs Abstract Factory — базово.

Factory Method (Фабричный метод) — создаёт объект одного типа, но позволяет наследникам решать, какой конкретный класс создать.

  • Один метод создания
  • Используется, когда класс не знает, какой именно тип объектов ему нужен
  • Наследники переопределяют метод для создания своих объектов
public abstract class Creator
{
    public abstract IProduct CreateProduct();
}

public class ConcreteCreatorA : Creator
{
    public override IProduct CreateProduct() => new ProductA();
}

public class ConcreteCreatorB : Creator
{
    public override IProduct CreateProduct() => new ProductB();
}

Abstract Factory (Абстрактная фабрика) — создаёт семейства связанных объектов.

  • Интерфейс фабрики содержит методы для создания нескольких типов продуктов
  • Клиент работает с фабрикой, создавая целые семейства объектов
  • Разные реализации фабрики создают разные семейства
public interface IUIFactory
{
    IButton CreateButton();
    IWindow CreateWindow();
}

public class WindowsFactory : IUIFactory
{
    public IButton CreateButton() => new WindowsButton();
    public IWindow CreateWindow() => new WindowsWindow();
}

public class MacFactory : IUIFactory
{
    public IButton CreateButton() => new MacButton();
    public IWindow CreateWindow() => new MacWindow();
}

Когда использовать:

  • Factory Method: когда нужно создать один объект с возможностью расширения
  • Abstract Factory: когда нужны семейства взаимосвязанных объектов
